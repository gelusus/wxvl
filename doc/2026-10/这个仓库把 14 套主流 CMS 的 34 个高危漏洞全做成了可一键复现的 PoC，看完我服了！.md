重点导读项目定位
CMS-Hunter 是一个以厂商为维度组织的内容管理系统漏洞归档仓库。它把分散在各处的历史漏洞，整理成按产品名归类的目录树，每个漏洞对应一个独立子目录，目录内同时提供受影响版本、官方公告链接、复现步骤、原始请求数据包、运行截图以及参考来源。
与纯粹的漏洞列表不同，仓库中相当一部分条目附带了可直接执行的 Python 脚本或落地用的 WebShell 文件，读者无需自行重写请求构造逻辑，克隆后即可进入验证环节。
重点导读目录结构
PART 01顶层分类
仓库根目录下并列 14 个分类目录，覆盖国产内容管理系统、国外主流 CMS 以及 Java 中间件与框架：
DedeCMS、Discuz、Drupal、Ecshop、FineCMS、Joomla、Metinfo、PHPCMS、SeaCMS、Struts、ThinkPHP、ThinkSNS、WebLogic、WordPress。
其中 WordPress、PHPCMS、SeaCMS 三个目录的条目数量最多，ThinkPHP 与 WebLogic 以框架和中间件漏洞为主。
PART 02漏洞条目
全仓库共 34 个漏洞条目目录，命名遵循 产品名_版本号_漏洞类型 的组合方式，版本区间使用连字符表示，例如 ThinkPHP_3.2.3-5.0.10_缓存函数设计缺陷 与 Joomla_3.4.4-3.6.3_未授权创建特权用户。
部分条目附带产品源码快照或框架完整目录，如 ThinkPHP 条目下放置了 ThinkPHP 3.2.3 与 5.0.22 两套完整框架代码，用于定位缺陷位置。
重点导读覆盖组件
国产 CMS 部分的条目集中在 DedeCMS 5.7 系列与 SeaCMS 6.x 系列，涵盖存储型 XSS、CSRF 组合利用、后台代码执行与前台 GetShell 等典型场景。
国外 CMS 部分包含 WordPress 4.4 至 4.9.6 之间的 SSRF、信息泄露、未授权内容注入与任意文件删除，Joomla 3.4.4 至 3.7.0 的 SQL 注入与未授权创建特权用户，以及 Discuz 3.4 以下的前台任意文件删除。
中间件与框架部分收录了 WebLogic 的 XmlDecoder 序列化漏洞与 T3 协议反序列化漏洞，Struts 的 S2-048，以及 ThinkPHP 5.x 远程代码执行。
重点导读文档规范
每个漏洞条目的 README 采用固定段落结构：

标题行，与所在目录名保持一致
Official，官方安全公告或 CVE 记录地址
Affected Version，受影响版本范围
PoC，复现过程，含请求参数、数据包、代码片段与截图
References，原始披露来源

截图为 PNG 或 JPG 格式，直接存放在条目目录内，与文档同级引用。Discuz 条目使用了云端图片链接的形式。
部分条目附带了受影响版本的下载地址与访问凭据，方便读者搭建本地环境。
重点导读脚本形态
仓库内共有 15 个 Python 脚本，形态可以分为三类。
第一类是基于 requests 的接口封装脚本，PHPCMS 的四个条目与 Joomla 的两个条目采用这一形式，脚本内部先发起一次预热请求获取临时 Cookie，再构造注入或上传载荷发送，并把请求封装为带状态输出与异常处理的类结构。
第二类是原始套接字通信脚本，WebLogic 的两个反序列化条目直接使用 socket 库拼接 T3 协议握手头与序列化载荷，手工调整报文长度字段后发送。
第三类是回连验证脚本，WordPress 的 SSRF 条目通过 DNSLog 域名观察外网请求是否由目标服务器发出。
需要注意，部分脚本使用 Python 2 的 print 语句语法，在 Python 3 环境下需要调整语法后方可运行。
此外，个别条目直接提供了用于验证的文件落地样例，用于确认漏洞是否成立。
重点导读漏洞类型
仓库收录的漏洞类型分布如下：

远程代码执行与 GetShell
SQL 注入
任意文件上传、下载、删除
存储型 XSS
CSRF
SSRF
信息泄露
未授权创建特权用户
反序列化

重点导读核心架构
PART 03目录索引层
顶层 README 维护一张产品到漏洞的跳转索引，每个产品一个二级小节，条目以列表形式指向对应目录。
PART 04条目层
每个漏洞一个独立目录，目录名承载产品、版本、类型三类信息，索引层与内容层通过目录名一一对应。
PART 05证据层
条目内的截图、请求数据包、PoC 代码、命令行输出构成可复核的验证证据链。
PART 06脚本层
可执行脚本与漏洞目录同放，脚本文件名标注目标产品与漏洞编号。
PART 07参考层
条目末尾统一保留 References 段落，记录原始披露地址。
重点导读复现流程
仓库条目的整体使用路径保持一致：

在索引层定位产品与漏洞条目
阅读 Affected Version 确认版本是否匹配
按文档准备环境或直接执行随附脚本
通过数据包比对与截图确认触发结果
依据参考来源追溯补丁版本

重点导读落地价值
对于安全运维人员，该仓库可以作为线上资产版本比对的排查清单，覆盖的组件类型与版本区间均处于实际运行系统中广泛存在的区间。
对于安全测试人员，条目中记录的数据包与参数构造方式可直接复用，省去重复的请求编写工作。
对于开发人员，漏洞形成原因与触发路径的记录可用于理解同类框架在输入校验、权限校验、序列化处理上的常见缺陷位置。
重点导读使用边界
仓库内容以历史版本为主，相关漏洞多已由厂商修复，实际环境中应先确认版本状态再决定是否需要验证。
所有复现动作须在自有或已获授权的目标上进行。
条目中的示例代码基于特定环境调试，跨环境使用时需要自行校验参数与路径。
