#  漏洞机构被自己的AI Agent打穿：Zammad双0day链，会话劫持到root只要几秒  
红队安全圈
                    红队安全圈  红队安全圈   2026-10-03 12:00  
  
漏洞披露机构 DIVD 自己被 AI Agent 打穿：Zammad 双 0day 链，会话劫持到 root 只用几秒，日志里还留着 Agent 给自己写的正当性注释。两个洞已进 KEV，10 月 5 日前必须修。  
  
## 01  引言  
  
荷兰漏洞披露机构 DIVD 自己被黑客打穿了。攻击者用两个 Zammad 0day（  
CVE-2026-102489 会话劫持到 RCE +   
CVE-2026-102490 本地提权到 root）组成链，从会话劫持到拿 root 只用几秒——因为攻击者是 AI Agent，自动化决策每一步。DIVD 确认这是有日志证据的 agentic AI 实战攻击，两个漏洞已进 KEV（10-05 前必须修复），Zammad 6.3.0-6.5.4 实际可利用。  
  
## 02  事件还原：AI Agent 的攻击轨迹  
  
DIVD（荷兰应用漏洞披露组织）9 月 21 日首次发现异常，22 日全数据中心断网启动应急，随后五份声明把事件拼完整。攻击链三步：  
  
第一步，利用 Zammad 会话固定漏洞（CVE-2026-102489）劫持会话，在 6.3.0 到 6.5.4 版本上直达 zammad 用户的远程代码执行。  
  
第二步，利用本地提权漏洞（CVE-2026-102490）——存在于包括最新 alpha 在内的所有版本——从 zammad 用户提到   
root。  
  
第三步，以 root 身份横移访问其他服务并外带数据。  
  
真正的重点在攻击方式。DIVD 公布的日志截图显示，攻击脚本里包含 Agent 给自己行为做的正当性注释——它在解释"我这么做是合理的、这不算钓鱼"，这是人类攻击者绝不会写的东西。整个攻击响动很大也很乱：Agent 自动化推进、自己决定下一步、逻辑粗糙，但它过度的注释反而让 DIVD 的逆向分析轻松了不少。  
  
后果：志愿者数据（DIVD 邮箱和可能的联系方式）已确认外泄，DIVD 提醒外界警惕冒充其志愿者的钓鱼。网络分段和应急响应拦住了攻击者深入核心资产，但 DIVD 仍按"已被打穿"处理。

## 04  影响范围与修复  
  
修复：升级到 Zammad 7（CVE-2026-102489 修复在 7.2.0）。无法升级的，DIVD 的建议很直接：  
把实例下线。CISA 已将两个漏洞列入 KEV，联邦机构 10 月 5 日前必须完成修复——民用环境建议照此标准执行。  
  
排查：DIVD 已发布 IOC 检查脚本（cve-2026-102489_ioc_check_script_v2.sh），可直接扫描 Zammad 日志确认是否中招。  
  
## 05  检测与排查  
  
1. 版本自查：Zammad 实例版本在 6.3.0-6.5.4 的，按在野被利用对待。  
  
2. 日志排查：跑 DIVD 的检查脚本，重点看会话异常绑定和 zammad 用户的异常进程。  
  
3. 横向排查：确认到过 root 的机器，检查计划任务、SSH 授权键、新增服务——几秒拿到 root 意味着攻击者的清理窗口和你的排查窗口都极小。  
  
## 06  红队视角  
  
这件事的行业意义大于两个漏洞本身。  
  
第一，这是首次有确凿日志证据的 agentic AI 实战攻击。Agent 全自动完成侦察、利用、提权、横移，它的"自我正当化注释"成了全新的取证特征。防守方的检测规则可能要新增一类：脚本里带解释性注释、工具调用日志里有自我论证痕迹的，单独标可疑等级。  
  
第二，攻击"响、乱、快"是 Agent 的双刃剑。它决策快，几秒走完人类数分钟的链；但逻辑粗糙、注释过度，反而给应急响应留了指纹。这不是 AI 攻击比人强的证据，而是攻击成本结构变了——不会写利用链的人也能驱动 Agent 打穿一个安全机构。  
  
第三，披露机构自己被打穿，说明拥有漏洞知识不等于拥有防御力。救了 DIVD 核心资产的是网络分段——应用被打穿后横向走不远，损失就止得住。每个运营 Zammad 或工单系统的人都该对照自查：你的应用服务器被打穿后，横向能走多远？  
  
Zammad 是开源工单系统，企业客服和技术支持场景用得很多。还在跑 6.x 的，这周内处理掉，别等 KEV 截止日。
