CONTEXT  
### 方案背景  
  
  
漏洞管理的难题变了。  
  
过去是扫不出来，现在是  
   
扫出来的太多  
   
，多到团队处理不过来。每天都有新的 CVE 发布，关键补丁的部署往往  
   
延迟数周  
   
，靠人工排优先级的团队很难聚焦在真正构成威胁的漏洞上。  
  
三个数字可以说明现状：  
  
高达 44% 的网络攻击  
  
始于利用已知漏洞。  
  
近 50,000 个新 CVE  
  
2025 年登记数量。  
  
约 40-55 天  
  
修复关键漏洞的平均耗时。  
  
![漏洞态势与修复窗口数据卡](https://mmbiz.qpic.cn/sz_mmbiz_png/Oy7lbA08GzbCvbYR01RFdsZ0CgttHcHAycLZWGNMUgHXBbym4kysj0shribibcQ0ngIvhkKyGf9SibibNJxvrFcibh6ICANEnKW32wq1JhrjaxO0/640?wx_fmt=png&from=appmsg "")  
  
— 漏洞态势与修复窗口：44% 的攻击利用已知漏洞，关键漏洞平均修复周期 40-55 天  
  
这 40-55 天里，基础架构一直  
   
暴露在潜在攻击风险之下  
   
。  
  
发现漏洞只是第一步  
   
。真正的挑战在于判断哪些漏洞会造成实际风险、它们位于何处，以及是否赶在攻击者利用之前完成了修复。这是  
   
卡巴斯基漏洞管理  
   
瞄准的问题。  
  
作为  
   
企业级解决方案  
   
，它集中管理漏洞、IT 资产和配置错误。产品帮助组织把分散式扫描升级为  
   
规范化管理流程  
   
，覆盖资产可见性、定期漏洞检测、配置评估、补丁管理及修复控制，同时压缩安全和 IT 团队的运营工作量。  
  
  
02  
  
CAPABILITIES  
### 核心能力  
  
  
资产清查：先让资产看得见  
  
您无法保护您看不见的东西  
   
。这句老话在漏洞管理领域依然成立，也是绕不开的前提。过时的电子表格和不完整的清单，支撑不了风险决策。  
  
卡巴斯基漏洞管理支持两种清查方式：  
  
基于代理的资产清查  
  
用代理组件收集设备、操作系统和已安装软件信息，把漏洞与具体资产关联起来，维护基础架构的最新视图。  
  
基于网络的清查  
  
发现网络中的资产，包括未安装代理的设备，覆盖可能超出标准管理范围的部分。  
  
两种方式同时铺开，Windows 和 Unix/Linux 环境都能  
   
统一清查和分析  
   
。混合基础架构里，不必为不同系统另起炉灶。  
  
漏洞检测：覆盖与排序并重  
  
漏洞检测要解决两件事：把资产覆盖全，把风险排明白。  
  
覆盖靠扫描。  
   
按计划自动扫描  
   
定期运行，跟踪新漏洞和安全态势变化，不需要手动触发。具体手段有两类。  
   
基于代理的扫描  
   
，用已安装的卡巴斯基组件分析工作站和服务器上的漏洞，优势在于无须传输服务账户凭据做远程访问，深度评估照样成立。  
   
无代理网络扫描  
   
则面向没有代理的资产，从端口和服务层面识别易受攻击的服务。  
  
排序靠优先级。漏洞按严重性、资产上下文和对基础架构的潜在影响评估，团队  
   
聚焦最重大的风险  
   
，而不是按发现顺序逐条处理。

— IT 资产清查与漏洞检测的能力矩阵，代理与网络两条线互补覆盖  
  
配置评估：错误配置也是入侵入口  
  
错误配置可能造成  
   
与未修补 CVE 同样严重的风险  
   
，却常常被漏掉。  
  
卡巴斯基漏洞管理按安全要求、内部策略和适用标准检查配置参数，识别那些  
   
扩大攻击面的配置错误  
   
。基于安全最佳实践和监管要求的  
   
预定义配置文件  
   
，简化了合规性控制流程，审计准备工作也更从容。  
  
补丁管理：修复漏洞，而不只是报告漏洞  
  
扫描器只能显示问题。企业真正需要的，是  
   
风险实际下降  
   
。  
  
卡巴斯基漏洞管理把补丁管理集成进统一的漏洞管理流程，结合卡巴斯基端点安全实现  
   
集中的更新和补丁部署  
   
。借助与卡巴斯基安全中心 Linux 的集成，Windows 更新也能一并管控。补丁管理任务可以嵌进现有的卡巴斯基管理基础架构，从漏洞检测到修复的推进在受控流程内完成，  
   
缩小检测与实际修复之间的差距  
   
。  
  
修复验证：闭环的最后一步  
  
修复完成后要验证。团队需要知道哪些风险已处置、哪些隐患待处理、哪些节点还需要安全或 IT 团队进一步介入。  
  
修复状态跟踪把漏洞管理从一次性检查转变为  
   
受管闭环流程  
   
：  
   
发现、优先级排序、修复、验证  
   
。  
  
统一工作流：一个控制台管到底  
  
漏洞、资产、配置、更新若分散在不同流程里，协作成本就下不来。  
  
统一管理控制台  
   
把这几个环节集中在一处，减少流程碎片化，安全团队与 IT 运维的协作对接随之简化。  
   
情报报告  
   
输出资产和漏洞报告，安全团队、IT 运维及管理层都能掌握当前风险态势，追踪风险降低工作的阶段进展。  
  
集成方面，产品支持与卡巴斯基端点安全、卡巴斯基安全中心及  
   
卡巴斯基 SIEM  
   
对接，漏洞数据可以纳入更广泛的  
   
网络风险管理体系  
   
，安全信息统一汇聚与协同利用。

VALUE  
### 业务价值  
  
  
方案的价值最终要落到团队日常的改善上。文档给出五个方向：  
  
1  
资产和漏洞的可见性和控制。维护对基础架构、已安装软件和相关漏洞的最新视图。  
  
2  
更快的响应周期。扫描、补丁管理和修复控制结合，帮助团队更快地从漏洞检测走向修复闭环，缩短漏洞修复的平均时间。  
  
3  
提高安全团队效率。集中化管理和报告减少人工工作，安全和 IT 团队可以专注其他重要风险。  
  
4  
降低监管和行业合规差距的风险。配置评估、报告和修复监控展示可量化的风险降低，为内部和外部审计提供支持。  
  
5  
与多项卡巴斯基产品的原生集成。产品作为卡巴斯基统一安全生态系统的一部分开发，漏洞数据能在更广泛的网络风险管理环境中使用。

SUMMARY  
### 总结  
  
  
漏洞管理的分水岭不在能不能扫到，而在  
   
扫到之后能不能闭环  
   
。  
  
卡巴斯基漏洞管理的思路是把资产清查、漏洞检测、配置评估、补丁管理和修复验证串成一条  
   
受管流程  
   
：先看清资产，再按风险排序，修复跟上，最后验证确认。配合统一控制台与卡巴斯基生态集成，安全团队和 IT 运维在  
   
同一套流程  
   
里协作。  
  
对正在被扫出来一堆、修不动困扰的团队，这套方案值得放进评估清单。
