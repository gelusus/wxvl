#  Tailscale SSH 漏洞可导致提权至 root  
sec随谈
                    sec随谈  sec随谈   2026-10-27 01:15  
  
网络安全研究员 Erica Windisch 近日披露了影响 Tailscale SSH 实现的严重漏洞。  
Tailworm 研究门户  
发布的研究详细说明了 Unix 套接字转发和权限方面的严重缺陷。控制一台已授权设备的攻击者可以利用转发路径访问特权服务，进而提升权限，获取目标节点的完整 root 访问权限。  
  
**跨已授权 Tailnet 节点的权限提升**  
  
Tailscale SSH 用一套集成的、基于身份的架构取代了传统的 OpenSSH 配置。在这种模式下，由 tailnet 访问控制列表（ACL）决定哪些设备可以连接目标服务器。但已授权的客户端节点一旦被攻破，这种基于信任的架构就会带来严重风险。  
  
研究人员在测试中发现，普通的转发会话会暴露本地的特权资源，攻击者可以借此绕过预期的限制，访问仅限 root 的服务。恶意攻击者还能直接从目标机器上提取节点认证密钥，从而注册未经授权的设备，并在内部 tailnet 中横向移动。  
  
**Tailscale 确认研究结果并着手修复**  
  
Tailscale 工程师已确认上述发现，并立即启动了安全审查。开发人员在一篇关于  
近期 Tailscale 漏洞报告  
的官方讨论中介绍了正在进行的修复工作。维护者正在重新设计 Unix 套接字的授权逻辑，并限制后台转发行为。  
  
相关代码改动已经开始合入项目仓库。开发人员已合并 Pull Request 21937，为专用的 SSH Monitor 建立通信通道。工程师还在评审 Pull Request 21942，该 PR 会把所有转发操作交给这个隔离的监控进程处理。维护者确认受影响的配置范围后，将发布正式安全公告和软件补丁。  
  
**网络管理员应立即采取的加固措施**  
  
各组织应立即审计现有的 tailnet 访问策略，把 SSH 权限严格限制在必要的用户和机器范围内。  
  
**禁用套接字转发并强制重新认证**  
  
各团队可以在所有终端上禁用套接字转发，从而阻断这一攻击途径。具体做法是在 tailscaled 守护进程的环境中把环境变量 TS_SSH_DISABLE_FORWARDING  
 设为 1  
。这是一项临时防护措施，会禁用套接字转发，但不影响普通的终端会话。处理敏感业务的企业部署还应启用 SSH check 模式，要求用户在登录敏感系统前重新进行交互式认证。
