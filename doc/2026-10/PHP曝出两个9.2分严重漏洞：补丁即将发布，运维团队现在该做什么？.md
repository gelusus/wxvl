#  PHP曝出两个9.2分严重漏洞：补丁即将发布，运维团队现在该做什么？  
 白安全组   2026-10-21 08:58  
  
网络安全快讯 · 2026年10月21日  
  
PHP 安全团队预告即将发布紧急更新：两个核心漏洞的 CVSS v4.0 评分均为 9.2。  
  
它们被外部安全机构关联到 CVE-2026-109618 和 CVE-2026-109619，并被认为可能带来远程代码执行风险。PHP 广泛用于网站、业务后台和内部系统，运维团队现在就该盘点资产、预留升级窗口。  
  
**先说清楚：**  
截至本文整理时，PHP 官方尚未公布完整技术细节、精确受影响版本和确认有效的临时缓解方案。“PHP2Shell”是社区称呼，不是官方漏洞名称。  
## 01｜目前确认了什么？  
  
PHP 官方公告确认：此次安全更新针对两个严重漏洞，评分均为 **CVSS v4.0 9.2**  
。计划于 **10 月 21 日 14:00 UTC（北京时间 22:00）**  
发布；若技术细节提前泄露或出现实际利用证据，也可能提前发布。  
  
欧盟计算机应急响应团队 CERT-EU 提醒组织尽快识别 PHP 资产，并准备在修复版本发布后立即升级。关于“PHP 5 以后所有版本都受影响”的说法，官方尚未确认，不能据此直接判断单台服务器是否存在漏洞。  
## 02｜为什么要连夜盘点？  
  
PHP 资产远不止 WordPress。企业官网、电商、CRM、工单、运维面板、内部 API、定时任务和容器，都可能运行不同版本的 PHP。系统自带、面板内置和容器镜像中的 PHP，还可能由不同团队维护。  
  
若远程代码执行在常见部署中成立，攻击者可能获得 Web 服务账号权限，进而读取配置与数据库凭据、写入站点文件或接触内网资源。实际可利用条件和影响范围仍需等待官方公告。

## 04｜补丁发布前的五项动作  
  
**① 列清单：**  
记录业务、服务器、PHP 版本、部署来源、是否公网开放和维护人。  
  
**② 排优先级：**  
优先处理公网入口、敏感数据系统、具备上传功能以及可访问内网的服务。  
  
**③ 备升级窗口：**  
确认软件源、主机面板或容器镜像的更新渠道，并备好回滚方案。  
  
**④ 缩小暴露面：**  
限制非必要接口和管理后台访问；暂时无法升级的系统可考虑隔离。  
  
**⑤ 盯异常：**  
关注 PHP 进程崩溃、异常子进程、可疑外联和文件写入，保留日志以便排查。  
## 05｜补丁发布后如何验收？  
  
先按 PHP 官方公告确认受影响与修复版本，再通过可信渠道升级。升级后重启 Apache、PHP-FPM 和常驻 PHP 进程；容器需要重新构建并发布镜像。最后从真实业务入口核验正在运行的版本，并回看升级前后的日志。  
  
**不要做的事：**  
不要在生产环境运行来源不明的利用脚本；不要只凭命令行 PHP 版本宣布修复完成；不要把 WAF 通用规则视作补丁。
