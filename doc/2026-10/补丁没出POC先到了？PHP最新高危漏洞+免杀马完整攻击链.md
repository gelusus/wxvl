## 01 先看入口：这漏洞为什么吓人  
  
按目前公开信息，两个洞都是 PHP 解释器/引擎层的远程代码执行（RCE），CVSS 9.2，属于"严重"。  
  
三个关键信号，每条都值得细品：  
  
**信号一：mod_php 和 PHP-FPM 两条路径都能打。**  
也就是说，漏洞大概率在解释器/引擎层，和 SAPI 架构无关。别再说"我用 FPM，不关我事"。  
  
**信号二：回显是 www-data。**  
不是 root，但已经够要命——数据库凭据能读、WebShell 能写、横向移动的起点有了。  
  
**信号三：影响面极大。**  
有统计称约 150 万台暴露主机的 59% 还在跑 PHP 8.1 或更早分支——这些版本已 EOL，今天就算补丁发出来，它们也等不到修复包。  
  
德国安全团队甚至拿它跟 Log4Shell 比：如果这两个洞能免认证、通过普通 HTTP 请求触发、影响常规配置，实际影响面可能超过 Log4Shell。  
  
原因很直白：Log4Shell 的战场在 Java 企业内网，PHP 的战场在公网——WordPress、Drupal、Magento 和绝大多数共享主机，全靠它撑着。

攻击者拿到 www-data 权限后，第一件事往往是：往服务器上留一个能持久控制的"后门"。  
  
这个后门，就是 WebShell（一句话木马）。  
  
它的逻辑很简单：把一段能执行命令的 PHP 代码放到目标站点目录里，然后通过 HTTP 请求传参执行。

但问题来了——这句太经典了，杀软、WAF、主机安全产品、甚至扫描器，一眼就能认出来。  
  
于是，"免杀"成为 WebShell 能否站住脚的关键。  
  
免杀的本质就一句话：**让高危函数和特征签名，看起来不像它们自己。**

把命令拼接、把函数名拼接——"system" 拆成 "sys"+"tem"，在静态扫描眼里就不是高危函数名了。  
  
同类手法有一串：array_filter、array_walk、iterator_apply、foreach 动态调用，都是把函数名先拆开、再触发。  
  
但这一类玩法，安全引擎早就摸透了，拼串特征会被标记。于是要继续升级。
