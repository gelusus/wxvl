#  Linux内核TCP漏洞，CVSS评分9.8，影响Ubuntu、Red Hat及其他发行版  
原创 ZM
                    ZM  暗镜   2026-10-30 22:00  
  
Linux 内核 TCP 代码中的一个漏洞（编号为CVE-2026-98432）会影响 Ubuntu、Red Hat Enterprise Linux (RHEL) 和其他 Linux 发行版。内核自身的 CVE 团队根据 CVSS 评分标准，将其评为 9.8 分（满分 10 分）。  
  
10 月 27 日， Anthropic 公司表示，其 AI 模型编写了一个利用该漏洞的漏洞利用程序，允许没有凭据的远程攻击者在具有多路径 TCP 监听器的 Linux 服务器上以 root 身份运行命令。  
  
截至10月29日，Ubuntu和RHEL尚未发布修复后的内核。Red Hat、Amazon、Oracle和SUSE对该漏洞的评分在5.9到8.1之间，低于内核团队给出的9.8分。  
  
该缺陷是建立新的 IPv4 TCP 连接的代码中存在竞态条件。它会导致内核读取已释放的内存，这种错误类型被称为释放后使用 (use-after-free)。  
  
内核修复程序将漏洞报告者归功于 Anthropic 的研究员 Xinyang Ge。无论是 CVE 记录还是修复程序本身，都没有提及多路径 TCP (MPTCP)。该漏洞与 MPTCP 的关联来自 Anthropic 的公告。  
  
MPTCP允许一个连接同时使用多个网络路径。在 Linux 系统中，应用程序在打开套接字时必须请求 MPTCP。  
  
Anthropic 的公告称，该漏洞“已在上游修复，并已移植到所有维护的稳定内核分支”。对于发行版用户而言，该修复程序仅包含在厂商提供的内核软件包中。Debian、Oracle Linux、SUSE 和 Amazon Linux 已发布了修复后的软件包（至少在其部分内核中如此），但 Ubuntu 和 RHEL 尚未发布。

竞争发生在 TCP 握手期间。连接建立完成后，内核会将存储在待处理请求中的 IP 选项传递给新的套接字，而不会进行复制。  
  
如果在另一个 CPU 仍在使用该选项来响应重新连接请求时该套接字被销毁，内核将读取已释放的内存。  
  
IPv6 不受此竞争条件的影响，因为内核会复制 IPv6 连接的选项。  
  
该漏洞是在 Linux 4.4 中引入的。内核开发人员在 10 月 5 日应用了修复程序，比 CVE 发布早了十天。  
  
该修复方案使内核等待其他 CPU 完成读取选项后再释放它们。  
  
内核的 CVE 团队在 10 月 24 日将 9.8 分添加到 CVE 记录中，这是在发布 CVE 九天后。  
  
该评分假设攻击者发送一个带有 IPv4 路由记录或时间戳选项的 TCP 连接请求，然后重新发送该请求以试图赢得竞争。该团队认为攻击复杂度较低，并表示竞争双方都是“攻击者造成的”。  
  
研究团队表示，在这种情况下，该漏洞可能会将附近的内核内存发送回攻击者，损坏内核内存，或者导致系统崩溃。  
  
截至 10 月 28 日，国家漏洞数据库(NVD) 尚未添加自己的评分，显示的是内核团队给出的 9.8 分。Ubuntu 的页面也显示了该评分。  
  
红帽公司的 CVE 页面将此漏洞的严重程度评为“中等”，评分为 5.9 分，因为修复难度较大。页面指出，最可能的结果是内核崩溃，理论上也可能导致内存损坏，并且“尚未发现对机密性或完整性造成影响”。  
  
红帽公司于 10 月 29 日更新的机器可读安全公告文件将该漏洞的影响等级列为“重要”，并对其机密性和完整性造成高度影响，评分为 8.1。红帽公司的漏洞跟踪系统也在同一天将该问题的严重性从“中”提升至“高”。当天，CVE 页面显示该漏洞的严重性等级为“中等”，评分为 5.9。  
  
Oracle 和 SUSE 也给这个漏洞打了 8.1 分，使用的 CVSS 向量与 Red Hat 的安全公告文件中的相同。除了攻击复杂性之外，这些分数在所有指标上都与内核团队的评分一致；厂商对攻击复杂性的评分很高，而内核团队的评分很低。亚马逊的评分是 7.0 分。  
  
Anthropic公司在10月27日的一篇博文中描述了其人工智能模型Claude发现并利用的Linux漏洞。HAnthropic公司表示，Claude是在“初步提示”下编写了该漏洞利用程序。  
  
该漏洞利用分两个阶段进行。首先，利用竞争条件诱使内核向攻击者发送额外的字节。一旦其中一个回复包含内核地址，攻击者就可以绕过内核内存地址随机化机制（KASLR）。其次，同样的漏洞会导致缓冲区溢出，并将回调指针覆盖为攻击者已放置在内核内存中的有效载荷的地址。当内核调用该指针时，有效载荷会以 root 用户身份执行攻击者选择的 shell 命令。  
  
该公司表示，即使攻击失败，也只会导致一次连接尝试失败，不会导致系统崩溃，因此攻击者可以继续尝试。在他们的测试中，泄露内核地址耗时48分钟，而执行命令则又耗时5分钟。红帽公司表示，能够访问暴露的 TCP 服务的远程攻击者可能会触发竞争条件攻击。然而，Anthropic 的 root 漏洞利用针对的是具有多路径 TCP 监听器的服务器。该文章并未说明没有多路径 TCP 监听器的服务器是否也会受到同样的攻击。  
  
截至10月29日，无论是厂商公告、CVE记录还是Anthropic公司发布的帖子，均未报告利用该漏洞发起的攻击。卢森堡CIRCL于10月28日更新的CISA已知已利用漏洞目录副本中也未出现该漏洞。
