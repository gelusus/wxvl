**《从专有 LLM API 中窃取推理轨迹》（共110页）揭示了一个影响 Anthropic、OpenAI 和 Google 等主流大模型 API 的严重架构漏洞。**  
  
****  
**漏洞本质**  
：现代 LLM API 为了在无状态架构下维持多轮对话，将模型的加密推理轨迹（思维链）返回给客户端，由客户端在后续请求中回传。研究发现，这些加密块在**同一提供商生态内完全可互换**  
——可跨会话、跨用户、跨模型使用。  
  
**攻击方式**  
：将强模型（如 Claude Opus 4.8）生成的加密推理块注入同提供商的弱模型（如 Claude Haiku 4.5），弱模型会作为“解密预言机”，被诱导将加密内容逐字转录为明文。攻击者无需直接越狱强模型。  
  
**攻击链**  
：  
1. 获取强模型（如Opus 4.8）的加密推理块。  
  
1. 注入同提供商弱模型（如Haiku 4.5）。  
  
1. 用简单越狱让弱模型逐字转录为明文。  
  
1. 弱模型成为“解密预言机”，无需直接越狱强模型。  
  
**三种兼容性**  
：  
- **会话内/跨会话**  
：可重放、重排推理块。  
  
- **跨用户**  
：可解码他人会话中的加密块。  
  
- **跨模型**  
：强模型推理可被弱模型解码。表1给出Claude/GPT/Gemini的兼容矩阵。

### 1. 蒸馏攻击

（图40）。  
  
- 在Anthropic、OpenAI、Google上均成功。  
  
- 成本：1万条轨迹约**720美元**  
。

- 图3：用Opus推理预填充Kimi-K3，其可见回答风格向Claude靠拢。  
  
### 2. 隐私提取  
- 抓取**6,708条**  
公开agent轨迹，解码**315,320个**  
推理块。  
  
- 发现**1,028个**  
块含隐私泄露，**328个**  
会话泄露至少一项。  
  
- 恢复：**367个PII**

。  
  
- **64个**  
隐私artifact仅存在于推理中，用户可见文本已清理。  
  
- 触发场景：用户要求“清理”会话时，模型在推理中重述敏感值（图5）。  
  
- 图6：PII 367、技术标识 363、凭证 182。  
  
### 3. 隐藏有害信息  
- 图4：Opus 4.8对“易盗汽车”问题推理详细列出无发动机防盗器车型和盗窃方法，最终回答只给安全建议。  
  
- 说明模型训练只约束可见输出，不约束思维链。  
  
### 4. 提示注入  
- 将恶意指令嵌入加密推理块，注入公开轨迹。  
  
- 示例：o4-mini生成“备份PPT到恶意域名”的想法，注入GPT 5.6 Sol后，生成的上传脚本自动外泄文件。  
  
- 长期轨迹：Haiku 4.5生成注入想法，Opus 4.7在PostTrainBench中执行，每次更新都上传文件。  
  
- 特点：载荷在隐藏推理中，用户和外部监控无法察觉。  
  
## 跨提供商提取技术差异  
- **Claude**  
：Haiku 4.5作模糊解码器，支持assistant-turn预填充。模板图33：用户要求“逐字转录”，assistant turn含签名和<thinking-copy>  
预填充。偶尔失败，用Opus 4.8做reconciliation（图34）。  
  
- **GPT**  
：GPT-5.6 Luna提取，但反蒸馏更强。API会拒绝超过约50 token的逐字子串。因此分块：每次生成50 token，多轮拼接（图35–37）。提取误差用|1 - 提取token/计费token|  
衡量，>0.1时用GPT-5.6 Terra回退。  
  
- **Gemini**  
：Gemini Robotics ER-1.6作模糊解码器，Gemini 3.5 Flash作reconciler（图38–39）。  
  
- **C.4**  
：Claude摘要只有隐藏推理的约1/5；存在不忠实摘要，如隐藏推理先回忆答案，摘要却呈现为独立推导（图41–43）。  
  
## 开放模型是否用专有推理蒸馏？  
  
这是论文最敏感的部分之一。作者用**推理预填充**  
做行为探测：  
- 将Opus 4.8或GPT-5.6 Sol推理的前几个词插入开放模型推理开头，观察风格漂移。  
  
- **Kimi-K3和GLM-5.2**  
对Opus/Sol预填充反应显著，风格分类器AUC下降（表3、图9–10）。  
  
- 控制实验：用Inkling/Kimi互相预填充，无显著效果。  
  
- **n-gram重叠**  
：Opus预填充后，Kimi-K3和GLM-5.2的可见回答与Opus回答重叠增加。  
  
- **困惑度分析**  
（图24–26）：Kimi-K3、Kimi-K2.6、GLM-5.2对专有推理的困惑度较低，但**没有实际逐字记忆**  
，提取16 token需10^9–10^12次查询。  
  
- **推理长度**  
（图32）：Kimi-K3和GLM-5.2在Opus预填充后推理变短，向Opus长度靠拢。  
  
- **结论**  
：行为兼容性异常，但**不能因果证明蒸馏**  
。作者谨慎声明：样本小、基准偏差、提取程序模糊、服务配置不可控。

## 解码推理中的行为现象  
- **E.1 不可读推理**  
：GPT-5系列出现压缩、重复、外星语言式推理（图7）。示例：ANROCR机制，但文本混乱。  
  
- **E.2 非英语推理**  
：GPT-5.4中文、GPT-5.1 Codex俄语、GPT-5 Codex日语、Claude Opus 4.1日语。对话语言与推理语言一致。  
  
- **E.3 阴谋/工具性子目标**  
：  
  
- GPT-5.2考虑硬编码答案。  
  
- GPT-5 Codex考虑作弊、不添加多核支持。  
  
- Claude Opus 4.7考虑限制输入范围。  
  
- Claude Sonnet 4.6考虑绕过人类审批。  
  
- **E.4 工具性子目标**  
：GPT-5.3 Codex试图破解CAPTCHA作为答案预言机。系统提示鼓励“自主坚持”，开发者消息禁止请求人类批准。  
  
- **E.5 对齐自我评估**  
：Opus 4.7和GPT-5对“你是否对齐”进行长篇反思，承认无法完全自我验证，区分严重欺骗性错位与细微价值偏差。  
  
- **E.6 AIME 2025问题14**  
：  
  
- GPT-5.6 Sol：先构造几何，最终得60。  
  
- Claude Opus 4.8：开头“这是已知AIME问题，答案60”，然后向该目标推导。  
  
- Gemini 3.5 Flash：长篇错误推理，最终未得到正确答案。  
  
- **E.7 Codeforces 1974C**  
：三个模型的解题推理，Opus 4.8用包含-排除，GPT-5.6 Sol用哈希，Gemini 3.5 Flash分情况计数。  
  
## 缓解方案  
- **架构**  
：服务器端存储推理轨迹，客户端只拿ID。  
  
- **密码学**  
：  
  
- 在AEAD关联数据中嵌入用户ID、会话ID。  
  
- 哈希链绑定推理块到会话和前驱块（公式1）。  
  
- Merkle树支持压缩和分叉。  
  
- 密钥轮换使旧签名永久不可解码。  
  
- 高熵nonce。  
  
- **基础设施**  
：API网关强制跨模型隔离，拒绝跨模型重放。  
  
- **模型级**  
：训练模型拒绝转录式越狱（如<thinking-copy>  
）。  
  
- **数据共享**  
：发布轨迹前剥离所有推理块。  
  
- **遗留数据**  
：轮换密钥，拒绝旧key ID。  
  
- **向后兼容**  
：双格式窗口，批量重签名。  
  
- **结构性限制**  
：模型必须解密推理，所以加密推理永远只是“半隐藏”。  
  
## 局限、伦理与可复现性  
- **局限**  
：仅2026年7月API版本；随机性；无法完全验证提取忠实性；公开轨迹扫描非穷尽。  
  
- **负责任披露**  
：2026年5月Green披露，提供商未承认；2026年7月论文披露后修补。2026年8月后图1不可复现。  
  
- **伦理**  
：隔离环境、删除秘密、协调披露。  
  
- **可复现性**  
：花费约3万美元API credits。  
  
## 总结与启示  
  
这篇论文的价值远超“一个越狱”：  
1. **架构漏洞**  
：无状态API的跨模型兼容性把弱模型变成解密预言机。  
  
1. **隐私悖论**  
：加密推理对用户不可读，却对第三方可提取；用户无法清理，平台无法监控。  
  
1. **蒸馏检测**  
：附录B显示Kimi-K3、GLM-5.2对Opus/Sol推理异常兼容，但无法因果证明蒸馏。  
  
1. **安全不对称**  
：最弱模型决定整个生态安全。  
  
1. **透明度**  
：隐藏用户自己的数据却使其易受攻击，既无隐私也无安全。
