#  Nginx UI 远程代码执行漏洞已披露，附 PoC 利用代码  
sec随谈
                    sec随谈  sec随谈   2026-10-10 01:30  
  
一个严重的 Nginx UI 远程代码执行漏洞允许已认证的攻击者在受影响服务器上执行任意代码。安全研究人员近期披露了该漏洞的完整细节及可用的 PoC 利用代码，管理员必须立即更新部署以保护基础设施安全。  
  
**为何值得重视**  
  
Nginx UI 项目在 GitHub 上拥有超过 11,600 个 Star，表明其拥有庞大的全球用户群。一旦攻击成功，攻击者将获得对底层服务器架构的完全管理控制权。由于该软件负责管理 Web 流量，被入侵的实例可能暴露高度敏感的运营数据，攻击者可读取加密密钥、篡改数据库记录并彻底中断核心业务运营。漏洞细节和 PoC 利用代码的公开披露大幅提升了现实攻击的风险，威胁行为者通常会密切关注公开披露信息以快速将漏洞武器化。目前尚未确认存在在野利用案例。  
  
**攻击原理**  
  
该漏洞通过系统备份恢复过程中的信任边界失效触发。攻击者首先以已认证的管理员身份建立会话，随后上传一个包含恶意应用清单的伪造配置备份文件。应用程序从攻击者提供的数据中派生备份签名密钥并解密载荷，随后在未经适当验证的情况下盲目接受该文件并覆盖受保护的应用程序设置。通过向特定配置参数中注入恶意操作系统命令，攻击者可强制应用程序执行任意命令，这些命令在应用程序的运行时上下文中执行，而该上下文通常具有较高的系统权限。  
  
**受影响版本**  
  
该后认证漏洞影响 Nginx UI 2.3.8 至 2.5.0 之前的版本，并绕过了此前旨在防止初始安装窗口期未认证访问的安全修复措施。  
  
**缓解措施**  
  
软件维护者已在 Nginx UI 2.5.0 版本中修复了该严重问题，此次更新引入了对恢复配置文件的严格验证机制，并使用服务器端安全密钥对备份进行认证。管理员必须立即部署此补丁以防止漏洞被利用。详情请查阅  
官方安全公告  
。
