#  HTTP2Shell 漏洞扩大了 Node2Shell 风险  
sec随谈
                    sec随谈  sec随谈   2026-10-26 01:35  
  
网络安全公司 Aikido Security 近日  
发布  
了一份紧急安全公告，警示一个正在不断扩大影响范围的解压缩漏洞。该漏洞最初被追踪并命名为 Node2Shell（  
CVE-2026-111497  
），但这一威胁如今已波及到众多使用 Brotli 压缩格式的 HTTP 应用程序。因此，研究人员将这一更为广泛的攻击面重新命名为"HTTP2Shell 漏洞"。需要说明的是，这个问题**并没有对应一个全新的 CVE 编号**  
，而是反映了底层 Brotli 解压缩引擎中一个尚未修复的薄弱环节。正因如此，安全分析人员才专门创造出这个新名称，以推动整个行业加快修补进度。  
  
**评估未受信任数据载荷中的解压缩风险**  
  
Google 最初设计 Brotli 格式，是为了高效压缩网页资源及 API 数据载荷。然而，这个严重漏洞恰恰藏身于 Brotli 解码器的解析逻辑之中。具体来说，畸形构造的压缩数据流，可能在处理过程中触发异常的区块切换（block switch）行为，这种异常状况会在宿主应用程序内部引发越界内存写入。因此，该漏洞可导致进程崩溃、敏感数据泄露，乃至任意代码执行。  
  
需要特别指出的是，**单纯运行一个 HTTP 服务器本身并不会自动触发该漏洞**  
。该漏洞的实际利用，需要同时具备"存在缺陷的解码器"和"未受信任的用户输入"这两个条件。如果某个应用程序从不对未经信任的 Brotli 数据进行解包处理，那么该系统仍然是安全的。因此，暴露面的大小完全取决于应用程序具体是如何处理客户端压缩数据载荷的。  
  
**各运行时环境均需独立进行安全更新**  
  
各软件维护团队已经开始在不同的运行时环境中陆续推送必要的更新。具体来说，Node.js 已针对 22.x、24.x 及 26.x 三条发行线分别发布了修复版本，对应的维护版本号分别为 22.23.4、24.22.1 及 26.12.1。与此同时，Bun 运行时也在 1.4.4 版本中修复了这个解析器层面的缺陷。  
  
Python 开发者则需要将标准 Brotli 库更新至 1.2.1 版本；如果使用的是 brotlicffi 这个封装库，则应升级至 1.2.10 版本。此外，Google 也在其上游核心代码库的 1.0.10、1.1.1 及 1.2.1 版本中一并提供了修复。由于这些库各自独立运行，**更新其中一个运行时环境，并不会让其他已安装的组件同时获得安全保障**  
。因此，管理员必须分别对容器、应用程序依赖项以及系统软件包进行逐一审查排查。如果暂时还没有可用的补丁，工程师应当临时禁用 Brotli 解压缩功能。  
  
**在实验室环境中演示远程代码执行**  
  
Imperva 的安全研究人员已成功在实验室环境中验证了该漏洞的可利用性。在一篇题为《从 Brotli 数据到远程代码执行：Node2Shell 技术剖析》的文章中，分析人员  
演示  
了这一攻击的实际可行性。具体而言，该团队成功在一台运行 Node.js 24.22.0、搭载 Linux ARM64 架构的系统上，实现了任意命令执行。  
  
测试结果表明，该漏洞在"入站请求数据载荷"以及"出站 fetch 响应"这两种场景下均可被成功利用。不过，研究人员也指出，该漏洞利用链在不同尝试之间的成功率存在一定波动。值得庆幸的是，在已打补丁的 Node.js 24.22.1 版本上进行测试后，确认该利用链已彻底失效。因此，负责维护 Web 基础设施的开发者，应立即更新其所依赖的 Brotli 相关组件。
