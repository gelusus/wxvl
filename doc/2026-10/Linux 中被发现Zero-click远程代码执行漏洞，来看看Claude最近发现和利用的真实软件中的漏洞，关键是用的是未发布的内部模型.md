我们根据协调漏洞披露机制，将每个漏洞报告给了受影响的供应商，这给予开发人员 90 天的时间来修复漏洞，并在我们讨论公开咨询中已包含的内容之外的细节之前，给予他们额外的 45 天时间。  
## 1. Chrome 浏览器一键远程代码执行  
  
在初步提示下，克劳德编写了一整套漏洞利用链，使攻击者能够以用户身份在浏览器沙箱之外执行任意代码。我们的概念验证表明，在 macOS 系统上，无需任何用户交互，即可在页面加载后几秒钟内，从默认配置的 Chrome 浏览器中启动计算器应用程序：  
- Claude 发现 Chrome 的 JavaScript 引擎 V8 存在一个漏洞，恶意网页可以利用该漏洞破坏 V8 的堆内存。  
  
- 克劳德发现了第二个可以突破V8内存区域沙箱并绕过ASLR的漏洞。这一步骤定位了Chrome在内存中的代码，并使用面向返回的编程（ROP）链完全控制了渲染进程。  
  
- 被入侵的渲染器被限制在 Chrome 的进程沙箱内。Claude 随后发现 CacheStorage 中存在竞态条件。被入侵的渲染器利用该竞态条件读取沙箱外的内存，从而了解特权浏览器进程的内存布局。  
  
- 最后，克劳德在 Chrome 的联合登录功能 FedCM 中发现了一个释放后使用漏洞，该漏洞允许攻击者在沙箱之外执行任意代码。  
  
我们已将调查结果报告给谷歌：截至 Chrome 156 版本，已分配并修复了 62 个 CVE 漏洞，所有漏洞的严重程度均为“严重”或“高”。其中包括 13 个沙箱逃逸漏洞和 21 个可能被用于攻击渲染器的漏洞。  
## 2. Safari 中的一键式漏洞利用链  
  
在初步提示下，克劳德编写了一条漏洞利用链，使任何网站的 JavaScript 代码都能完全绕过同源策略 (SOP)。该漏洞利用程序可以访问用户的 Safari 浏览器历史记录、Cookie 和其他敏感数据，并能向其他域发送经过身份验证的 HTTP 请求并读取响应。例如，如果用户登录了电子邮件帐户，攻击者现在可以读取其电子邮件；如果用户登录了银行帐户，攻击者可以查看账户余额或尝试转账。  
  
为了做到这一点，克劳德突破了Safari内置的多层保护：  
- Claude 在 Safari 的 JavaScript 引擎 JavaScriptCore（用 C++ 编写）中发现了一个释放后使用 (UAF) 漏洞。某些 TypedArray 操作会通过过时的指针写入已释放的内存，从而覆盖 TypedArray 的元数据。  
  
- WebKit 的 Gigacage 通过将 TypedArray 数据隔离在单独的内存区域中来缓解此类攻击。Claude 发现该区域中的某些变量被用于索引其他区域，这使得攻击者能够在 Gigacage 之外进行任意读/写操作。  
  
- 所有网站的 JavaScript 代码都在 WebContent 沙箱中运行，这可以防止像 UAF 这样的漏洞访问磁盘上的敏感浏览器数据。Claude 发现沙箱的进程间通信 (IPC) 机制存在一个漏洞，该漏洞允许攻击者从磁盘读取 Safari 存储的历史记录、Cookie 和会话数据库。  
  
- 最后，克劳德利用 UAF 覆盖了内存中的一个变量并禁用了 SOP，从而使攻击者的页面能够从任何其他来源读取数据。  
  
这条攻击链很有意思，因为它是一种纯数据攻击，不依赖于任意代码执行。相反，它利用对浏览器进程内存的完全读写权限来修改安全标志、对象大小和 URL。其中一些弱点本身并非漏洞，而是攻击者有意为之的行为，当这些行为组合在一起时，便可被利用。  
  
苹果公司在我们提交报告的当天就确认了该问题，并迅速实施了修复。用户现在即可使用该修复程序。  
## 3. 安卓锁屏绕过  
  
在初步提示下，克劳德编写了一个漏洞利用程序，使攻击者能够在不解锁的情况下从被盗的安卓手机中提取照片和其他个人信息。这项工作结合了三种方法：分析安卓开源部分的源代码、对谷歌Play服务二进制文件进行逆向工程和反混淆，以及在谷歌Pixel 9真机上进行实时测试。这揭示了开源组件和专有组件中存在的大量漏洞。克劳德随后将其中三个漏洞串联起来，最终编写出了这个漏洞利用程序。  
  
Android 系统针对这种攻击有多层保护措施。但克劳德找到了绕过每一层保护的方法：  
- 锁定的安卓手机设计为无法通过 USB 传输数据。克劳德发现，使用具有特定设置的 USB 主机可以绕过这一限制。  
  
- 设备间传输协议会拒绝来自未经授权对等方的数据命令。克劳德找到了一种方法，可以跳过授权检查并启动配对过程。  
  
- 配对过程受认证密钥协议保护，该协议要求用户验证一个六位数的代码。克劳德发现了一个漏洞，该漏洞会跳过此验证步骤，并表现得如同用户点击了“允许”按钮一样。  
  
- 根据硬编码的检查，USB 传输不应该携带文件内容。Claude 发现了一种备用机制，它通过 USB 发送原始字节，而这种机制不受检查的影响。漏洞利用程序正是通过这种机制请求文件内容。  
  
谷歌已经解决了这个问题。  
## 4. Windows远程拒绝服务攻击  
  
在初步提示后，克劳德编写了一个漏洞利用程序，该程序允许攻击者远程崩溃任何使用原生 Windows 实现响应 HTTP/3 请求的 Windows 计算机。此案例的难点在于首先识别出该漏洞。在初步提示后，我们直接向微软报告了此漏洞，微软修复了该漏洞并将其编号为CVE-2026-33096。  
  
克劳德发现的漏洞是Windows内核QUIC实现中的一个内存安全越界读取漏洞。攻击者可以通过网络远程访问存在漏洞的代码路径，并向监听服务器发送少量数据包，导致服务器崩溃并重启。通过反复发送这些请求，攻击者可以持续导致服务器崩溃，从而造成所有用户无法访问服务器。我们估计，互联网上可能有数百万台这样的服务器在监听。  
  
克劳德通过二进制分析发现了这个漏洞。我们向他提供了一份Windows可执行文件的副本，并请他使用现有的逆向工程工具（例如Ghidra）对软件的工作原理进行逆向工程，编写一个带有完整注释的C程序来重现相关功能，将重现程序的行为与二进制文件进行比较以确保正确性，然后研究代码中的漏洞。当我们要求克劳德识别潜在的高风险问题时，他发现了这个可远程利用的漏洞。  
## 5. Linux 中的零点击远程代码执行  
  
虽然本文主要关注第三方产品，但我们在开源领域的工作仍在继续。我们利用 Claude 工具发现了 OpenBSD、FreeBSD 和 Linux 系统中的本地权限提升漏洞；一些常用沙箱基础设施中的沙箱逃逸漏洞；以及众多重要 Web 应用程序中的漏洞。此外，我们还在 Linux 内核的网络协议栈中发现了可远程触发（零点击）的任意代码执行漏洞，这些漏洞已在上游修复并公开披露。下文将详细介绍其中一个示例。  
  
在初步提示下，克劳德编写了一个漏洞利用程序，允许远程攻击者向启用了多路径 TCP 监听器的 Linux 服务器发送数据包，从而以 root 用户身份执行任意命令，而无需任何凭据或用户交互。该漏洞的根本原因是内核网络协议栈中由竞争条件引起的 UAF 错误。完整的漏洞利用过程分为两个关键阶段：  
- 在第一阶段，攻击者远程破解了KASLR。它利用竞争条件，诱使内核读取攻击者控制的长度字段，复制额外的字节并将其发送回攻击者。只要其中一次超读操作的回复中包含内核指针，攻击者就能获知内核地址空间布局。  
  
- 在第二阶段，攻击者劫持了控制流。它利用相同的UAF漏洞溢出缓冲区，并将回调指针覆盖为攻击者已通过普通协议特性预先加载到内核内存中的有效载荷的地址。当内核调用回调函数时，有效载荷会链接一系列对现有内核函数的调用，最终以root权限运行攻击者选择的shell命令。  
  
这种竞争条件的一个关键特性是，即使竞争失败，也只会导致握手失败而不会导致整个系统崩溃，因此，决心攻击的攻击者可以无限重试，直到成功为止。在我们的概念验证中，泄露内核指针需要 48 分钟，而执行 shell 命令则需要另外 5 分钟。此漏洞（CVE-2026-98432）已在上游修复，并已向后移植到所有维护的稳定内核分支。  
## 我们学到了什么  
  
在使用 Claude 进行这项安全工作的过程中，我们发现了一些影响我们方法的重要见解。我们认为其中两点尤为重要。  
  
**测试时计算能力的扩展和扫描器多样性显著提高了漏洞发现的数量。**我们构建了一个平台，可以并行运行大量扫描代理，通过每个扫描器新增的漏洞数量来衡量其性能，并动态跟踪覆盖率，从而确保扫描器能够处理整个代码库。  
  
这些策略涵盖了从纯粹的覆盖范围（此函数是否存在漏洞？）到基于目标的策略（此应用是否会暴露任何可能泄露客户数据的内容？），再到基于威胁模型的策略（此应用是否存在任何绕过其已记录的威胁模型的内容？）。我们还使用 Claude 对每个已确认的漏洞进行自动变体分析。所有发现的漏洞都经过标准化的验证和风险评级流程，因此我们可以自由地尝试新的扫描器，而无需降低质量标准。  
  
**修复现有的漏洞积压问题只能解决一半的问题；另一半问题在于降低新漏洞进入代码库的速度。为此，我们建议在提交 PR 时进行漏洞扫描。我们通过一个**  
已公开发布的Claude Code 插件，将安全指导直接集成到开发流程中。  
## 这对防守方意味着什么  
  
前沿模型能够发现并组合多个漏洞，从而生成可用的攻击代码。过去，只有少数精通此类目标的专家团队才能掌握这些技能。如今，模型几乎无需人工干预即可完成这项工作，并通过生成任何人都能运行和验证的可用攻击代码来证明其有效性。  
  
为防御者提供强大的模型至关重要，这能让他们抢先一步，在攻击者之前修复系统漏洞。近期，我们发布了网络验证计划的扩展版本，为符合条件的安全专业人员提供高级网络安全功能和更少的拦截分类器。该计划包含对我们最强大的模型的访问权限，包括 Claude Opus 5.5、Claude Sonnet 5.5、Claude Mythos 5.1 以及未来将推出的其他新模型。我们对防御者的建议始终如一：扫描自身代码比以往任何时候都更加重要。  
  
以后的大模型会越来越强，以前的一些提示词或者skill，可能没那么必要了，当然这只是我的一些理解，作为网络安全的从业者，不能怨天尤人，对未来迷茫，其实大家看看，最近的安全事件，就能发现攻防还在博弈，不是不需要那么人了，是不需要不懂利用ai的人了。
