**修复方案：升级为主，缓解为辅**  
  
****  
**官方已提供安全版本：**  
  
请立即升级至 PHP 8.5.12、8.4.27、8.3.36 或 8.2.35。升级后必须重启相关服务（php-fpm、Apache、Nginx 等）。  
  
  
**如何升级：**  
  
优先使用操作系统包管理器更新（Ubuntu/Debian、CentOS/RHEL 等主流发行版已推送修复包）。  
  
  
或从官方下载页面获取源码包自行编译安装：https://www.php.net/downloads.php  
  
  
升级完成后执行 php -v 确认版本号已更新。

PHP 8.1 / 8.0 / 7.4：官方提供了最小源码回移植，可自行编译临时修复。相关链接如下：

**PHP 7.3 及更早（含 5.x）：**  
  
官方无补丁，风险极高。公网暴露系统如短期无法升级，建议临时限制访问或下线。  
  
  
**公网优先修复：**  
  
所有对外公网接口均为高危攻击面，应优先修复；内网隔离系统可延后排期，但仍需限期升级。  
  
**临时缓解措施（仅作为过渡手段，不能替代正式升级）**  
  
若无法立刻升级，请立即落实以下措施并重启所有 Worker：  
  
  
设置 session.upload_progress.enabled = 0禁用会话上传进度；  
  
  
设置 memory_limit = -1（建议通过 php_admin_value 强制生效）该设置仅用于降低部分攻击路径风险，会取消 PHP 自身的内存上限，应结合资源隔离、请求限制和内存监测使用，并评估内存耗尽对服务可用性的影响；  
  
  
降低 post_max_size；  
  
  
PHP 8.5 环境额外设置 fatal_error_backtraces = 0；  
  
  
在 Web 服务器/反向代理层限制请求体大小、字段数量、multipart 部分数等。  
  
  
**注意：**  
临时措施只能降低部分攻击路径风险，**无法完全消除威胁。**  
正式升级仍是唯一彻底的解决方案。
