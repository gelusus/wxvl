#  NGINX 爆出 3 个高危漏洞！可远程使服务崩溃，特定条件下可代码执行  
原创 维度攻防
                        维度攻防  维度攻防   2026-10-15 04:37  
  
**重要安全通告**  
：F5 官方披露 NGINX 开源版与 NGINX Plus 共计 3 个严重内存安全漏洞。未经身份认证的远程攻击者，发送特制 HTTP 请求即可造成工作进程崩溃；在特定配置环境下，如果 ASLR 被关闭或可被绕过，漏洞还存在**远程代码执行风险**  
。  
  
三个漏洞编号：**CVE‑2026‑97205、CVE‑2026‑93479、CVE‑2026‑15176**  
。 CVSS v3.1 评分均为**8.1（高危）**  
，CVSS v4.0 评分达到**9.2（严重）**  
。漏洞全部作用于处理业务流量的数据平面，而非管控平面。  
> 注意：**并非所有 NGINX 默认安装就会中招，漏洞触发需要特定版本 + 特定业务配置同时满足**  
，需要管理员核对版本与实际 nginx 配置文件。  
  
## 🔍 三个漏洞详细解读  
### CVE‑2026‑97205：ngx_http_core_module 释放后重用（Use‑After‑Free）  
  
触发条件：开启异步文件 IO（AIO），同时 SSI 页面使用include virtual  
指令。  
  
NGINX 工作进程会访问已经释放的内存，引发内存损坏、worker 进程异常退出。  
> 漏洞由安全研究员 Cyberlanc3r 上报。  
  
### CVE‑2026‑93479：map 指令相关堆缓冲区溢出  
  
和map  
指令、正则捕获变量相关。 当root  
指令、访问日志格式，在 map 输出变量之前使用正则捕获变量；或者字符串表达式使用不可缓存变量时，会触发风险。  
  
攻击者构造恶意请求，让工作进程向已分配内存边界之外写入数据，导致进程重启。  
> 由 Tolmo 公司 Matt Suiche、Mateusz Gierblinski 协同上报。  
  
### CVE‑2026‑15176：ngx_http_core_module 堆缓冲区溢出  
  
风险配置场景：location 块中同时使用alias  
 + rewrite  
，并且set  
/return  
指令引用$request_filename  
； 另外，访问日志log_format  
中使用$request_filename  
也存在风险。  
  
无需身份认证即可触发，但是需要服务端满足特定配置条件，该漏洞由 F5 内部发现。  
## 📉 受影响版本范围  
#### NGINX 开源版  
1. CVE‑2026‑97205 / CVE‑2026‑15176  
  
- 1.31.0 ~ 1.31.6  
  
- 1.0.0 ~ 1.30.5  
  
> CVE‑2026‑15176 还影响古老 0.x 版本分支  
  
1. CVE‑2026‑93479  
  
- 1.31.2 ~ 1.31.6  
  
- 1.30.0 ~ 1.30.5  
  
#### NGINX Plus  
- 37.0.0 ~ 37.0.4，三个漏洞全部命中  
  
#### 相关衍生产品同样受影响  
  
NGINX Instance Manager、F5 WAF for NGINX、NGINX Gateway Fabric、部分 NGINX Ingress Controller 版本。  
## ✅ 修复版本（强烈建议升级）  
1. **NGINX 开源版**  
：升级至 **1.31.7 或 1.30.6**  
  
1. **NGINX Plus 37.x**  
：升级至 **37.0.5.1 或 37.1.0.1**  
  
1. 配套组件：  
  
- NGINX Instance Manager → 2.24.0  
  
- F5 WAF for NGINX → 5.16.0 /5.14.2  
  
- NGINX Gateway Fabric → 2.8.0  
  
- NGINX Ingress Controller →5.7.0  
  
> 部分老旧分支不再维护，请迁移至受支持版本获取补丁。  
  
## 🛠️ 临时缓解方案（无法立刻升级时使用）  
> ⚠️ 配置规避不等于彻底修复，只能阻断已知风险路径，**升级补丁才是最优方案**  
。  
  
1. **CVE‑2026‑97205**  
：关闭 AIO 或者关闭 SSI  
  
- 关闭 AIO 会在高负载大静态文件、流媒体场景带来性能损耗；关闭 SSI 则不再解析 SSI 标签。  
  
1. **CVE‑2026‑93479**  
：正则尽量使用命名捕获，不要使用$1/$2  
这类无命名捕获，并且捕获变量仅在匹配块内部使用。  
  
1. **CVE‑2026‑15176**  
：尽量避免 location 块内使用alias  
，减少$request_filename  
变量使用。
