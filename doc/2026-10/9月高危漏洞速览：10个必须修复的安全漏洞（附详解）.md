腾讯云安全研究团队综合评估“漏洞危害程度、影响范围、技术细节披露情况、安全社区关注度、在野利用情况”等因素，筛选出需优先修复的安全漏洞，定期发布企业必修安全漏洞清单。

一、Nacos权限绕过漏洞  
  
  
概述：  
  
腾讯云安全近期监测到关于  
Nacos  
的风险公告，  
漏洞编号：  
TVD-2026-58044  
。  
成功利用此漏洞的攻击者，可绕过身份验证创建新的管理员账户，进而获取  
Nacos  
服务端的完全控制权限。  
  
Nacos  
是阿里巴巴开源的服务注册与配置管理平台，致力于帮助开发者更敏捷地交付和管理微服务架构。它提供服务发现和健康检查功能，支持基于  
DNS  
和  
RPC  
的服务发现方式，同时提供动态配置服务，允许以热更新方式管理应用配置。  
Nacos  
还支持动态  
DNS  
服务，具备权重路由和健康检查能力，其核心特性包括服务发现、配置管理、动态  
DNS  
和服务管理  
API  
，广泛应用于云原生和微服务架构场景。  
Nacos 3.x  
版本引入了全新控制台界面和增强鉴权机制，是企业管理微服务基础设施的重要组件。  
  
据描述，该漏洞源于  
Nacos 3.0.0  
至  
3.2.3  
版本中鉴权作用域存在错配缺陷，导致权限校验机制未能正确覆盖特定  
API  
路径。远程未授权攻击者可通过向目标  
Nacos  
服务端发送特制请求，绕过身份验证并创建新的管理员账户，进而获取服务端的完全控制权限。

二、JeecgBoot JimuReport 远程代码执行漏洞  
  
  
概述：  
  
腾讯云安全近期监测到关于  
JeecgBoot JimuReport  
的风险公告，  
漏洞编号：  
TVD-2026-58833  
。成功利用此漏洞的攻击者，可在无需认证的情况下通过构造恶意表达式执行任意系统命令，最终实现远程代码执行。  
  
JeecgBoot  
是一款基于代码生成器的低代码开发平台，专注于企业级  
Java Web  
应用快速开发。它集成了  
Spring Boot  
和  
MyBatis-plus  
框架，支持在线表单设计、在线报表配置、在线流程编排等核心功能。  
JimuReport  
（积木报表）是  
JeecgBoot  
生态中的开源报表组件，提供可视化报表设计器，支持通过  
Aviator  
表达式引擎动态计算数据，并支持导出  
Excel  
、  
PDF  
等多种格式。其导出接口通过注解控制访问权限，广泛应用于企业数据可视化和报表生成场景，是不法分子频繁攻击的目标。  
  
据描述，该漏洞源于  
JimuReport  
导出接口  
/jmreport/auto/export  
标注了  
@JimuNoLoginRequired  
注解且被  
Shiro  
配置为  
anon  
，允许未认证访问。攻击者可通过该接口传入以  
=  
开头的恶意  
params  
参数值，该值经  
ExpressUtil.a  
处理后进入  
Aviator  
表达式引擎执行。虽然  
Aviator  
禁用了  
NewInstance  
功能，但  
use  
和静态方法调用仍可用，攻击者可利用  
classpath  
上的  
groovy.util.Eval.me  
方法执行任意系统命令。

三、JeecgBoot JimuReport 远程代码执行漏洞  
  
  
概述：  
  
腾讯云安全近期监测到关于  
JeecgBoot JimuReport  
的风险公告，  
漏洞编号：  
TVD-2026-60895  
。成功利用此漏洞的攻击者，可通过未授权访问的导出接口绕过  
Aviator  
沙箱限制，调用系统命令执行方法，最终实现远程代码执行。  
  
据描述，该漏洞源于  
JimuReport  
中  
/jmreport/auto/export/python/plugin  
导出接口存在未授权访问，且在处理  
reportParams  
参数时，对用户输入的  
p  
参数值直接通过  
ExpressUtil.eval  
进行表达式求值。攻击者可利用该接口绕过  
X-Sign  
头签名校验，通过两步构造恶意  
Aviator  
表达式：首先利用  
Java  
反射机制获取  
FunctionMissing  
实例覆盖沙箱限制，随后通过  
Aviator  
沙箱逃逸调用  
java.lang.Runtime.getRuntime().exec()  
执行任意系统命令。

概述：  
  
腾讯云安全近期监测到关于  
GitLab CE/EE  
的风险公告，  
漏洞编号：  
TVD-2026-64041  
（  
CVE  
编号：  
CVE-2026-85706  
，  
CNNVD  
编号：  
CNNVD-2026-20211096  
）  
。成功利用此漏洞的攻击者，可在无需认证的情况下读取  
GitLab  
服务器上的任意文件，获取敏感配置信息和凭证，最终可能导致服务器被完全接管。  
  
GitLab  
是一款开源的  
DevOps  
平台，提供从项目规划到代码管理的全流程支持。  
GitLab CE  
（社区版）和  
EE  
（企业版）集成了  
Git  
代码仓库管理、  
CI/CD  
流水线、代码审查、  
Issue

Wiki  
等核心功能。其内置的仓库提交  
API  
允许用户通过  
HTTP  
接口访问代码库中的提交记录和文件内容。  
GitLab  
采用  
Ruby on Rails  
框架开发，支持多实例集群部署，广泛应用于企业内部代码协作和持续交付场景，是全球开发团队最常用的代码托管平台之一。  
  
据描述，该漏洞源于  
GitLab CE/EE  
中仓库提交  
API  
存在身份验证缺失和路径限制不当的双重缺陷。一方面，该  
API  
在特定条件下未正确强制身份认证，允许未授权用户访问；另一方面，文件路径未被正确约束在预期目录范围内（  
improper path confinement  
）。攻击者无需登录即可通过构造特制请求，利用路径遍历读取  
GitLab  
服务器进程有权访问的任意文件，包括配置文件、密钥文件等敏感信息。

十、Next.js next/og 远程代码执行漏洞  
  
  
概述：  
  
腾讯云安全近期监测到关于  
Next.js next/og  
的风险公告，  
漏洞编号：  
TVD-2026-70061  
（  
CVE  
编号：  
CVE-2026-94545  
，  
CNNVD  
编号：  
CNNVD-2026-94408662  
）  
。成功利用此漏洞的攻击者，可通过构造恶意内容使  
Satori  
库生成被篡改的  
SVG  
标记，在  
Next.js  
服务端环境中触发远程代码执行，最终获取服务器控制权限。  
  
Next.js  
是由  
Vercel  
开发维护的  
React  
全栈开发框架，广泛应用于企业官网、电商和内容平台等场景。其内置的  
next/og  
模块用于在服务端动态生成  
Open Graph  
社交分享图片，底层依赖  
Satori  
库将  
HTML  
和  
CSS  
转换为  
SVG  
输出。  
Satori  
是一个轻量级库，负责将结构化内容渲染为  
SVG  
矢量图，支持  
Flexbox  
布局和自定义字体。  
Next.js  
凭借其文件系统路由、服务端渲染和  
API  
路由等特性，是现代  
Web  
应用开发的主流框架之一，  
next/og  
模块则是其社交分享预览图生成的核心组件。  
  
据描述，该漏洞源于  
next/og   
的  
 Node.js ImageResponse   
实现受到上游依赖漏洞影响。当应用将攻击者可控的值传入  
 ImageResponse  
生成的  
SVG  
内容、属性或样式时（例如将  
 URL   
参数直接嵌入  
<title>  
等  
SVG  
元素），攻击者可通过构造特制的输入触发该漏洞，从而实现远程代码执行。  
  
注：攻击者要成功利用该漏洞，应用必须使用  
 Node.js   
版  
 next/og   
的  
ImageResponse   
实现，并且将攻击者可控的值传入  
 SVG   
内容、属性或样式。  
  
使用  
 Edge   
版  
 ImageResponse   
实现的应用，或未将攻击者可控值传入  
 SVG   
内容、属性或样式的应用，不受此漏洞影响。
