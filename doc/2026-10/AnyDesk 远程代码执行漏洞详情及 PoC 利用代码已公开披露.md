**内容摘要**  
  
V12 安全团队的研究人员公开发布了 AnyDesk Linux 版中一个预认证远程代码执行漏洞的 PoC 利用代码。该漏洞被命名为 AnyPwn，可在用户批准远程会话之前即获取 root 命令执行权限。AnyDesk 已在 8.0.3 版本中修复该漏洞。  
  
V12 安全团队的 Rick de Jager 发现了该漏洞，并于 2026 年 10 月 8 日在   
GitHub 上发布了 PoC 利用代码  
。团队于 6 月 22 日首次披露 AnyPwn，AnyDesk 于次日予以确认。截至 10 月初，该漏洞尚未被分配 CVE 编号。  
  
**为何值得重视**  
  
AnyDesk 是被数百万终端使用的远程访问软件。在 Linux 上，该服务通常以 root 权限运行，因此一个可用的漏洞利用程序可在任何审批提示出现之前便赋予攻击者 root 级别的控制权。随着 PoC 代码和完整技术细节的公开，未打补丁的系统面临真实风险。  
  
**攻击原理**  
  
该漏洞存在于 AnyDesk 的会话协议中。数据流数据包处理程序在验证远程端发送的长度值之前便直接信任该值。在内存分配过程中，对超大长度值进行 32 位算术运算时发生整数回绕，导致分配到一个极小的数值。结果是 AnyDesk 仅分配了一个小缓冲区，却仍按原始的大尺寸处理数据。复制数据包字节时写入超出缓冲区范围，导致堆内存损坏，攻击者正是利用这一损坏实现命令执行。  
  
**利用现状**  
  
目前尚未确认存在在野利用案例。但公开的 PoC 可通过 7070 端口的直接 TCP 连接运行，研究人员表示同一漏洞路径也可通过 AnyDesk 中继连接触发。  
  
**受影响版本**  
  
公开的 PoC 针对 AnyDesk Linux 8.0.2 版本。研究人员推测 8.0.1 等早期版本同样包含存在漏洞的代码，但尚未得到确认。  
  
**补丁与缓解措施**  
- 将 AnyDesk 更新至 8.0.3 或更高版本，当前最新版本为 8.1.0  
  
- 通过防火墙规则限制 TCP 7070 端口的入站访问  
  
- 将 AnyDesk 的访问范围限制在可信网络内  
  
- 在条件允许的情况下，避免以 root 权限运行 AnyDesk 服务
