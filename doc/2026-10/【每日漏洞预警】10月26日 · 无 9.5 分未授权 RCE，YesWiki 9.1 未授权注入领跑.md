CVE-2026-116207 / CVE-2026-116211 / CVE-2026-116208 / CVE-2026-116204  
  
YesWiki（PHP 维基 / Bazar 表单协作平台）  
  
未授权 SQL 注入：反引号逃逸别名读库，同批 4 条一并修复  
  
CVSS 9.1 · CRITICAL  
  
   
  
YesWiki 是法国社区里用得很多的一个 PHP 维基，Bazar 表单是它的核心协作组件。这次最狠的一条在 SearchManager::prepareSearchRequest()  
：公开的 Bazar 条目搜索 API 会把 query  
 与 searchfields  
 参数里的字段名直接拼进反引号包裹的别名  
，而转义只用了 mysqli_real_escape_string  
——这个函数不转义反引号  
。攻击者塞一个反引号闭合别名，后面就能接任意子查询：读 wiki_users  
 里的密码哈希，或者用 SLEEP()  
 把数据库线程全占满。整个过程完全不需要登录  
。同一个 4.7.0 版本还一起修了三条：PageManager::save()  
 里 Bazar 建条目请求的 date_maj_fiche  
 字段未转义拼进 INSERT（8.2，默认安装下未授权就能打，同样可以子查询拖 wiki_users）；ActivityPubService::syncActorPosts  
 缺授权检查（8.1，恶意 ActivityPub 服务器可以喂一份投毒的 outbox，在管理员触发同步时删除、覆盖、伪造甚至批量删条目）；despam  
 动作的 CSRF（8.1，页面里放一个自动提交的表单，管理员一点开就会按 clean / suppr[] / rev[] 删页面或覆盖正文）。四条都是「公网站点上不需凭据」的类型，凑在一起等于把一个维基的内容和账号体系一起交出去。  
  
  
📦 影响版本  
  
所有 < 4.7.0 的版本；5.0.0-alpha1 < 5.0.0-alpha4（注入自 4.5.0 起、ActivityPub 越权自 4.6.2 起）  
  
✅ 修复版本  
  
4.7.0 / 5.0.0-alpha4 及以上

02  
CVE-2026-116201 / CVE-2026-116199  
  
Snipe-IT（开源 IT 资产 / 设备管理系统）  
  
SAML 断言重放（并发绕 nonce）+ Google SSO 停用账号登录绕过  
  
CVSS 8.8 · HIGH  
  
   
  
Snipe-IT 是自建资产管理里最常见的一套，很多单位把它放在公网给外包和远程同事用，所以这两条值得单独说。CVE-2026-116201（8.8）  
：SAML 的 /saml/acs  
 处理里，对断言 nonce 的检查不是原子操作  
（先查后写，中间有窗口）。拿一条截获的合法断言并发打过去，可以换出多个已认证会话  
，而且这些会话绕开了 IdP 侧的吊销  
——管理员在身份提供方那边踢人、改口令，已经换出来的会话照样能用。前提是攻击者手里已经有一条有效断言（PR:L），常见于日志、代理、浏览器扩展或共享终端泄露。CVE-2026-116199（8.1）  
：GoogleAuthController::handleGoogleCallback  
 只要 Google 账号邮箱和用户名一致就直接登录，没校验 activated 标记  
。也就是说，账号被停用的人只要那个同邮箱的 Google 身份还在，就能从 Google SSO 登回来，权限还是原来那一档，包括管理员  
。人员离职后停用账号却不回收 Google 身份，就是这个洞的现成利用条件（AC:H，需要邮箱形用户名 + 身份仍有效）。  
  
  
📦 影响版本  
  
所有 < 8.6.3 的版本（SAML 断言重放在 < 8.5.0 上就已存在）  
  
✅ 修复版本  
  
8.6.3 及以上  
  
  
🎯 利用状态：  
 ⚠️ 官方 GHSA 公告与修复版本已公开，暂无公开 PoC / EXP 仓库

03  
CVE-2026-116165 / CVE-2026-116163  
  
Parse Server（开源 BaaS 后端 / REST + GraphQL API）  
  
未授权删除 Mongo 类 schema + AuthAdapter 子类认证绕过  
  
CVSS 8.8 · HIGH (v4.0)  
  
   
  
Parse Server 常被当作 App 的后端直接挂在公网 API 域名上，这两条都打在「API 就是暴露面」这个位置上。CVE-2026-116165（8.8，NVD 只给了 v4.0 评分，按本号口径标注 v4.0）  
：在 MongoDB 部署  
下，没有 master key 的客户端可以对内部 _SCHEMA  
 集合发 REST DELETE  
，把任意 class 的字段定义、class 级权限、受保护字段配置  
删掉。schema 一没，原本受保护的字段就变成可读可写——这条不是直接读数据，而是先把门拆了  
，之后的数据泄露是「顺带」发生的（VC:L / VI:H）。CVE-2026-116163（7.4）  
：继承 AuthAdapter  
 的自定义适配器里，validateSetUp / validateLogin / validateUpdate  
 三个方法从来没被调用  
，实际走的是父类默认实现——「任何 authData 都接受」。结果是攻击者可以随便伪造 authData 完成注册、绑定身份、直接登录既有用户  
，或者跳过自定义的二次认证因子。自己写过 AuthAdapter 子类的部署要特别当心，这类代码往往被当成「已经加过校验了」。  
  
  
📦 影响版本  
  
< 8.6.102；9.0.0 < 9.10.5-alpha.2  
  
✅ 修复版本  
  
8.6.102 / 9.10.5-alpha.2 及以上  
  
  
🎯 利用状态：  
 ⚠️ 官方 GHSA 公告与修复版本已公开，暂无公开 PoC / EXP 仓库

处置建议  
  
1YesWiki：  
升到 4.7.0（5.x 线用 5.0.0-alpha4 及以上）。Bazar 条目搜索 API 是公开面，升级前先按「wiki_users 密码哈希已泄露」评估，管理员口令与会话一并轮换；ActivityPub 同步与 despam 动作也别外开放行。  
  
2Snipe-IT：  
升到 8.6.3。开 SAML 的把 /saml/acs 限流并对账 IdP 侧会话吊销记录；开 Google SSO 的检查是否存在「邮箱形用户名 + 已停用」的账号，这类账号现在能登回来且权限照旧。  
  
3Parse Server：  
升到 8.6.102 / 9.10.5-alpha.2。MongoDB 部署上给内部 _SCHEMA  
 集合加写保护，REST API 别把 master key 之外的管理面暴露到公网；自定义 AuthAdapter 的部署要复核 validateSetUp / validateLogin 是否真的被调用。  
  
4今日未入榜但同样要看：  
Unitree Go2 升级到 1.1.11.5（9.6 命令注入，机器人本体、需交互、无公网指纹）；Dokploy ≤ 0.30.10 存在跨租户越权（8.8，自建内网管理面）；vLLM（8.2 SSRF / 7.7、7.5 资源耗尽）与 ImageMagick（8.1 bzip2 栈溢出）属库与推理服务，按本号口径不占主榜。
