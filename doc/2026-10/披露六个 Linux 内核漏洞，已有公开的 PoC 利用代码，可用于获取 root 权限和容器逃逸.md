#  披露六个 Linux 内核漏洞，已有公开的 PoC 利用代码，可用于获取 root 权限和容器逃逸

**摘要**  
研究员 Hyunwoo Kim 公开了他称为"Infinity Core"的六个 Linux 内核漏洞的完整细节和概念验证（PoC）利用代码。其中五个可导致本地权限提升和容器逃逸，一个会使内核崩溃。上游已有修复，因此管理员应立即安装已修补的内核。  
  
**为何重要**  
这些漏洞位于内核的核心代码中：定时器、信号、内存管理、futex、调度器和 SLAB 分配器。Kim 指出，这些领域历来较少出现安全问题。此外，他的研究排除了网络、BPF 以及需要用户命名空间的漏洞等较为"嘈杂"的领域。  
  
这使得这组漏洞更加危险。大多数加固指南会限制用户命名空间或 BPF，以缩小攻击面。然而，这些控制措施并不能阻止这些漏洞。任何本地用户或容器内的代码都有可能触及它们。在共享主机上，这意味着一个被攻陷的容器可能演变为对整个主机的接管。对于云服务提供商和 Kubernetes 集群来说，这些 Linux 内核漏洞会把一个小小的立足点，变成跨越节点上所有工作负载的权限提升。  
  
**利用细节现已公开**  
Kim 在禁运期间向 linux-distros 邮件列表报告了这些漏洞。禁运结束后，他将细节发布到 oss-security，并在 GitHub 上发布了   
Infinity Core 技术文章和 PoC 利用代码  
。根据该文章，公开的 PoC 可将其中五个 Linux 内核漏洞转化为来自非特权账户的 root shell。  
  
定时器漏洞的危害更大。Kim 称，它可以在三星 Galaxy S26 Ultra 上，从普通应用沙箱获得完整的 root 权限。他已暂时不公布该 Android 利用代码，等待三星为其设备打补丁，目前只发布了它的哈希值。  
  
**攻击原理**  
这六个漏洞都是由内核代码中的竞争条件或边缘情况触发的内存安全缺陷。攻击者首先需要获得本地代码执行能力。随后，这些漏洞会破坏内核内存，而 PoC 会把这种破坏转化为 root 访问权限。  
- CVE-2026-98260  
（定时器）：在带有 CPU 定时器的多线程进程中，当 exec() 失败时出现的释放后使用漏洞。  
  
- CVE-2026-98256  
（信号）：exec() 与信号队列清理之间的竞争条件导致的释放后使用漏洞。  
  
- CVE-2026-89754  
（内存管理）：mincore() 所使用的页表遍历器中的越界写入。  
  
- CVE-2026-80775  
（Futex）：私有 futex 哈希设置中的竞争条件导致的释放后使用漏洞。  
  
- CVE-2026-98385  
（调度器）：调度器缓存统计中的释放后使用漏洞。仅当内置并启用了可选的调度器缓存功能时才适用。  
  
- CVE-2026-97941  
（SLAB）：SLUB 分配器中的链表损坏。其 PoC 会导致内核恐慌（panic），Kim 称目前尚无权限提升的利用链。  
  
**利用情况**  
这六个漏洞都已有公开的 PoC 代码。不过，没有任何来源报告存在真实环境中的利用，这些 CVE 也均未出现在 CISA 的 KEV 目录中。  
  
**受影响版本**  
Kim 在 Ubuntu 26.04（内核 7.0.0-30-generic）和 Arch Linux（7.2.4-arch1-2）上测试了这些利用代码。内核 CVE 记录列出了以下已修复的稳定版本：  
- CVE-2026-98260：影响自 5.7 起的内核。已在 6.6.158、6.12.112、6.18.54 和 7.2.8 中修复。  
  
- CVE-2026-98256：影响自 6.15 起的内核。已在 6.18.54 和 7.2.8 中修复。  
  
- CVE-2026-89754：影响 7.0 以及部分 6.18 和 6.19 的回移植版本。已在 6.18.50 和 7.2.4 中修复。  
  
- CVE-2026-80775：影响自 6.17 起的内核。已在 6.18.47、7.1.11 和 7.2.1 中修复。  
  
- CVE-2026-98385：影响 7.2。已在 7.2.9 中修复。  
  
- CVE-2026-97941：影响 7.2。已在 7.2.7 中修复。  
  
**补丁与缓解措施**  
- 安装你所用发行版的最新内核更新并重启。  
  
- 优先处理多租户主机、容器节点和共享构建服务器。  
  
- 检查你的厂商内核是否包含修复提交，因为回移植的情况各不相同。  
  
- Android 用户应在三星发布安全更新后及时应用。  
  
freenode  
 上的报道警告称，容器、多租户以及落后于上游的 Android 构建面临的暴露风险最大。由于可用的利用代码已经公开，这些 Linux 内核漏洞应当被提到补丁队列的最前面。
