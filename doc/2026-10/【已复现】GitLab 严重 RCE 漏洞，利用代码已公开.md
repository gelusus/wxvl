#  【已复现】GitLab 严重 RCE 漏洞，利用代码已公开  
原创 360漏洞研究院
                    360漏洞研究院  360漏洞研究院   2026-10-14 07:53  
  
GitLab CE／EE 曝出严重远程代码执行漏洞（CVE-2026-97229，CVSS 10.0）。攻击者在满足特定条件时，可借助恶意 CI/CD 配置中的正则表达式触发整数溢出，并在 GitLab 服务器上执行代码。  
  
  
**利用前置条件：**  
- 攻击者能够访问目标 GitLab 服务及公开项目的 CI Lint 接口  
  
- 攻击者具备公开项目的写入权限，可提交恶意 CI/CD 配置及特制仓库路径；允许自行注册并创建公开项目的实例也可能满足该条件  
  
- 公开 PoC 受版本及系统架构限制，最终触发请求无需认证  
  
**目前360图龙锋 · 漏洞挖掘智能体已成功复现该漏洞。**  
本文包含完整影响范围、正式修复方案、技术原理与复现细节。

**01**  
  
**漏洞影响范围**  
  
  
  
受影响版本范围：  
  
19.2.0 <= GitLab CE／EE <= 19.2.7  
  
19.3.0 <= GitLab CE／EE <= 19.3.4  
  
19.4.0 <= GitLab CE／EE <= 19.4.1  
  
  
**02**  
  
**修复建议**  
  
  
  
**正式防护方案**  
  
19.2 分支升级至 19.2.8 或更高版本  
  
19.3 分支升级至 19.3.5 或更高版本  
  
19.4 分支升级至 19.4.2 或更高版本  
  
  
**03**  
  
**漏洞描述**  
  
  
  
近日，安全研究员披露了 GitLab CE／EE CI/CD 正则表达式编译器中存在的整数溢出漏洞（CVE-2026-97229）。该漏洞源于正则表达式校验不足，攻击者可利用恶意 CI/CD 配置中的特制正则表达式绕过初步校验，并在匹配包含特定 UTF-8 字符的仓库路径时，触发 Ruby Onigmo 正则表达式引擎重新编译。由于重新编译过程中的长度计算存在整数溢出问题，可能导致生成的正则表达式指令异常，进一步破坏内存状态并控制程序执行流程。攻击者在具备公开项目写入权限的情况下，可通过 CI Lint 接口触发漏洞，即使最终请求未经身份认证，也能够以 GitLab 服务的 git 用户权限执行任意系统命令。该漏洞可能导致服务器遭受远程代码执行、敏感数据泄露及业务服务中断等严重影响。  
  
  
**04**  
  
**漏洞复现**  
  
  
  
360漏洞研究院依托图龙锋漏洞挖掘智能体已成功复现 CVE-2026-97229。通过向 GitLab 公开项目提交特制 CI/CD 配置及仓库路径，触发 CI Lint 接口中的整数溢出漏洞，成功以 GitLab 服务的 git 用户权限执行系统命令，并获取目标系统信息，验证了远程代码执行漏洞的实际危害。
