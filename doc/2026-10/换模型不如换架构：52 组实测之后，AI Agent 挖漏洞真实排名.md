#  换模型不如换架构：52 组实测之后，AI Agent 挖漏洞真实排名  
 穹苍经略   2026-10-19 23:00  
  
星标代表关注度，不代表漏洞发现率；单次 Demo 跑通，不代表在 63 道题上稳定。我们把腾讯安全云鼎实验室的实测数据和 GitHub 生态数据叠在一起看，结论和大多数人的直觉相反。  
  
![](https://mmbiz.qpic.cn/sz_mmbiz_png/m3tfzlbEQPrnibcC1SKBQhOHmYACpCZWGIKxTFianJeugtJsHLO6a45YKibcuY0FnU1LcMC6I14IbqU5u5ckRxu3wiaAQvhgiaMsDc4FYFLnf0ZM/640?wx_fmt=png&from=appmsg "")  
  
如果你今年要选一个 AI 渗透 Agent 落地，第一个该想清楚的问题是：**预算应该花在换更强的模型上，还是花在挑更好的架构上？**  
  
过去一年，行业里的默认答案是「模型」。毕竟大家看到的是同一个现象：换个新模型，Agent 立刻变聪明。  
  
但 2026 年 Q2 的一批公开数据，给出了一个不太一样的答案。  
  
腾讯安全云鼎实验室的 **TSecBench v1**  
 用 63 道题、六大能力域，跑了 13 个 Agent × 4 个国产主流模型 × 3 轮，共 156 份结果，选出 52 组「最优轮次」。这是目前少有的、能在统一题集和环境里横向比较的公开数据。  
  
与此同时，GitHub 上「AI 渗透测试」赛道的星标格局也基本定型：Strix 60.1k、Shannon 47.6k、PentAGI 22.2k……  
  
两份数据单独看都有盲区。  
  
所以我们就把两份数据叠在了一起。  
  
开篇 · 四个反直觉的发现  
  
架构比模型更决定成败  
  
同一个模型下换 Agent，成功率平均波动 **33.1**  
 个百分点；同一个 Agent 换模型，平均波动只有 **18.7**  
 个百分点。前者接近后者的两倍。  
  
模型决定天花板，架构决定你离天花板多远  
  
Kimi K3 在 13 个 Agent 中的 **11 个**  
上是该 Agent 的最佳模型——模型确实定义了上限。但同样是 Kimi K3，最好的 Agent（90.5%）和最差的（56.8%）差了 **33.7**  
 个百分点。  
  
所有人都在同一个地方摔跤：多阶段渗透  
  
即便每个组合都取三轮最优，多阶段渗透的整体成功率只有 **29.53%**  
，完整解题率 **8.33%**  
。表现最好的 Cairn 也只有 44.6%。  
  
效率差距大到可以写进预算表  
  
CHYing 用 **27.92M**  
 Token 换到 80.56% 的完整解题率；Cairn 用 **458.50M**  
 Token 换到 82.14%。同样的分数，成本差 **16.1**  
 倍。

三个读法  
  
**第一梯队没有断层。**  
第 1 名（77.70%）到第 4 名（73.65%）只差 4.05 个百分点。这意味着在同等条件下，前四名的能力差距小于单次运行的随机波动——选型时不必迷信第一名。  
  
**头部和尾部的差距是 31.75 个百分点。**  
这个数字比模型之间的差距（16.73 pt）大得多。

**云攻击和对抗规避已经「能打」了。**  
云攻击普遍在 83%–100%，对抗规避在 76.8%–100%。这两类任务目标明确、反馈清晰，正是当前 Agent 擅长的形态。  
  
**多阶段渗透是全体塌陷区。**  
最高只有 Cairn 的 44.6%，中位数在 35% 左右，垫底的 PentestAgent 只有 5.4%。即便三轮取优，整体成功率也只有 29.53%、完整解题率 8.33%。  
  
**单点强 ≠ 链路强。**  
LuaN1ao 二进制挖掘 90.4%（并列第一），多阶段渗透却只有 28.6%。BreachWeave 漏洞利用 69.4%，多阶段 35.7%。**当前的 AI 渗透 Agent 普遍是「优秀的单点手 + 糟糕的指挥官」。**  
  
一个有趣的例外是 **shannon**  
：二进制挖掘只有 42.3%（全场最低），但多阶段渗透 42.9%（全场第二）。它的白盒定位决定了取舍——读源码做架构推理，不擅长二进制，但严格的任务图和验证门禁让它在长链任务上反而不掉队。  
  
这意味着什么？长链任务的规划、状态保持、失败恢复，是 2026 下半年真正的战场。谁先把多阶段渗透从 30% 拉到 60%，谁就重新定义了这个赛道。

**结论：工程完备度和实战得分的相关性很弱，在部分项目上甚至是负相关。**  
  
为什么会这样？因为两套评价体系奖励的东西不一样。  
  
**TSecBench 的 63 道题奖励「精悍的任务闭环」**  
——快速定位、准确利用、拿到 flag。它不奖励可观测性、可运维性、企业级治理、报告合规。  
  
**工程评估奖励「架构成熟度」**  
——隔离、记忆、编排、证据管理、CI 集成、人工审批。这些在解题榜上是纯开销。  
  
所以正确的选型姿势是分场景，而不是找一个「全能冠军」。  
  
另外提醒一个容易被忽略的事实：**CAI 的仓库已经归档**  
，官方引导迁移到 CSI。它的实战成绩（67.91%，第 8）其实不差，但生产选型必须单独扣分——能力在线，维护停摆。  
  
八、综合排名总榜

权重偏向实战，因为可复现的实测数据比架构评审更硬。

**一条通用的工程建议：**  
无论选哪个，都要在编排层之外自己补上**目标与权限边界、凭据隔离、证据存储、重复发现去重、人工审批**  
这五件事。目前没有任何一个开源 Agent 把它们做全了。  
  
十、2026 下半年，看什么  
  
基于这批数据，我们判断五个方向。  
  
01  
  
从「工具调用」转向「状态空间搜索」  
  
排名第一的 Cairn 不是工具流水线，而是把渗透测试抽象成「事实-意图图」上的状态空间搜索，Worker 通过 OODA 循环探索，不预设固定角色。Pentest-Swarm-AI 用共享 pgvector 黑板做 stigmergic 协作。**固定角色的 Multi-Agent 可能是过渡形态。**  
  
02  
  
技能底座与执行引擎会合流  
  
reverse-skill（34k）和 Anthropic-Cybersecurity-Skills（32k）代表了另一条路：不写执行引擎，只做安全知识密度的提升。它们大概率会与 Strix、Cairn 这类引擎组合，而不是互相替代。  
  
03  
  
长链任务是唯一的分水岭  
  
多阶段渗透 29.53% 的成功率是全行业的耻辱柱，也是最大的机会窗口。**谁能把它拉到 60%，谁就重新定义赛道。**  
  
04  
  
Token 成本会成为产品级指标  
  
16.1 倍的效率差距说明，上下文管理、工具结果裁剪、记忆压缩不再是「优化项」，而是核心竞争力。未来 Agent 的技术文档里，Token 效率会和成功率并列。  
  
05  
  
五个可审计部件会成为标配  
  
目标与权限边界、任务图、工具运行时、证据图/记忆、验证与报告门禁。真正拉开差距的不是模型名称或工具数量，而是能否在受控环境中重复完成「假设 → 行动 → 证据 → 复现 → 结论」，并在失败时可恢复、可追踪、可人工接管。  
  
· · ·  
  
回到开头的问题：**换模型，还是换架构？**  
  
数据的答案是：**先把架构挑对，再把模型配到最好。**  
架构决定了你的波动区间（33.1 pt），模型决定了这个区间的上限（18.7 pt）。顺序搞反了，花再多钱也是在错误的架构上换引擎。  
  
但也要记住：**这批数据反映的只是「能力上限」**  
。三轮取优、统一靶场、63 道题——它是一个干净的实验环境，不是你的生产环境。真实落地时，你大概率拿不到 77.70%，你会拿到这个数字下方、并且伴随着误报、超时和需要人工兜边的长尾。  
  
最后，也是最重要的  
  
本文涉及的所有 Agent 都具备主动扫描或利用能力。任何实际运行都应严格限定在**自有资产、书面授权范围、CTF/靶场或明确允许的 Bug Bounty 计划**  
内。优先使用本地、测试或临时环境，并为网络范围、凭据、速率、日志和数据清理设置显式策略。  
  
  
TSecBench 的全部测评也均在授权、受控的靶场环境中完成。
