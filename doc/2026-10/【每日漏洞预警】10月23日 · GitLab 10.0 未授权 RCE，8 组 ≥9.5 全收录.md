01  
CVE-2026-110264  
  
GitLab CE/EE 自建实例（Omnibus 打包的 Ruby 运行时）  
  
Onigmo 正则编译整数溢出 → 未授权 RCE（内存破坏可致代码执行）  
  
CVSS 10.0 · CRITICAL  
  
   
  
根因不在 GitLab 业务代码，而在它随包分发的 Ruby Onigmo 正则引擎  
：引擎用 short int（16 位）  
 存正则字节码的重复操作数（MemNumType  
，regint.h），编译器统计重复次数时用的是不设上限的 int，写入时却走 add_mem_num()  
 做截断转换（regcomp.c）。于是任何含 32767 个以上区间重复（{n,m}）的正则  
，后续 ID 会回绕成负数：匹配阶段读 repeat_range[负数]  
（regexec.c 越界读）并写 repeat_stk[负数]  
（越界写），读写窗口落在分配块下方约 256KB  
 的已映射内存里。投递面是 .org 文件  
：issue、wiki、snippet 里的 #+TODO:  
 关键字会被 org-ruby 原样插进 Regexp.new，未登录即可触发。公开 PoC 在 ruby 3.4.11（GitLab 打包的同一条线）上稳定打出 SIGSEGV，寄存器里能看到回绕值 RSI=0xffff8000  
（即 -32768）；从崩溃到控制流劫持还要做堆布局，目前公开代码只到确定性崩溃/堆破坏，未武器化  
。GitLab 已发两条检测规则（Onigmo native worker crash、Org mode render error burst），并在 2026-10-21 的补丁里回移了 Ruby 侧的 repeat-ID 修复；同引擎的兄弟漏洞 CVE-2026-97229 已于 10-12 修过。

CVE-2026-114575  
  
TOTOLINK A950RG（AC1200 双频千兆路由）  
  
未授权命令注入：UploadCustomModule 上传 .so 并以 root 加载执行  
  
CVSS 10.0 · CRITICAL  
  
   
  
10.0、AV:N/PR:N  
，且已有完整公开技术分析。cstecgi.cgi 的鉴权白名单  
把「路由键里含 UploadCustomModule」的请求当成已认证，请求因此不带 token 直达 lib/cste_modules/product.so  
 的 UploadCustomModule。处理函数只校验两点：Action 必须等于 GetCustomModule  
、FileUrl 必须含 custom.so  
；然后把 base64 编码的 .so  
 用 strcpy 拷进 204800 字节栈缓冲  
、解码写到 /tmp/custom_file，再用请求自带的 FileMd5  
 做完整性校验——校验值由攻击者自己提供，等于没有校验  
。通过后文件落到 /tmp/custom/cste_modules/custom.so，随后 system("initcste &")  
 重启框架，cste_sub 会把该目录下所有 .so 加载进以 root  
 运行的守护进程——一条未认证 HTTP 请求换 root 代码执行。利用链不需要任何凭据，也不需要知道管理员口令，攻击面就是设备的管理接口本身。
