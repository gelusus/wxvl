#  Linux 内核曝出严重漏洞：可导致虚拟机逃逸并获取宿主机控制权  
 网安百色   2026-10-16 10:42  
  
![](https://mmbiz.qpic.cn/sz_mmbiz_png/WibvcdjxgJnuBFs0vTm7xjov89DibDOH5BSYkfKzCib5kFKkrwkGr5mSbw1bb0sfEMBc4lcVw8jPicnFdOiae1hTVXRTPAWOwBiaI96iaySFAG6qYs/640?wx_fmt=png&from=appmsg "")  
  
Linux 内核中存在一处严重漏洞，可能允许攻击者控制的虚拟机 (VM) 突破其隔离边界并直接影响宿主机系统。该漏洞编号为 CVE-2026-99999，被研究员 Paulos Yibelo 命名为 "PwnEscape"。其根源在于 Linux 的网络代码，而非特定的虚拟机监视器 (hypervisor)。  
  
Paulos Yibelo 演示了一种可泄露宿主机内存的技术，并在其实验室环境中进一步实现了宿主机级别的代码执行。对于在虚拟机中运行不受信任工作负载的云服务商和企业而言，此漏洞危害极大。虚拟机隔离的初衷，正是为了防止客户机 (guest) 内部的代码触及宿主机或其他工作负载。  
  
PwnEscape 揭示了宿主机数据包处理路径中的弱点如何威胁这一隔离边界，即使底层问题并不出在虚拟机监视器本身。  
### PwnEscape 内核漏洞详情  
  
Linux 支持延迟计算网络数据包的校验和 (checksum)。这是一项常规的性能优化特性：数据包元数据会告知内核校验和操作应从何处开始，以及结果应写入何处。  
  
问题出在可信度较低的数据包元数据能够影响后续对 IPv4 头部的写入操作。Linux 已经使用头部先前的内容处理了该数据包，但在分片 (fragmentation) 操作之前，延迟的校验和计算可能会修改这些内容。随后的代码则依赖了更新后的 IPv4 头部长度。  
  
在 Paulos Yibelo 的测试用例中，数据包最初显示为标准的 20 字节 IPv4 头部。在延迟写入发生后，该头部可能被解析为 60 字节长。随后，分片代码可能会将超出数据包有效线性数据范围的字节视为头部的一部分，并将其包含在发出的数据包中。他报告称，这导致了 32 字节的宿主机内存泄露。  
  
这种内存泄露并不等同于代码执行。报告描述了另一条独立的、在受控实验室环境中构建的利用链：研究人员通过观察宿主机内存并精心控制内存分配行为，演示了特定的内核内存写入，并运行了一个获取宿主机 root 权限的辅助程序。他们特别指出，该结果是在研究人员自有的系统上复现的，并不能作为在云服务商生产环境中实现 root 权限执行的证明。  
  
宿主机内存泄露可能会暴露本应超出客户机访问范围的信息。要将这种基础利用条件 (primitive) 转化为对宿主机的实际控制，可能还需要进一步的利用步骤；且该报告并未证明所有 Linux 虚拟机或虚拟机监视器都面临同等程度的风险。

Linux 上游补丁在特定的校验和完成操作之前增加了一项检查。它会验证校验和的起始位置是否不在 IPv4 头部之内。如果元数据未通过该检查，内核将不会沿受影响的路径继续执行该校验和写入。此项更改覆盖了多个调用方，包括 IPv4 分片处理逻辑。  
  
提交信息 (commit) 将此项更改描述为一种纵深防御 (defense-in-depth) 措施，同时指出，在数据包输入阶段进行更严格的验证仍需进一步工作。换言之，该补丁在内核完成校验和的环节增加了防护，但并未对校验和元数据如何进入网络协议栈进行全面重构。  
  
管理员应查阅其 Linux 发行版厂商的安全公告，并安装包含此修复的更新内核。上游提交记录有助于识别该更改，但 Linux 发行版通常会将安全修复向后移植 (backport) 到较旧的内核版本中。
