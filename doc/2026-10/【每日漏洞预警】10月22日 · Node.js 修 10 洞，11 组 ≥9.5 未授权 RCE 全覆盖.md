今天 Node.js 官方发了安全版本，一次修 10 个 CVE  
，最高评级 HIGH  
（NVD 尚未收录，所以没有具体分数，只有评级）。四条 high 里最重的是：CVE-2026-111497 —— Brotli 解码器越界写，可导致远程代码执行  
。Node 里 Brotli 常用于 Content-Encoding: br  
 的请求/响应体解压，也就是说「处理一个压缩体」就可能踩到，攻击面是任何接受压缩输入的 Node 服务。另外三条 high 是企业环境更容易踩的：CVE-2026-105483  
 把 IP 写成全角数字  
就能让 TLS 证书主机名校验被绕过；CVE-2026-106069  
 在 host 能被宽松解析成 IP 时同样绕过校验；CVE-2026-105482  
 则让 dns.resolve  
 在域名含 NUL 字符  
时被截断（DNS 层面的解析歧义）。medium 里有一条容易被忽略但很阴：CVE-2026-106074  
 —— crypto.randomUUID() / randomInt() 的熵缓存会跟着用户态启动快照和 SEA 一起打包  
，导致每个进程重复同一批「随机数」，等于令牌/ID 可预测；其余是 keep-alive 响应顺序（105481）、非规范 IPv4 主机名的证书校验（106072）。low 三条是 ZipFile 可控前缀（106070）与 Permission Model 越权（106071 / 106073）。

CVE-2026-105944 / CVE-2026-105869  
  
Apache Pulsar Manager 与 Pulsar Broker（MQ 管理面）  
  
未授权创建超管 + 代理转发盗走集群凭据（10.0）；JWT 不验签 → 伪造任意角色（9.2）  
  
CVSS 10.0 · CRITICAL · v4.0  
  
   
  
两条都在 Apache Pulsar 身上，一条打管理面、一条打消息面。CVE-2026-105944（10.0，v4.0）  
：Pulsar Manager 的「创建初始管理员」操作不需要认证，而且实例初始化完成后依然可用  
——任何能访问到 Manager 的人都能再建一个超管并登录（0.3.0 起无权限分级，新账号即全权）；同时它代理到集群的 admin API 请求不走自己的鉴权  
，更狠的是代理目标可以由请求方指定  
，Manager 会把自己的 Pulsar 凭据（token 甚至签名密钥）一起带过去——凭据直接被外带。最要命的是：项目已退役，官方公告明写「不再修复、不再发版」  
，这不是「等补丁」的漏洞，是「必须下线」。CVE-2026-105869（9.2，v4.0）  
：MultiRolesTokenAuthorizationProvider 在授权时自己不看签名  
，直接去掉签名解析 claims；当 broker 配了非空 anonymousUserRole、且 strictAuthMethod 为默认 false 时，认证失败的请求会落到匿名角色，却仍保留 Authorization 头，于是伪造/未签名 token 里写什么角色就是什么角色  
，写进 superUserRoles 就是超管。  
  
  
📦 影响版本  
  
Pulsar Manager ≥ 0.3.0（0.2.0 部分受影响），全部版本均无修复；Pulsar 2.8.1~<4.0.14、4.1.0~<4.2.5（且使用 MultiRolesTokenAuthorizationProvider + 非空 anonymousUserRole）  
  
✅ 修复版本  
  
Pulsar Manager 已退役，官方明确不修复 → 下线并移除部署、轮换其持有的凭据；Pulsar 升级 4.0.14 / 4.2.5
