PART 02  
  
Citrix：管理面自己不看身份  
  
   
  
公告 CTX697320，11 月 12 日首次发布。CVE-2026-120869，CWE-287，CVSS 4.0 给 9.4。  
  
**影响**  
：NetScaler Console 14.1 低于 14.1-74.34 的版本。前置条件只有一句，能访问到 Console 的 IP。  
  
**危害**  
：未认证访问受限资源。Console 管的是 NetScaler 机群的配置、证书、策略下发，进了管理面，流量往哪走就能改。向量里 AV:A，攻击者要落在相邻网络，不是全球任意地址都能打；同一网段、VPN 里、云上同 VPC，都算相邻。  
  
**修复**  
：升到 14.1-74.34 或更高。  
  
**复现**  
：公告只写了"绕过认证控制访问受限资源"，没给路径、参数、请求样例，也没写在野利用。公开渠道没有 PoC。  
  
PART 03  
  
FortiMail：路径穿出去，命令就执行了  
  
   
  
Fortinet 那天发了 93 条，挑最狠的一条。FG-IR-26-199，CVE-2026-126147，组件写的是 API，类别路径穿越，CVSS 9.8，攻击类型 Unauthenticated。  
  
**影响**  
：FortiMail 8.0.0–8.0.1、7.6.0–7.6.6、7.4.0–7.4.8，7.2 全系。  
  
**危害**  
：公告原话是执行未授权的代码或命令。路径没被限制在应用目录内，从 API 穿出去之后能落到哪，取决于是什么进程在跑。FortiMail 站在邮件网关的位置，前面是外网邮件，后面是内部目录和账号体系，一台机器拿下来，往两边都能走。  
  
**修复**  
：8.0.2、7.6.7、7.4.9；7.2 没有修复版本，官方让迁移。FortiMail Cloud 客户不用动，10 月 5 日已统一升到 7.6.7 GA 或 8.0.2 GA。虚拟补丁：无。  
  
**同批还有**  
：CVE-2026-126148（9.8，HA join-request 包命令注入，不用登录）、CVE-2026-126164（9.4，SQL 注入）、CVE-2026-126150（9.1，找回口令流程可重置任意 IBE 用户的口令）；FortiOS 的 CVE-2026-126253（9.3，LSA 广播认证绕过）和 CVE-2026-126259（9.8，HA FGSP + standalone-config-sync 或 autoscale 场景下缺认证，直接以超管执行命令）。  
  
**复现**  
：接口位置收在"API"两个字里，路径和参数都没写，PoC 没有公开。9.8 的未认证命令执行，这种时候等的是补丁，不是 PoC。  
  
PART 04  
  
Payara：一个请求头先放行  
  
   
  
Payara 的管理 REST 有个老规矩：secure-admin 只允许本地访问，远程请求直接拒。CVE-2026-110003 的问题出在"拒"之前。  
  
代码先看请求头里有没有   
X-GlassFish-authToken  
。有，就当成一次带令牌的调用，跳过远程拒绝检查。然后才去验令牌。令牌是假的怎么办？不报错，流程落到口令认证——默认域的管理口令是空的，认证就这么过了。  
  
**影响**  
：Payara Community 与 Enterprise 的管理 REST。修复在 Community 7.2026.11（FISH-14855，Remote Admin Authentication Bypass via Unvalidated Auth Token Header）、6.44.0、5.93.0、4.1.2.191.61，以及 Enterprise 7.6.0。  
  
**危害**  
：CVSS 4.0 9.3。公告写的是执行任意管理命令，等于整台服务器失守。  
  
**复现**  
：要两个条件同时成立，管理口可达、默认域还是空口令。改过口令的生产环境打不穿。也正因为这样，写不出干净的模板——只探测管理口通不通，误报会很难看。  
  
同一天 Payara 还有一条 CVE-2026-90908（9.3）。GenericAdminAuthenticator 里伪造客户端地址，绕过 JMX/RMI 的访问限制，到 MBean Server 再到 RCE。一个产品，两条绕过，都是把"来源"当成了"身份"。  
  
PART 05  
  
REMS：is_local_auth 是谁填的  
  
   
  
OpsTree REMS 是个开源的可观测性平台。登录接口   
POST /api/v1/user/login/  
，请求体里除了邮箱和口令，还有一个字段叫   
is_local_auth  
。  
  
这个字段本该由服务端判断，这条请求是不是从本机来的。REMS 直接读客户端传来的值。填 true，服务端就跳过口令校验，给这个邮箱发一个有效的 JWT。邮箱填管理员的，拿到的就是 SuperUser。  
  
**影响**  
：REMS 1.0.0 及之前。  
  
**危害**  
：CVSS 3.1 9.8，CVSS 4.0 9.3。用户管理、数据源、看板都在超管手里。  
  
**公开**  
：VulnCheck 11 月 11 日发布通告，NVD 在北京时间 12 日 03:17 收录。发现者 Neel Saurabh Kotnis 在 gist 里放了说明。  
  
**修复**  
：通告没有给修复版本。  
  
**复现**  
：一个 JSON 请求，不需要任何前置。模板见 PART 08。  
  
PART 06  
  
Portabase：webhook 写到了主密钥  
  
   
  
Portabase 是开源的数据库备份还原工具，PostgreSQL、MySQL、MongoDB 这些都支持。1.21.2 之前，TUS 上传协议的 webhook 处理器   
app/api/tus/hooks/route.ts  
 有两个问题叠在一起：不验身份，路径也不夹。  
  
未认证的请求能把文件写到私有数据目录里的任意位置，包括   
/data/private/keys/master_key.bin  
。这是备份加密用的 AES-256-GCM 主密钥。  
  
**危害**  
：CVSS 3.1 9.8。主密钥被覆盖或者被换掉，备份里存的凭据就归写文件的人。备份系统通常握着全公司的数据库口令，这一层破掉，备份就成了跳板。  
  
**修复**  
：1.21.2，对应 commit 8dcb406、PR #355，公告 GHSA-7697-vf3j-253j。  
  
**公开**  
：NVD 北京时间 12 日 06:17 收录。  
  
**复现**  
：没有公开的请求样例，webhook 的路径拼接细节要读提交。不给模板。  
  
PART 07  
  
MISP：列表接口把 key 吐出来  
  
   
  
MISP 做威胁情报共享，modules 是它的扩展组件，带一个小的 Web 管理界面，用来配外部工具：VirusTotal、Cortex、各种 SOAR。  
  
CVE-2026-127046 的问题在   
/external_tools/list  
。这个接口不用登录，返回的 JSON 里带着每个外部工具的   
api_key  
。编辑表单还把密钥写进输入框，密钥在 DOM 和网络请求里各走一遍。  
  
**影响**  
：misp-modules 3.1.4 及之前。修复提交 61c2789 在 11 月 12 日 16:37（北京时间）进主干，最新 tag 还是 11 月 8 日的 v3.1.4，没有新版本可用。  
  
**危害**  
：CVSS 4.0 9.2，CWE-200 和 CWE-522。key 泄露的后果不在 MISP 本身，在那些外部服务：攻击者可以冒充这台实例提交查询，也可以直接拿去刷别人的额度。安全团队自己的基础设施被读走凭据，通常比一台业务服务器被打更难受。  
  
**同处还有**  
：CVE-2026-127016（9.2），外部工具的增、删、改、改配置几个接口没有执行 ADMIN_PASSWORD 策略，同一个修复提交。

：GET 一下列表接口就能看到，模板在下面。
