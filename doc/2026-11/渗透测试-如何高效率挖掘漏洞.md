#  渗透测试-如何高效率挖掘漏洞  
原创 炫彩之星
                        炫彩之星  菜鸟学安全   2026-11-11 00:30  
  
接一个目标，有人半天就出洞，有人扫了一天啥也没有——差距往往不在工具多少，而在流程走没走全。效率挖掘的本质，是把"漏扫 → 端口 → 目录 → 指纹 → 功能点 → 凑洞"这条链一环环走完整，每一环都拿到产出，洞自然就堆起来了。  
  
这篇文章把我常用的工具和打法按这条链捋了一遍：从 AWVS、Xray 的漏扫，到端口、目录扫描的套路，再到 Struts2、Shiro、WebLogic、SpringBoot、Log4j2 这些框架的识别与利用，最后是功能点测试和凑洞环节，可以直接当实战 checklist 用。  
  
开始之前，先立三条心法：**一、做渗透由始至终，忌讳穿插其他项目进行。**  
做 A 项目的间隙顺手摸 B 项目，两个项目的思路互相干扰，哪个都做不深。**二、按顺序细心测试每一个功能点，保证漏洞无遗漏。**  
洞是按功能点一个一个抠出来的，跳着测、看着测，漏一个功能就少一窝洞。**三、山重水复疑无路，柳暗花明又一村。**  
一个点利用不到，灵活变通换方向，别在一个死胡同里耗到天黑。

重点接口整理：  
```
/env、/actuator/envGET 请求 /env 会直接泄露环境变量、内网地址、配置中的用户名等信息；属性名命名不规范时（password 写成 psasword、pwd）还会泄露密码明文，同时有一定概率可以通过 POST 请求 /env 设置属性，间接触发相关 RCE 漏洞，也有概率拿到星号遮掩的密码、密钥等重要隐私信息的明文。/refresh、/actuator/refreshPOST 请求 /env 设置属性后，可配合 POST 请求 /refresh 接口刷新属性变量，触发相关 RCE 漏洞。/restart、/actuator/restart暴露出此接口的情况较少；POST /env 设置属性后，再 POST /restart 重启应用，触发相关 RCE 漏洞。/jolokia、/actuator/jolokia可以通过 /jolokia/list 寻找可利用的 MBean，间接触发相关 RCE 漏洞、获得星号遮掩的重要隐私信息的明文等。/trace、/actuator/httptraceHTTP 请求跟踪信息，有可能在其中发现内网应用系统的请求详情，以及有效用户或管理员的 cookie 等信息。
```

## 写在最后  
  
整条流程捋下来，"高效率挖洞"其实没什么神秘技巧：工具该跑的都跑、指纹识别清楚就上现成利用链、功能点一个不落、凑洞环节把低垂的果子摘干净——洞是按流程堆出来的，不是靠运气碰出来的。开头三条心法再强调一遍：单项目专注、功能点全覆盖、打不通就换方向，这三条贯穿始终。  
  
反过来看防御：上面这些洞，十有八九都能靠"收敛攻击面"提前拦住——非必要的服务端口不暴露、Actuator 等管理端点加鉴权、登录提示语统一、短信接口加频控，攻击者的 checklist 自然就断了大半。  
  
这份工具和套路清单可以直接当实战 checklist 用，下一篇继续拆具体打点细节。
