#  帆软 FineReport FVS 插件未授权 RCE 代码分析  
Kratos
                    Kratos  Kratos Sec   2026-11-24 10:15  
  
11 月 22 日，长亭安全应急响应中心发布通告并完成复现：帆软 FineReport 的 FineVis（FVS）大屏插件存在未授权远程代码执行，编号 QVD-2026-115643。攻击者不需要任何账号，向暴露在网络里的报表服务器上传并"应用"一个构造的 FVS 复用包（.mfvs 文件），就能以应用进程权限执行任意系统命令——复现环境里这个进程在容器内是 root。同一天 360 漏洞研究院发了独立通告，定性与长亭一致：鉴权、输入处理、连接层防护三处缺陷叠加。  
  
两个背景先记下。一是 FVS 是帆软的可视化大屏插件，官方安装包通常自带——也就是说大量部署在金融、制造、政企的 FineReport 实例，默认就带着这个攻击面。二是修复版本（FineReport 11.5.16 与 FVS 插件 4.15.0，10 月 16 日发布）比披露早了一个多月，走了先修后曝的流程，但帆软官方漏洞声明页至今没有单列这个条目——十月份默默发版，十一月份才被通告点破，中间这一个多月打没打补丁，全看客户是不是每周盯升级公告。  
  
登录校验是怎么被一个归一化为空的参数击穿的、复用包里的哪些字段变成了任意文件写和 JDBC URL 注入、以及三个执行出口分别借了服务端的什么现成能力——全程无内存破坏。

## 0x1 攻击面：一个 .mfvs 复用包里装了什么，谁在校验它  
  
FVS 内部代号 Duchamp，插件的 HTTP 端点全部挂在 /view/duchamp/**  
 下，其中复用包的上传与应用在 /view/duchamp/reuse/*  
。复用包（.mfvs）本意是模板及其依赖资源的搬家载体，解开后是几层结构：  
```
content/biz/BizLayer.json                     # 实体映射content/biz/attachments/AttachmentLayer.json  # 附件清单：{"attachInfos":[{exportPath, originPath}]}content/biz/attachments/…                     # 附件本体（按清单写入服务端）data/appdata.mv.db                            # 嵌入式 H2 示例库（数据层）props.name                                    # 复用包名 → appName，多个环节复用
```  
  
这些端点本应经过模板鉴权组件做登录校验。反编译 4.13.0 的鉴权逻辑（示意还原）：  
```
// wysiwyg 插件 4.13.0，/view/duchamp/** 全端点共用// DuchampTemplateRequestChecker.checkRequest（逻辑还原）String templateId = normalize(req.getParameter("tplPath"));// normalize 会剥掉模板目录前缀，例如 "reportlets/xxx" → "xxx"if (StringUtils.isEmpty(templateId)) {    return true;                    // 空值 = 判定为"无需登录的模板访问"，直接放行}return loginCheck(req, templateId); // 正常路径：按 templateId 查权限
```  
  
缺陷就在这：?tplPath=reportlets  
 剥掉 reportlets  
 前缀后得到**空字符串**  
，checkRequest  
 对空 templateId 直接返回 true。请求被当成"无需登录的模板访问"，未认证用户就此进入了本该登录才能用的上传与 apply 流程。带尾斜杠的 reportlets/  
 同样剥空——证明根因是"空值放行"而不是某个特定字符串。版本差分给了实锤：4.15.0 加了空值卫兵，同样的请求被拒。  
  
一个参数归一化为空，整棵 /view/duchamp/**  
 端点树的登录校验就全部失效。这是 360 通告里"资源复用与模板导入接口在特定请求形态下会错误放行未登录请求"的代码形态。  
## 0x2 字段流向：复用包里两个不带过滤的入口  
  
进门之后看数据流。复用包应用阶段，导入组件把包内字段往两个危险方向送，对应两个缺陷。  
  
**入口一：props.name 一路拼进 JDBC URL。**  
 数据层的导入代码（反编译）：  
```
// fine-app-reuse-2.1-SNAPSHOT.jar  DBFileImporter.writeDuckFilebyte[] data = IOUtils.inputStream2Bytes(dataLayer.getDirectory().read("appdata.mv.db"));this.localImportAndTestConnect(reusePack.readInfo().getName(), data);  // name 可控// localImportAndTestConnect 双流程穿透String dbPath = ExampleDBFileUtils.importDBFileToLocal(appName, data); // ① 写文件ExampleDBConnectionHelper.local(dbPath).testConnection();              // ② 建连接
```  
  
流程① 把上传的 mv.db 写到 <WEB-INF>/assets/reuse/import_temp_dir/<appName>/appdata.mv.db  
——appName 是复用包名，攻击者可控。流程② 打开它时 URL 由 H2ExampleDB.constructUrl  
 拼出：  
```
return String.format("%s:%s;%s", "jdbc:h2", path /* 含 appName */,        "USER=sa;DEFAULT_LOCK_TIMEOUT=5000;MODE=MYSQL;…");   // 尾部固定设置串
```  
  
appName 落在 ;  
 分隔的连接设置串中间——**在这里面注入 ;INIT=… 就是一条合法的 H2 连接设置**  
，URL 尾部自动拼的库名用 SQL 行注释 --  
 吃掉。testConnection  
 建立连接时执行 INIT 语句，H2 内置的 FILE_WRITE(字节, 路径)  
 就是任意路径、任意后缀的文件写。  
  
**入口二：附件清单直通 WEB-INF。**  
 附件层的导入先于实体导入执行：  
```
// BizLayerImporterChain.apply（反编译）AttachmentLayerBean bean = …getAttachmentLayer().getInfo();  // 读包内 AttachmentLayer.jsonfor (AttachmentInfoBean a : bean.getAttachInfos()) {    byte[] data = attachmentLayer.getDirectory().read(a.getExportPath());    SafeImportIO.write(a.getOriginPath(), data);             // originPath 相对 WEB-INF}
```  
  
SafeImportIO.write  
 只有两道检查（反编译，4.13.0）：  

## 0x4 修复拆解：4.15.0 补了什么  
  
按长亭的版本差异分析，FVS 4.15.0 收了两处：**空模板路径下的鉴权判定收紧**  
（空值卫兵，同载荷对照已证失效）和**复用包附件写入路径的禁用校验**  
（WEB-INF 根与配置文件不再可写）。社区复现仓库同步给了完整修复面，挑要害四条：  
- **入口**  
：name 这类进入文件路径 / JDBC URL 的字段做严格白名单（如 ^[\w.-]+$  
）——治的是入口一；  
  
- **连接层**  
：INIT/URL 参数过滤要覆盖 CALL / 函数路径——治的是"加固只防 ALIAS"的路径盲区；  
  
- **实例化**  
：模板 XML 的 class  
 属性只允许可信类名——GeneralXMLTools.readXMLable  
 目前按名字加载任意类，这个 sink 不修，出口 C 的变体永远存在；  
  
- **纵深**  
：JSP-Monitor 覆盖全部 webapps（现在只盯 webroot，ROOT webapp 是盲区）、应用进程降权、运行账户对 WEB-INF/  
 和 Tomcat conf/  
 无写权限。  
  
升级注意配套关系：引擎 11.5.16 与插件 4.15.0 都要到位，官方声明页未单列条目，升级前按帆软支持渠道确认适配。

按惯例给验证思路不给完整武器。第一段完整无害，第二段刻意缺零件。  
  
**第一段（完整），攻击面与鉴权绕过检测。**  
 只发 GET、随机资源名、不携带任何凭据，用带不带 tplPath

 缺三个零件：INIT 单语句载荷的构造与单组件长度限制的绕法、三个出口各自的落地文件内容（web.xml/x.env/frm 模板的具体形态）、apply 触发与结果回读的时机。包结构和调用序留在这里，零件在上文原理里都能找到方向：

**第三段，防御侧的"验证"。**  
 升级后在测试环境重放第一段差分：预期两个请求都被鉴权拦下（4.15.0 空值卫兵生效）；再核对反代/WAF 上 /view/duchamp/reuse  
 的拦截规则是否真的拦 POST 而不只拦 GET。  
## 0x6 自查与处置  
  
**暴露面三问。**  
 装没装 FVS：官方安装包通常自带，别按"我们没买大屏模块"想当然，登录管理后台看插件列表（wysiwyg/FineVis）最准；版本在哪：FineReport 与 FVS 插件两个版本都要核对，任一低于 11.5.16 / 4.15.0 即在射程；谁能连：报表服务暴露在办公网全段甚至互联网的情况在政企环境不少见，/view/duchamp/**  
 是否可达直接决定这漏洞是"高危"还是"理论风险"。  
  
**失陷痕迹，按三个出口的落点排查。**  
 文件面：WEB-INF/web.xml  
 的 mtime 与内容（FR 本体不该有这个文件，**存在即可疑**  
）、WEB-INF  
 下陌生 .env  
 文件、ROOT 等 webapp 下新增 JSP、WEB-INF/classes  
 下来源不明的类、conf/Catalina/localhost/  
 下新增描述符、<WEB-INF>/assets/reuse/import_temp_dir/  
 的残留目录；日志面：security.enhance 插件 JSP-Monitor 的 .blocked  
 改名记录（拦到过就是有人试过）、Tomcat 的 deployDescriptor / StandardContext.reload 记录（非运维窗口出现即为异常）、访问日志里未登录来源对 /view/duchamp/reuse  
 的 POST。失陷处置按 RCE 标准流程走，特别注意：**报表系统里存着全部业务库的连接凭据**  
，主机处置完要按数据库凭据泄露另算一笔。  
  
**处置优先级。**  
 升级到 11.5.16 + FVS 4.15.0 是根治；升不了的先做三件事——网络层把报表服务收进可信来源白名单、WAF/反代拦 /view/duchamp/reuse  
 的 POST（注意 GET 拦不住也拦不全，这只是拖延手段）、评估后临时下线外网暴露。帆软历史漏洞不少（channel 反序列化、模板注入、FVS 目录穿越），这个产品值得在资产库里单独立一个盯升级的条目。
