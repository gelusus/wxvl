重点导读项目速览
Penetration_Testing_POC 是一个面向渗透测试与漏洞研究方向的公开资料仓库，以非结构化归档的方式沉淀了漏洞分析文档、验证脚本、现成利用工具与提权辅助材料。截至克隆时，仓库内文件总量约 2300 个，体积约 3.7 GB。
资料覆盖从固件逆向、移动端组件安全到 Java 反序列化、Web CMS 漏洞的完整链路。内容以中文技术笔记为主要形式，同时保留了大量原始 PDF 论文与离线 HTML 存档。

重点导读核心资产
PART 01现成利用工具
vuln_pocs/exploit-tools/ 下收录了 11 个可直接运行的完整工具工程：BlueKeep 远程代码执行、Redis rogue server、ThinkPHP5 GetShell、Struts2 045、JBoss CVE-2017-12149 反序列化、Weblogic 批量扫描、禅道 GetShell、青龙面板认证绕过至 RCE、Discuz ML-RCE、macOS 内核利用、百度网盘 RCE。
其中 JBoss 工程体量最大，含 746 个文件，源码、编译产物与验证 Jar 齐备；Redis 工程含 40 个文件，覆盖主从复制与rogue server 落盘链路。
PART 02CVE 归档
vuln_pocs/cve/ 保留了 10 个高价值 CVE 的完整验证目录，涵盖 CVE-2018-6389、CVE-2019-0211、CVE-2019-0803、CVE-2019-11043、CVE-2019-11510、CVE-2019-13051、CVE-2019-15107、CVE-2019-16097、CVE-2019-6977、CVE-2019-8451。
PART 03辅助工具集
tools/ 目录的实用价值集中在绕过与探测两类：sqlmap 的多套 tamper 脚本覆盖安全狗、云锁、D盾及企业建站程序过滤规则；Shiro 系列包含三个工具包与一个 fat Jar；Fastjson、Struts2、SpringBoot、ThinkPHP、泛微 ecology、通用 OA 的利用工具并存，另有 Mimikatz 脚本、CSAgent 插件包、内存马相关附件与横向移动工具。
PART 04技术文档
books/ 是仓库体量最大的模块，主题分为三类：漏洞复现与代码审计、框架与协议原理、攻防技术方法论。其中 Java 反序列化系列按基础、漏洞、配置三个分册成体系展开，覆盖 CC1 至 CC7 链、Hessian、JNDI、RMI、URLDNS 与 JavaAgent、Spring、Tomcat 三类内存马；Android 移动安全系列以十六章形式覆盖组件导出、Intent、Binder、ContentProvider、WebView、DeepLink、PendingIntent、广播、UI 欺骗、SSRF、加密存储、证书校验、ZipSlip、FragmentInjection、SELinux 与沙箱机制。
重点导读自动化流水线
仓库内置两条 GitHub Actions 工作流，构成内容增量维护机制。
PART 05CVE 检索工作流
cve_poc_update.yml，触发周期 6 小时。

检索式：CVE-{当前年份} (poc OR exploit) created:>{近三日日期}
GitHub Search API 翻页：3 页，每页 100 条
证据字段：README 摘要（截断 3000 字符）、根目录文件清单（上限 50 项）、作者画像
审校：大模型调用，温度 0.1
分类映射：IoT、Web、提权、桌面四个 README 分区
去重：.cve_poc_seen.txt，保留上限 3000 条
编号补位：重复 CVE 以 -a、-b 后缀区分
提交：.commit_titles.txt 承载提交信息，由机器人账号回写

关键词权重层面，rce、远程代码执行、命令执行、sql、注入、提权、接管、认证绕过、未授权、反序列化、任意文件、getshell 归入高价值类；xss、csrf、开放重定向、点击劫持、dos 归入低价值类并降低收录优先级。
PART 06RSS 聚合工作流
rss_update.yml，触发周期 3 小时。

数据源：RSS 订阅接口
解析：feedparser 条目标题与链接
筛选：Web 类漏洞关键词集
写入位置：README 的 Web APP 章节标记区间
提交：机器人账号直接推送变更

PART 07自动化产出
从提交历史可见，仓库近期的更新记录基本由机器人批量生成，单次提交可追加 7 至 15 个新 CVE PoC 条目，提交信息统一采用自动追加格式并附带审核标记。

仓库为纯资料型集合，无需编译即可阅读 Markdown 与 HTML 文档。涉二进制工具（Jar、Exe、Zip）建议先在沙箱中解包静态分析，确认无异常行为后再运行。README 中的条目数量庞大，配合 Ctrl+F 按 CVE 编号、产品名或漏洞类型检索效率更高。

重点导读安全边界
仓库内多数条目附带明确的 CVE 编号、影响版本与复现步骤，属于公开披露的安全研究成果，但部分工具具备直接利用能力。使用建议：

在虚拟机或容器中隔离运行
优先使用靶场环境替代真实资产
工具二进制先做静态与沙箱分析
