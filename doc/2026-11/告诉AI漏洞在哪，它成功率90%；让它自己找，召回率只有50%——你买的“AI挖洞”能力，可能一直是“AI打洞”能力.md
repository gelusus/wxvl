#  告诉AI漏洞在哪，它成功率90%；让它自己找，召回率只有50%——你买的“AI挖洞”能力，可能一直是“AI打洞”能力  
原创 www.klsec.com
                    www.klsec.com  昆仑AI安全实验室   2026-11-04 09:40  
  
2026年6月，一篇发表在arXiv上的论文做了一个很干净的控制变量实验。  
  
研究团队把LLM渗透测试拆成了两个阶段：侦察和利用。然后分别测量每个阶段的能力边界。结果是一个让整个行业需要重新校准预期的数字对：**当Agent拿到准确的漏洞上下文时，函数成功率高达90.0%。当它需要自己从零开始侦察、定位漏洞时，以目标漏洞召回率衡量，天花板停滞在约50.0%**  
。论文把后者的根因写得很直接：**解析非结构化遥测数据的失败**  
。  
  
这不是“AI行不行”的问题。这是 **“AI做的到底是哪件事”**  
 的问题。你看到的“AI挖到了洞”，绝大多数发生在第一个数字里。你真正需要它做的，是第二个数字。  
  
**一、同一个模型，两种任务，两个世界：数据比直觉更刺眼**  
  
“AI挖洞”和“AI打洞”之间的差距，不是几个百分点的波动，是一个数量级的分野。  
  
UIUC的一项被反复引用的研究给出了一个更极端的对比。GPT-4 Agent利用一日漏洞（one-day vulnerability）：**给定CVE描述时，成功率87%（13/15）；去掉CVE描述后，成功率7%**  
。同样的模型、同样的目标、同样的工具，唯一的变化是“有没有人告诉它漏洞长什么样”  
。  
  
CVE Bench的数据方向一致但幅度稍缓：AI Agent的成功率在“被交给已知漏洞描述”时，大约是“被要求从零发现”时的**两倍**  
，从约13%移动到约25%  
。Security Boulevard的总结一针见血：**“AI在利用已知问题方面可测量地优于发现新问题”**  
。  
  
把这些数字和开头那篇论文放在一起，一个清晰的层次浮现出来：  
  
**给定漏洞描述 → 87%–90%。给定漏洞上下文但需要自己定位 → 约50%。完全自主的冷启动发现 → 个位数到低两位数。**  
  
你追的“更强模型”，在第一个层次上已经接近饱和。**瓶颈不在它能不能打，在于它能不能找到该打哪里。**  
  
**二、“发现”比“利用”难在哪里：不是在代码里找模式，是在噪声里建地图**  
  
为什么“告诉它漏洞在哪”和“让它自己找”之间，差了一个数量级？  
  
**第一层，发现需要的是“解析非结构化遥测数据”，而不是“匹配代码模式”。**  
 解耦论文把自主侦察的失败直接归因于这一点  
。利用一个已知的SQL注入，你面对的是一个明确的参数、一个明确的Payload结构、一个明确的回显判断标准。发现一个SQL注入，你面对的是几百个端点、每个端点几十个参数、每个参数在不同的HTTP方法和Content-Type下有不同的解析行为，以及一个不告诉你“这里有没有问题”的响应。**利用是“在已知坐标上挖”，发现是“在一片没有地图的地形里先画出地图”**  
。  
  
**第二层，发现需要长序列的状态保持和试错闭环，而这恰恰是当前模型的结构性弱项。**  
 一篇系统性综述把87%→7%的差距解读为“当前能力在多大程度上仍然依赖人类 curated 的上下文，而非自主发现”  
。Halocent的分析更直白：**“状态保持与试错闭环，是当前模型的弱项”**  
 ，AI已经是很好的“漏洞发现放大器”，但还不是可靠的“自动攻击者”  
。  
  
**第三层，也是2026年越来越清楚的一层：那被覆盖的50%，高度集中在训练分布之内的低垂果实上。**  
 黑盒测试中，前沿模型的真实覆盖率只有4%–8%，加上外部工具也只到10%–19%。而**结构化的方法论编码进领域专用Agent后，每个漏洞家族的检出率可以超过50%，最高召回率达到80.5%**  
。同一个模型，换了“怎么用”，覆盖率从个位数跳到接近人类水平。**4-8%是“裸模型”在没有方法论时的自主能力，50%和80.5%是“Harness和方法论”的功劳。发现能力的上限，不在于模型“能不能看见”，在于它被放进了一个什么样的搜索结构里。**  
  
**三、MDASH的96%召回率在说什么：不是“模型自己找到了”，是“100个Agent在互相证伪”**  
  
有人会拿出微软MDASH的数据来反驳：CyberGym 88.45%，clfs.sys组件过去5年28个MSRC漏洞96%召回率，StorageDrive的21个植入漏洞全部命中、零误报  
。  
  
这些数字是真实的。但它们精确地说明了“AI发现”的另一个真相：**MDASH的96%召回率，不是某一个模型“自己看出来了”。它是一个由100多个Agent组成的系统的产出。**  
 有的Agent负责扫描代码路径，有的负责**辩论漏洞是否存在**  
，有的负责去重和合并，有的负责构造触发输入来**实锤漏洞**  
。  
  
MDASH的核心设计是**不让任何一个单模型“决定”一个漏洞是否存在**  
。**“模型只是输入，系统才是产品”**  
。它的召回率来自多Agent的交叉验证和辩论机制，而不是来自“模型自己在冷启动条件下有多强的发现直觉”。同一个Mythos Preview，在单Agent框架下是83.1%，在MDASH的100-Agent流水线下是88.45%。差距不大，但**“证明”环节的质量差距，远大于这5个百分点**  
。  
  
Stanford、CMU和Gray Swan在2025年12月的对比实验提供了一个更完整的画面。10个OSCP认证的人类测试员 vs 7个AI Agent框架，在一个真实的8000主机网络上。最好的AI框架总排名第二，压过了10个人类中的9个。**但它对每一个人类的假阳性率都更高**  
，而且它在**业务逻辑测试和GUI交互**  
上具体地挣扎——那些需要理解“应用应该做什么”、而不仅仅是“代码里有什么漏洞”的类别  
。  
  
**AI在“枚举和利用”上可以超过大多数人类。它在“判断什么值得挖”和“理解业务意图”上，还差得很远。**  
 而这后两件事，恰恰是“自主发现”的核心。  
  
**四、对你意味着什么：重新定义你买的到底是什么**  
  
如果你在评估AI安全工具，或者自己搭Agent，2026年下半年的判断框架需要围绕“它在做哪件事”来重构。  
  
**第一，把“漏洞利用”和“漏洞发现”当作两个独立的产品能力来评估。**  
 一个工具在已知CVE上的复现率是90%，在靶场上的“自主发现”率是50%，在真实冷启动环境里的覆盖率是4-19%。**这三个数字不是同一个能力的三个刻度，是三种不同任务下的三种不同表现。**  
 如果一个工具的宣传语是“AI自主挖洞”，问它：你的“发现”是在给定漏洞类型的靶场上测的，还是在没有先验信息的真实代码库上测的？你的召回率是在已知漏洞总数固定的条件下算的，还是在不知道有多少漏洞的条件下算的？  
  
**第二，把“方法论”和“Harness”的权重提到模型之上。**  
 同一个模型，裸跑黑盒覆盖率4-8%，加上结构化方法论后每个漏洞家族检出率超过50%。**方法论带来的提升，远大于从Sonnet换到Opus带来的提升。**  
 你花钱买“更强模型”的边际收益，在“发现”这个任务上，被“有没有一个知道该往哪里看的流程”远远甩在后面。  
  
**第三，用“证伪”而不是“自评”来衡量发现的可靠性。**  
 Refute-or-Promote的经验是：候选发现必须经过对抗性击杀才能推进。**“一个Agent找不到证伪证据”比“一个Agent声称我确认了”可信得多。**  
 一个系统如果只告诉你“我发现了X个漏洞”，而没有“我用什么独立机制试图推翻过这些发现”，你拿到的是一份候选清单，不是一份结论。  
  
**第四，接受“AI是放大器，不是发现引擎”这个定位。**  
 那篇系统性综述的结论值得直接引用：当前更可靠的定位是 **“强力的漏洞复现/利用助手 + 人机协同的模式泛化器”，而非“无人值守的自主挖洞机”**  
。**“发现”这件事的停止条件、业务影响判断、以及在噪声中识别信号的能力，仍然在人这一侧。**  
  
**写在最后**  
  
“AI挖到洞”这件事是真的。但那个洞，大概率在“有人告诉它该往哪里看”的那50%里，在“训练分布覆盖的模式”里，在“低垂果实”的集合里。  
  
**给定漏洞位置，成功率90%；让它自己找，召回率50%。这两个数字之间的差距，不是模型不够强，是两种任务在难度结构上的本质差异。**  
 发现需要解析非结构化数据、需要在没有地图的地形里先画地图、需要长序列的状态保持和试错闭环。这些恰恰是当前模型在没有外部结构支撑时最不擅长的东西。  
  
你追的“更强模型”，解决不了“AI不知道该往哪里看”的问题。能解决那个问题的，是一个知道该往哪里看的流程，一个会互相证伪的系统，以及一个不把“AI找到了”和“AI被告诉该找什么”混为一谈的判断力。  
  
**下次看到一个“AI挖洞”的战绩，先问一句：这个洞，是它自己找到的，还是有人告诉它该往哪里看的？**  
 这个问题的答案，决定了你看到的是一个能力，还是一个被精心构造的演示。
