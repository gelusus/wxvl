**数据背后的五条规律**  
  
1. "默认值"是最高频的坑。  
CWE-798   
硬编码  
密钥出现 11 次，加上各类默认口令，几乎每个项目都栽在"没设环境变量就带病上线"。khoj 的 !secret、poster-design 的xpai-design-admin-secret、coai 的 root/chatnio123456，同一类错误换了三个名字。  
  
2. SSRF 是 AI 应用的高发区  
。  
34 条 SSRF 是全场最大漏洞族。原因很直白：AI 应用大量内置"截图、网页读取、链接预览"能力，全是  
让服务端浏览器去访问 URL  
的天然入口；poster-design 的 puppeteer 截图接口甚至没鉴权，file://、云元数据 169.254.169.254 想访问就访问，还能把渲染结果以图片回显给攻击者。  
  
3. 缺失认证与越权是"孪生兄弟"。  
CWE-306（缺失认证）15 处 + CWE-639（IDOR）8 处。maxun 的 GET /storage/recordings 直接返回  
所有用户  
的 Robot 及其 Google/Airtable OAuth 令牌；AI-Infra-Guard 更离谱——把请求头里的 username 当身份，没有任何凭证校验。  
  
4. Agent 工具链成了新攻击面。  
当"LLM 调用工具"成为标配，工具本身就成了 RCE 通道：maxun 的 script、AI-Infra-Guard 的 execute_shell（shell=True 执行 LLM 生成的命令，sandbox_execution 标志是死代码）、open-multi-agent 的 Consequential bash。  
给 LLM 一把工具，就等于给提示注入一把钥匙。  
  
5. 中危占 58%，但组合起来就是超危。  
为什么中危能占到近六成？  
101 条中危里，SSRF + 路径穿越 + 硬编码密钥任意两两组合，都能串成完整攻击链  
——单独看都不致命，连起来就是接管。
