#  Windows 11锁屏界面存在新的零日漏洞，攻击者可利用该漏洞绕过 BitLocker 保护  
原创 ZM
                    ZM  暗镜   2026-11-26 00:00  
  
最新披露的 Windows 11 零日漏洞 FastUnlock 允许拥有物理访问权限的人绕过 Windows 锁屏的部分功能，并在不登录的情况下运行代码。  
  
该漏洞会影响微软内置的屏幕阅读器“讲述人”，即使启用了 BitLocker，也可能暴露正在运行的电脑。据报道，该绕过方法不会破坏 BitLocker 加密，也无法证明攻击者可以解密已关机的硬盘。  
  
这位名为 Nightmare Eclipse 的研究人员报告称，他在安装了2026 年 11 月安全更新的Windows 11 版本 26H2 上测试了 FastUnlock 。  
  
研究人员表示，从发现漏洞到攻破测试机大约用了五分钟。这个数字指的是一次已报告的测试，并非在所有Windows设备上测得的攻击时间。该研究人员没有测试Windows 10。  
  
据报道，此次攻击需要物理访问权限，并且至少需要一个与在线 Microsoft 帐户关联的用户帐户。攻击涉及帐户恢复屏幕，攻击者可以利用该屏幕，通过“讲述人”功能与登录前本不应显示的界面进行交互。  
  
问题不在于Windows在锁屏界面提供屏幕阅读器，而在于屏幕阅读器可以访问锁屏界面之外的控件。  
  
网络安全新闻此前在其11月的“周二补丁日”报道中提及了两个独立的Windows BitLocker安全功能绕过漏洞：CVE-2026-97015和CVE-2026-119832。这些修复程序不应与FastUnlock补丁混淆。  
  
截至 11 月 20 日，现有报告尚未发现微软针对 Narrator 缺陷发布的安全公告、CVE 编号或修复程序。  
  
ThreatLocker 对FastUnlock 进行了测试，并报告称它可以在 WsiAccount 账户下运行代码，该账户是 Windows 锁屏界面使用的账户。该账户并非管理员账户。  
  
结果证实，设备上的某人无需登录即可运行软件，但并不能证明他们可以接管已登录用户的会话、获得管理员权限或读取驱动器上的每个文件。  
  
区别在于驱动器解锁的时机。BitLocker 保护的是静态数据，但一旦 Windows 启动且系统驱动器解锁，锁定屏幕和 Windows 帐户权限就会控制用户可以访问的内容。  
  
FastUnlock 针对的是Windows 恢复环境的后期阶段。这与之前报道的名为 YellowKey 的 Windows 恢复环境漏洞不同，后者是在 Windows 完全加载之前攻击 BitLocker 保护。  
  
微软的 BitLocker 通用指南建议，对于需要更强物理访问防护的设备，应将可信平台模块 (TPM) 与启动 PIN 码结合使用。启动 PIN 码与 Windows 登录 PIN 码是不同的。  
  
它通过要求在访问驱动器之前进行身份验证来帮助保护已关机或休眠的设备。但它不会修复“讲述人”功能，也不会保护已解锁的驱动器。  
  
对于可能丢失、被盗或无人看管的笔记本电脑，安全团队应优先考虑关机或正确配置休眠模式，而不是睡眠模式。微软指出，睡眠模式会将正在运行的程序和文档保留在内存中，并且设备唤醒时无需输入 BitLocker 启动 PIN 码。  
  
在微软发布针对 FastUnlock 的具体指南之前，团队应限制对暴露设备的物理访问，并密切关注相关安全公告。在已审查的报道中，尚未发现任何利用 FastUnlock 发起的攻击。但这并不意味着无人看管的锁定笔记本电脑与已关机的笔记本电脑等同。
