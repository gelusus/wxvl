重点导读概述
OA-EXPTOOL 是一个以 Python 编写的 OA 系统漏洞检测命令行框架。项目采用 MSF 风格的交互式命令行作为人机界面，用统一的 YAML 文件承载漏洞验证逻辑，把厂商、产品、请求方法、请求体、响应匹配、变量提取压缩到同一套描述格式中。目前仓库内置 111 个 POC，覆盖通达 OA、致远 OA、用友系列、泛微 e-cology、万户 OA、蓝凌 OA 六条产品线。
与单纯的发包脚本不同，该工具在框架层解决了三个问题：漏洞描述的可维护性、批量目标的调度方式、以及多步骤请求之间变量传递的连续性。运维人员无需改动源码即可扩展检测范围，编写新 POC 只需新增一个 YAML 文件。
重点导读架构
PART 01分层
项目为五文件结构：main/yaml.py 负责 POC 解析，main/deal.py 负责目标归一化，main/request.py 负责请求编排与响应校验，main/output.py 负责终端着色输出与报告落盘，main/console.py 负责交互式命令解析，入口为 scan.py。
PART 02交互层
交互层基于 Python 标准库 cmd 模块派生 MyCmd 与 Entrance 两个命令类。MyCmd 暴露八个厂商快捷命令：zyscan 对应致远、tdscan 对应通达、yyscan 对应用友、whscan 对应万户、llscan 对应蓝凌、fwscan 对应泛微、frscan 对应帆软、htdlscan 对应天融信。Entrance 承载 set、show、use、run、option、q 六个子命令，构成厂商内部的二级会话。
PART 03解析层
解析层读取 bin/module.json，将命令别名映射到 book/ 下的目录名，随后遍历目录内 YAML 文件并归一化为等长的列表结构：编号、名称、时间、说明、请求方法、路径、请求体、请求头、匹配条件、提取器、参考链接。字段缺失时填入占位符而非抛错，单个文件解析失败时将其移出执行队列并继续。
PART 04执行层
执行层按 POC 顺序遍历目标地址，对每个 POC 按 YAML 中的 method 与 path 顺序发起请求。GET 与 POST 各自维护独立的请求头计数器，请求体按换行重组为标准换行格式后提交。全部请求完成后统一进入校验环节。
PART 05输出层
输出层区分命中、未命中与请求异常三种状态。命中结果同时写入终端与 report.txt，文件内容为地址、漏洞名称、参考链接三段式，便于直接作为工单附件。
重点导读目标处理
目标输入支持单地址与文件两种模式。地址未带协议头时默认补全 http://，未带端口时按协议分别取 80 与 443，最终统一归一化为 scheme://host:port 形式。文件模式逐行读取目标清单。
代理通过 set proxy 指定，格式为 IP 与端口，写入环境变量后由 requests 复用。代理置为 None 时清空环境变量中的代理设置，回退至系统默认。

PART 07漏洞类型
从文件命名可见的漏洞类型包括 SQL 注入、任意文件上传、任意文件读取、远程命令执行、反序列化、XXE 注入、路径遍历、任意用户登录、会话信息泄露、表达式注入等。
PART 08描述规范
单个 POC 为一个 YAML 文件，字段分五组。id 为必填的漏洞名称，time 为可选的披露时间。info 组承载名称、作者、等级、描述、参考链接与标签。http 组定义请求序列与验证规则。matchers 组给出响应断言，matchers-condition 取 and 或 or 决定多个断言之间的组合关系。extractors 组定义变量提取规则。
PART 09断言
断言支持 word、status 等类型，作用区域可选 body 与 header。word 类型在响应正文或响应头中做子串匹配，status 类型比对响应状态码。未指定作用区域时默认在响应正文中匹配。
PART 10提取器
提取器用于多步骤请求链。规则中指定触发时机为第几次请求、正则表达式、匹配目标位置以及待替换的占位符名称。当目标位置为 Gheader 或 Rheader 时，正则作用于响应头字典；当目标为 body 时正则作用于响应正文。提取结果回写到下一轮请求头的占位符处，实现会话 Cookie 与令牌的自动续传。
重点导读请求细节
请求默认携带固定的 Chrome User-Agent 与 Accept-Language，并生成 10.0 网段的随机 X-Forwarded-For 与 X-Real-IP 头。超时时间 5.1 秒，证书校验关闭，重定向不跟随。
