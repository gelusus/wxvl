#  黑客利用CVSS 10.0级Hex.pm RCE漏洞，入侵6台包注册服务器

![Hex.pm RCE漏洞](https://mmbiz.qpic.cn/sz_mmbiz_png/icBE3OpK1IX07fzMBwaNZazC4Tz8bsQ1PNPgq2wcicqibYv7IKLhyBAGUj0CCXjZ73kfE3UOwBBaBOuRmzxW9wFOvZGwltkCYtJnzRgjZBbSrM/640?wx_fmt=png "")  
  
  
近期，一名攻击者在Hex.pm的6台生产服务器上执行了操作系统命令。Hex.pm是Elixir与Erlang开发者获取依赖包的官方包注册中心。  
  
  
此次攻击利用的漏洞自2016年2月起就存在于Hex.pm的代码中。服务维护团队在检测到首个恶意请求后，仅用约15分钟就完成了所有服务器的补丁部署。  
  
  
后续核查未发现任何包被篡改的痕迹。Hex.pm团队表示，目前无法排除攻击者读取过邮箱地址、密码哈希、双因素认证密钥等账户数据的可能。  
  
  
Part  
01  
  
Hex官方公布用户应对措施  
  
  
维护团队已更换会话签名密钥与访问令牌密钥，所有hex.pm账号均已被强制登出。账号持有者需完成以下操作：  
  
- 更改hex.pm账号密码。  
  
  
- 重置双因素认证：绑定新的身份验证器条目，妥善保存新的恢复码。  
  
  
- 通过mix hex.user auth命令重新登录客户端；Erlang项目用户可使用rebar3 hex user auth命令完成登录。  
  
  
- 未来几天Hex客户端将发布新版本，搭载全新的注册中心签名系统，版本上线后请及时更新。  
  
  
- 警惕钓鱼攻击。由于邮箱地址可能泄露，所有涉及Hex的邮件都要确认链接指向hex.pm域名后再点击。  
  
  
API密钥无需更换。这类密钥为随机生成的128位值，仅以HMAC-SHA256哈希形式存储，实际上无法被暴力破解。密码采用bcrypt算法哈希存储，虽能降低猜解速度，但弱密码仍存在被破解风险，因此修改密码十分必要。  
  
  
报告作者之一Peter Ullrich在Elixir论坛的维护者说明中表示，从未注册过hex.pm账号、仅获取公开包的开发者无需重置任何信息。通过GitHub注册的用户仍需重新登录客户端，若已开启双因素认证，也要同步重置。  
  
  
官方同时提醒，在新版本客户端发布前，用户应仅从repo.hex.pm获取包，不要使用第三方镜像。目前注册中心签名密钥尚未更换，该密钥也在攻击者可能读取的凭证范围内。  
  
  
Part  
02  
  
满分RCE漏洞存在超十年  
  
  
该漏洞编号为CVE-2026-129514，CVSS评分达满分10.0，存在于Hex.pm用于解析Erlang数据格式请求体的解析器中。该解析器的运行优先级高于路由与认证流程，攻击者向站点任意地址发送无需认证的POST请求，即可触发漏洞。  
  
  
相关解码函数原本设计为安全模式，确实会拦截函数等危险表达式，但会接收带__struct__键的映射，导致请求体可以伪装成应用已加载的任意Elixir结构体。  
  
  
2016年2月23日，代码中本可拦截该风险的安全检查被移除，这也是漏洞存在时间的起点。目前没有证据表明周一之前该漏洞曾被利用。  
  
  
攻击者构造的结构体本身不会执行任何操作，只会触发报错。随后错误上报代码会检查该结构体，检查过程会调用Ecto、DBConnection等数据库依赖库，最终导致服务器执行攻击者指定的函数，以注册中心服务账号的权限运行操作系统命令。  
  
  
安全公告显示，Hex.pm受该漏洞影响的时间范围为2016年2月23日至事发周一。修复提交后，解码器会直接拒绝所有包含带__struct__键映射的内容。截至周一UTC时间18:31，所有Hex.pm服务器均已运行补丁版本。  
  
  
Hex.pm团队在昨日发布的事件报告中表示，负载均衡日志显示，周一UTC时间18:16至18:29期间共记录到69次漏洞利用请求，全部来自两个IP地址。漏洞利用过程中生成的文件出现在6台Web服务器上，其中一台在请求到达仅3毫秒后就出现了相关文件。这6台服务器中有3台是在攻击过程中上线的：服务重启时启动的机器仍运行存在漏洞的版本。  
  
  
为核查包完整性，团队将所有数据库表与首次漏洞利用请求前两分钟的备份做了比对，所有差异都可追溯至正常业务活动。攻击期间发布的23个版本均与审计日志一致，没有任何旧版本被篡改，当晚写入的包与注册中心文件也和数据库记录完全匹配。  
  
  
由于数据库读取、Shell命令执行、环境变量访问、文件存储直接读取等操作均未记录日志，Hex.pm团队写道：“我们无法排除攻击者访问过数据库存储数据的可能。”该数据库存储了邮箱地址、密码哈希、API密钥哈希、双因素认证密钥与会话数据，私有包也可能在不留痕迹的情况下被读取。  
  
  
核查未发现攻击者遗留的Shell，审计日志中也没有新增账号或云密钥记录。目前攻击者身份尚未查明。这两个地址早在上周晚些时候就有活动痕迹，说明攻击者此前搭建了Hex.pm本地副本开展测试。  
  
  
攻击结束后，周一UTC时间19:07，团队收到了另一封关于同一漏洞的安全报告邮件。截至昨日上午，除注册中心签名密钥外，团队已更换了所有攻击者可能读取的凭证。周一晚间，团队已分别向瑞典数据保护局、美国CISA、欧盟ENISA上报了此次安全事件。  
  
  
Part  
03  
  
三款Elixir生态库修复同类漏洞  
  
  
此次事件发生的同时，三款广泛使用的Elixir库的维护者也披露了各自涉及不可信数据构造结构体的漏洞，并于昨日发布了修复版本。这些漏洞为独立披露，不代表Hex.pm遭到了进一步攻击。  
  
  
![](https://mmbiz.qpic.cn/mmbiz_png/icBE3OpK1IX33rEhPX3B9qoial3SXFWor7zvUDGqE2gfm9jrWCicYZ3Vk8ucyN9mZiaYK6DSPJe1mUsnm8LcME2HSBAUGe5kR7M5S1TE1qibDWD0/640?wx_fmt=png&from=appmsg "")  
  
  
这三个漏洞的利用都需要满足特定条件。Ash安全公告显示，Ash漏洞的利用需要满足三个条件：使用客户端提供游标的键集分页、特定排序字段类型、签名密钥保持默认未设置状态。  
  
  
DBConnection安全公告指出：“db_connection本身不存在可被直接利用的风险”，漏洞触发需要其他组件先将不可信数据解码为结构体。Flop安全公告显示，Flop漏洞的利用条件同样与分页游标相关。  
  
  
此次被利用的漏洞存在于hexpm服务端代码中，不影响Hex客户端。自行搭建私有包注册中心的机构，在部署补丁前都会受到该漏洞影响。
