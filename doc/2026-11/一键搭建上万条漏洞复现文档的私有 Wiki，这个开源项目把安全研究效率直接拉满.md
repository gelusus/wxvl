在攻防演练与漏洞挖掘的日常工作中，多数人卡住的往往不是漏洞本身，而是漏洞的定位与复现路径。市面上的漏洞检索平台普遍存在三个共性问题：收录门槛高、离线环境不可用、复现过程无法沉淀为团队资产。Vulnerability-Wiki 给出了一条务实的解决路径 —— 将散落在互联网上的公开漏洞资料重新组织为可全文检索的文档站点，并提供一键部署形态。
该项目的定位是一个基于 docsify 快速部署漏洞文档的工程化方案，其内容来源于同作者的 Awesome-POC 漏洞库。
重点导读项目概览
Vulnerability-Wiki 由三个可独立部署的文档站点组成，覆盖国产 OA 系统、CMS、开发框架、网络设备、开发语言、操作系统、Web 应用、中间件、数据库、云安全等方向，同时收录零组历史漏洞库与乌云漏洞库的镜像内容。
项目的主干结构极为克制：一份核心漏洞库、一份零组漏洞库、一个 Compose 编排文件。每个站点都是纯静态 Markdown 加一个 Dockerfile，没有数据库，没有后端服务，没有鉴权逻辑。
重点导读模块构成
PART 01docs-base
核心漏洞库，也是内容量最大的部分，全部文档遵循 docsify 的目录与侧边栏规则组织，支持侧边栏折叠、代码高亮、复制、分页导航与全文搜索。
PART 02docs-0sec
零组漏洞库。该站点自 2021 年停运，原始资料为互联网流传的 .docx 文件，项目将其统一转换为 .html 格式后打包为 release 压缩包分发。由于内容量过大影响主站的加载与检索速度，该站点被拆分为独立子项目。
PART 03wooyun
乌云历史漏洞库的镜像站点，以现成 Docker 镜像方式提供，需要挂载上传目录才能正常显示图片资源。

单文档结构统一为：漏洞描述、漏洞影响、网络测绘、漏洞复现。漏洞描述用于快速确认适用场景，影响版本与测绘特征以独立代码块给出，复现部分保留完整请求路径、请求包、Payload 与截图，便于直接复刻。
重点导读技术架构
PART 04目录组织
以产品维度而非漏洞类型维度建立顶层目录，每个漏洞对应一个独立 Markdown 文件，文件名采用 产品名-组件名-漏洞类型-编号 的组合规则。侧边栏文件 _sidebar.md 承担全站导航索引，导航栏 _navbar.md 提供跨分类快速跳转。
PART 05渲染方案
docsify v4，静态资源全部本地化存放于 static 目录。index.html 中通过 window.$docsify 配置 loadSidebar、loadNavbar、auto2top、sidebarDisplayLevel 等参数，搜索插件的 paths 设置为 auto、depth 设置为 1。
PART 06插件栈
侧边栏收起、复制代码到剪贴板、分页导航、Prism 代码高亮、全局搜索、图片缩放，全部分离为独立 js 文件引入。
PART 07镜像封装
两个 Dockerfile 结构完全一致，均基于 sujaykumarh/docsify 基础镜像，将 docs 目录复制到 /data/docs，交由 docsify serve 以 3001、3002 端口分别提供服务。
重点导读部署方式
PART 08本地部署
安装 docsify-cli 后，分别进入 docs-base 与 docs-0sec 的 docs 目录执行 docsify serve docs 启动服务。
PART 09Docker 部署
在对应目录下执行 docker build 构建镜像，再以 docker run 以后台模式映射端口启动。
PART 10Compose 部署
docker-compose.yml 编排三个服务，base 对应 3001 端口，0sec 对应 3002 端口，wooyun 对应 3003 端口。执行 docker-compose up -d 即可完成全部站点的启动。
重点导读运维要点
PART 11编码转换
部分历史文档为 GB2312 编码，在 VPS 环境下可能出现乱码。可通过 convmv 工具对 docs 目录做批量转码处理。
PART 120sec 解压
0sec 站点 404 报错多由 release 压缩包未解压到 docs-0sec 目录引起，解压后需重新构建镜像。
PART 13资源本地化
历史更新中已完成图片本地化处理，站点运行不再依赖外部图床，减少了失效链接与加载失败的情况。
重点导读使用价值
对于安全研究员而言，该项目提供的是一套可自持的漏洞知识底座：全文检索、分类下沉、离线可用、可多端同步到内网。对于团队而言，Markdown 与截图构成的内容格式可以直接接入内部知识库与复盘流程，无需二次加工。
