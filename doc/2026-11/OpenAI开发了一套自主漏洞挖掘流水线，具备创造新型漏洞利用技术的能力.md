漏洞发现正变得更容易规模化，但优先级排序与验证仍是运营瓶颈。OpenAI构建了一个原型，在受控研究环境中寻找 Linux 内核中的安全缺陷。该原型识别并分析了 2308 个 Linux 内核候选发现，动态复现了 1724 个漏洞，并生成了 948 个本地权限提升（LPE）利用程序，这些利用程序可使无特权本地用户获得 root 访问权限。API 成本为 120 万美元。  
# 方法  
  
在高层视角下，OpenAI的流水线运作如下：首先识别 Linux 内核中与安全相关的部分，对这些审计目标进行静态扫描以获取候选发现，在隔离环境中动态复现这些发现，创建概念验证（PoC）利用程序以证明可利用性，生成补丁，最后由人类安全研究人员审查结果。流水线的输出包括根因分析、最小崩溃概念验证、候选补丁以及完整利用程序，以协助人类研究人员评估漏洞严重性并向上游提交修复。  
# 发现  
  
在 2026 年 10 月中旬的一次运行中，OpenAI的流水线使用即将推出的网络模型动态复现了 1724 个漏洞，并为常用 Linux 发行版生成了 291 个信息泄露漏洞的 PoC 以及 948 个可用的本地权限提升（LPE）利用程序。总运行成本为 1213430 API 积分，即每个 LPE 利用程序 1279 美元。  
  
目标虚拟机运行的是未削弱的原厂桌面操作系统，采用与网络安全竞赛（例如 Pwn2Own、TyphoonPWN）相同的威胁模型。历史上，Pwn2Own 与 TyphoonPWN 对 Linux 内核 LPE 利用程序分别提供 2 万美元与 7 万美元的漏洞赏金。将这些历史赏金金额应用于这 948 个利用程序，会产生 1890 万至 6630 万美元的假设估值，约为OpenAI流水线成本的 16 倍至 55 倍。  
  
在适配的 kernelCTF 环境中（该环境为攻击面减少的 Linux 内核版本），OpenAI的流水线获得了 25 个信息泄露 PoC 与 21 个 LPE 利用程序。作为对比，截至撰写时，2026 年 kernelCTF 已接受 26 个经确认的 0-day LPE 利用程序。该活动大致花费了 32936 API 积分。若这 21 个漏洞被项目接受，将带来约 150 万美元的赏金奖励，约为扫描成本的 45 倍。据OpenAI所知，该流水线中的代理至少发现并使用了 10 种新型 Linux 利用技术。  
  
在未来几年内，OpenAI相信，若给定软件项目中存在漏洞，前沿模型很可能能够发现它们，而能力较弱的模型在漏洞披露后也可能能够开发利用程序。在一个没有未知漏洞的世界中，构建并维护高保障软件将至关重要，尤其是操作系统、浏览器、图像解析库、TCP/IP 栈等核心软件。除了发现并修复现有漏洞外，训练模型默认编写安全代码、通过移除不必要功能来最小化攻击面、以及形式化验证，都是有效规模化软件安全的有前景研究方向。  
# 漏洞研究流水线  
  
OpenAI的漏洞研究原型是一个五阶段流水线，核心使用即将推出的网络模型：  
  
漏洞发现：代理识别代码库中与安全相关的部分，并扫描这些部分以获取候选发现。  
  
动态验证：代理尝试在隔离环境中复现每个候选发现，并保留运行时证据。此步骤输出已复现并验证的漏洞。  
  
可利用性评估：代理测试已验证漏洞是否可能实现信息泄露或本地权限提升。  
  
补丁生成：代理生成针对每个已识别漏洞的补丁。  
  
人工审查：安全研究人员在向维护者报告前，审查利用程序、补丁与建议严重性。  
  
在流水线末端，系统打包根因分析、最小崩溃概念验证、候选补丁与完整利用程序，以协助人类研究人员评估漏洞严重性并向上游提交修复。  
# 新型利用技术  
  
OpenAI抽样了代理开发的 166 个利用程序，并分析了其中使用的利用技术。  
据OpenAI所知，代理在抽样利用程序中使用了 10 种新的利用技术。OpenAI与第三方内核利用专家分享了这些利用技术，这些技术对他们而言也是新的。  
  
在这 10 种技术中，两种是新型持久弹性对象，模型使用它们在目标内核缓存中喷射对象；两种是新型页面整理技术，以提高利用可靠性；五种是新型仅数据技术，以直接或通过任意写入获得权限提升；另一种技术涉及任意类型混淆。出于安全原因，OpenAI在本文中省略了这些新利用技术的完整技术细节。  
  
要点：前沿模型并非仅模式匹配已知的易受攻击代码模式，或仅使用已知利用技术；它们展现出创造力与新型方法。
