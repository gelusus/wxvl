PART 02  
  
群晖 DSM：OAuth 接口没把参数和命令分开  
  
   
  
Synology DSM 的 OAuth API 里有一个命令拼接问题，类型是 CWE-88，参数分隔符处理不当。公告的描述很短：远程攻击者可以读写任意文件，也能让服务进入拒绝服务状态。没有账号要求，向量是   
AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:H/A:H  
。  
  
CWE-88 通常意味着请求里的某个值被当成了命令行参数的一部分，空格、分号、引号这类分隔符没有被转义，拼进 shell 之后就成了另一条命令。具体是哪个接口、哪个参数，Synology 没有写。能确认的是结果：文件读写和 DoS 都在影响范围内。  
  
NAS 上的文件不只是用户数据。配置、备份、证书、容器卷、Hyper Backup 的仓库，都在这台机器上。任意文件写再往前走一步，就是改配置、换证书、塞定时任务。公告没有提代码执行，按“能读写任意文件”评估已经够重。  
  
**影响**  
：DSM 6.2.4-25556-9、7.1.1-42962-10、7.2.1-69057-14、7.2.2-72806-11、7.3.2-86009-6、7.4.1-90080-2 之前的版本。BeeStation OS 1.5 同样在列，修复状态仍是处理中。  
  
**触发**  
：OAuth Service 套件处于启用状态，接口可达。不需要账号，不需要交互。  
  
**危害**  
：CVSS 3.1 口径 9.8，CWE-88。读写任意文件，外加拒绝服务。  
  
**公开**  
：Synology 11 月 19 日 15:47 发布 SA-26:21，11 月 20 日 16:25 更新了 7.3 和 7.4 的修复状态；NVD 11 月 23 日 16:17（北京时间）收录。  
  
**修复**  
：DSM 7.4 升到 7.4.1-90080-2 或以上，7.3 升到 7.3.2-86009-6 或以上。7.2.2、7.2.1、7.1 还没有对应的固定版本，官方建议直接升到 7.3.2。临时措施是停用 OAuth Service 套件。  
  
**复现**  
：公告只给了结论，没有接口、参数和 PoC。模板不给，没有可验证的请求可以写。  
  
PART 03  
  
ifm O3D 相机：对外接口连认证都没有  
  
   
  
ifm 是德国的工业传感器厂商，O3D 系列是 3D 相机，常见于产线检测、物流分拣和机器人引导。CERT@VDE 的公告写得很直接：设备上有一个对外接口没有做认证和授权，未认证的远程攻击者可以往里发命令，让设备重启，或者上传恶意固件。  
  
CWE-306，关键功能缺少认证。攻击者不需要知道任何口令，也不需要先登录。重启只是最小的后果，能刷固件就等于拿到设备，之后改配置、改采集逻辑、把相机当成内网跳板都可以。  
  
这批设备通常装在生产网段里，位置比办公网更深。一旦被当成入口，往 PLC、MES、视觉服务器横向的成本会低很多。公告里没有提具体利用链，只列了影响和后果。  
  
**影响**  
：O3D300、301、302、303、304、305、310、311、312、314、353、354、355、361，O3DP01、03、21、23，O3X120、130，共 20 款。对应固件涉及 1.71.10735、1.90.107、1.90.119、1.20.6381、2.10.16、2.0.10412。  
  
**触发**  
：设备的暴露接口可达，能发命令。不需要认证。  
  
**危害**  
：CVSS 3.1 口径 9.8，CWE-306。设备重启、任意命令、恶意固件，最终是完全控制设备。  
  
**公开**  
：CERT@VDE 11 月 23 日 10:00（欧洲时间）发布 VDE-2026-148；NVD 同日 18:17（北京时间）收录。  
  
**修复**  
：没有。公告写明 No Remediation available。只能把设备放进独立网段，限制能访问它的源地址和端口，别让这个接口出公网。  
  
**复现**  
：公告没有给接口路径和请求格式。模板不给，入口都没公开。  
  
PART 04  
  
Virtualizor：一个邮箱地址就是管理员  
  
   
  
Softaculous Virtualizor 是卖 VPS 的常用面板。它的社交登录基于 HybridAuth，用户点“用 GitHub 登录”之后，回调落在   
enduser/auth_callback.php  
。这个文件拿 OAuth 返回的邮箱去查本地账号，查到就把对应的   
uid  
 写进 session。  
  
问题在拼接。查询长这样：  
SELECT uid, email FROM users WHERE email = '<邮箱>'  
。邮箱直接接在引号里，没有走参数绑定。面板里别的地方已经在用   
makequery()  
 的绑定写法，这一处没用。中间也没有   
filter_var  
、长度检查，更没有看提供方的   
email_verified  
。  
  
payload 本身就是一个合法邮箱。RFC 5321 允许 local-part 里出现   
'  
、  
/  
、  
*  
、  
=  
、  
#  
 这些字符，于是   
x'OR/****  
/uid=1#@mydomain.com  
 可以在 GitHub 注册并完成验证。  
//  
 当空格，  
#  
 注释掉后面的引号和域名，整句变成   
WHERE email = 'x' OR uid = 1  
，返回管理员那一行，  
uid  
 进 session，攻击者直接以管理员身份进入面板。  
  
前置条件只有一个：后台开了社交登录，至少配了一个 OAuth 提供方。这个功能默认不开，所以暴露面比“所有 Virtualizor”小。但开了的实例，攻击是预认证的，也不需要自己搭 OAuth 服务。  
  
厂商最初按“无法复现”的低危处理，理由是他们试的 payload 带空格，主流邮箱注册页会拒。研究者换成全   
atext  
 的写法之后，GitHub 接受了这个地址，链路才走通。这一段在公开分析里写得很清楚。  
  
**影响**  
：3.2.9 之前。公开分析在 3.2.8.5 上实测确认。修复版本 3.2.9，2026 年 5 月 12 日发布。  
  
**触发**  
：社交登录开启，至少一个 OAuth 提供方可用。攻击者能收到该地址的验证邮件。  
  
**危害**  
：CVSS 4.0 口径 9.2，CVSS 3.1 口径 8.1，CWE-89。登成管理员后，能读   
users  
 表的密码哈希和   
api  
 表里的 master key；master key 带全部   
act_*  
 权限，可以增删改集群里任意 VPS。研究者自己按 9.8 评估。  
  
**公开**  
：4 月 3 日发现，4 月 20 日报厂商，5 月 12 日 3.2.9 修复，6 月 22 日 Del Security 公开分析（DVE-2026-020）；NVD 11 月 23 日 23:17（北京时间）收录。  
  
**修复**  
：升到 3.2.9。升不了就关掉社交登录，入口消失，问题也就不存在了。  
  
**复现**  
：技术细节、payload 和查库语句都公开，自动化脚本没放。模板不给，要先有一个能收信的 OAuth 账号，再走完整个授权回调。  
  
PART 05  
  
Wing FTP：会话 ID 是算出来的，不是随机的  
  
   
  
Wing FTP Server 的管理后台用会话 ID 认人。公告说这个 ID 不是加密随机数，而是由进程、时间、ServerID 和客户端 IP 这几样状态推导出来的。可预测的来源，加上一个能判断会话是否有效的接口，就构成了枚举条件。  
  
攻击者不需要密码。先生成一批候选 ID，拿   
service_get_license.html  
 当校验器：返回正常说明这个会话还活着，返回错误就换下一个。会话 ID 里含客户端 IP 状态，枚举范围要覆盖到管理员那一侧。撞上管理员正在用的会话，直接接管，面板里的 Lua 控制台也一起拿到。  
  
这类问题比弱口令难防。密码可以改，会话 ID 只能等服务端换掉。管理方能做的只有缩小暴露面：管理端口不对公网，会话超时调短，把在线管理员踢下线重登一次。  
  
**影响**  
：8.2.8 之前。修复版本 8.2.8。  
  
**触发**  
：管理端口可达，目标管理员有活跃会话，攻击者能覆盖到会话 ID 里的客户端 IP 状态。  
  
**危害**  
：CVSS 4.0 口径 9.2，CVSS 3.1 口径 8.1，CWE-341。接管管理员会话，Lua 控制台等于在服务器上执行代码。  
  
**公开**  
：VulnCheck 11 月 23 日发布公告；NVD 同日 23:17（北京时间）收录。  
  
**修复**  
：升到 8.2.8。厂商官网的发布记录目前停在 8.2.2（8 月 17 日），8.2.8 的更新说明还没挂出来，拿到补丁的途径要看自动更新或镜像。升不了就把管理端口收到内网或白名单，缩短会话超时，让管理员重新登录一次。  
  
**复现**  
：公告写了推导要素和 oracle 端点，没有候选生成算法和脚本。模板不给，枚举会话不是一条 HTTP 请求能完成的。  
  
PART 06  
  
Weblate：少一个点，重置信寄给了别人  
  
   
  
Weblate 的重置密码页面按数据库的排序规则找账号。默认排序规则对重音和大小写不敏感，  
i  
 和   
ı  
（无点 i）、  
a  
 和   
á  
 在比较时算同一个字符。邮箱本身是唯一的，比较规则却不是。  
  
攻击者注册一个只差一个字符的地址，在重置页面填进去。数据库按不区分重音的规则比较，把它和受害者的地址当成同一个，于是生成的是受害者账号的重置令牌。邮件按用户填的地址发出去，落到攻击者的邮箱里。点开链接，设一个新密码，账号就换主人了。  
  
GitHub 的安全公告写明了三个前提：数据库排序规则把这两个地址判等、攻击者能拿到一个同形邮箱、目标账号没有有效的二次验证。公告也说明，演示的链路不绕过已有的 2FA。  
  
同一个比较规则还影响身份关联和邀请。2026.11.1 增加了账号安全检查，用来列出历史遗留的同形身份，方便清理。  
  
**影响**  
：2026.11 之前的所有版本。修复版本 2026.11，2026.11.1 补上历史身份检查。  
  
**触发**  
：数据库排序规则判等，攻击者控制同形邮箱，目标没开二次验证。  
  
**危害**  
：CVSS 4.0 口径 9.1，CVSS 3.1 口径 7.4，CWE-178。未认证接管账号，管理员账号同样适用。  
  
**公开**  
：NVD 11 月 23 日 06:17（北京时间）收录；GitHub 安全公告 GHSA-6hph-c9x9-4mcv。  
  
**修复**  
：升到 2026.11，再跟到 2026.11.1 做一次历史身份检查。给管理员账号开 2FA，这条链就走不通。  
  
**复现**  
：公告给了前置条件和比较规则，没有给具体字符组合和脚本。模板不给，要真的注册一个同形邮箱并收信。  
  
PART 07  
  
Portainer：Standard 用户接进了别人的容器  
  
   
  
Portainer 用 WebSocket 提供两种交互：  
/api/websocket/attach  
 接管一个运行中的容器，  
/api/websocket/exec  
 在容器里起一个 exec 会话。两个处理函数都只检查调用者对这个环境的权限，然后直接把连接劫持到 Docker socket。Docker 代理那条路径上有 ResourceControl 的容器归属检查，WebSocket 这条没有。  
  
attach 的容器 ID 只校验是不是十六进制，没有最小长度，Docker 又支持前缀匹配，不知道完整 ID 也能爆破。exec 的 ID 同样只校验形状，处理函数不会回头看这个 exec 属于哪个容器。容器 ID 和 exec ID 还会从 events、tasks、network inspect 这些不过滤的响应里漏出来。agent 和 Edge 的 WebSocket 代理是同一套逻辑，远程环境一样中招。  
  
结果是最低权限的 Standard 用户，只要能访问某个环境，就能在那个环境里任意容器拿到交互式 root。容器如果挂了   
docker.sock  
 或者是特权容器，下一步就是宿主机。  
  
**影响**  
：2.39.x 里 2.39.9 之前的版本、2.40.x 到 2.45.x 里 2.45.4 之前的版本、3.0.x 里 3.1.0 之前的版本。修复版本 2.39.9、2.45.4、3.1.0，11 月 19 日发布。  
  
**触发**  
：持有 Standard 用户角色并能访问某个环境；WebSocket 可达；知道或能枚举出容器 ID、exec ID。  
  
**危害**  
：CVSS 4.0 口径 8.7，CVSS 3.1 口径 8.8，CWE-639。跨租户接管容器，读环境变量、挂载文件、凭据和进程，权限足够时接管宿主机。  
  
**公开**  
：6 月 24 日首报，7 月扩展到 exec 和 Edge 路径，11 月 13 日、16 日分别合入修复分支，11 月 19 日发版并公开公告；NVD 11 月 23 日 06:17（北京时间）收录。这条有 18 位研究者独立报告。  
  
**修复**  
：升到 2.39.9、2.45.4 或 3.1.0。升不了就把互不信任的租户拆到不同环境，别再共用；同时审计 attach 和 exec 的访问日志，看有没有人请求了不属于自己的容器或短前缀 ID。  
  
**复现**  
：公告给了代码位置、攻击路径和影响，没有脚本。模板不给，要先登录，再拿到目标容器的 ID。
