11 月 23 日，开源地理空间数据服务端 GeoServer 发布安全公告，集中修复五枚漏洞。单枚漏洞的评分均不算突出——最低仅 6.9 分，但五枚漏洞按序串联后，构成一条从未认证直达命令执行的完整利用链，链级评分 9.8。目前 PoC 已公开，国家信息安全漏洞共享平台已于 11 月 25 日收录并发布安全公告。  
  
本文将依次说明：利用链各环节的衔接逻辑、默认配置为何构成完整攻击面，以及受影响单位应遵循的处置顺序。

01  
  
这不是一个洞，是一条链  
  
先说明背景。GeoServer 是 OSGeo 基金会维护的开源 Java 地理空间数据服务端，按 OGC 标准对外提供 WMS、WFS、WCS 等地图与要素服务，是国内大量 GIS 平台底层的地图服务引擎。国家信息安全漏洞共享平台在安全公告中明确指出：该组件在政府与行业地理信息基础设施中部署较广——政务服务、测绘地理信息、自然资源、水利、生态环境、交通运输、应急管理等领域的业务系统，普遍通过它发布图层空间数据。换言之，这类服务器往往直接承载着政府和国计民生系统的核心地理信息服务。  
  
典型部署行业  
  
政务服务  
  
测绘地理信息  
  
自然资源管理  
  
水利水务  
  
生态环境  
  
交通运输  
  
应急管理  
  
住建与城市规划  
  
行业 GIS 平台  
  
这类系统中承载的空间数据具有基础性与敏感性——图层背后关联着行政区划、自然资源权属、基础设施分布等政务与行业数据。服务一旦被接管，数据泄露与服务中断的影响均不限于单一系统。  
  
此次串联的五枚漏洞，单独看各自是一个常规缺陷：路径信息泄露、访问控制绕过、XML 注入、会话伪造、反序列化。但官方公告与第三方分析均指向同一事实：默认配置允许这五个缺陷被同一攻击序列连续利用。利用链的五个环节如下：  
  
第 1 环  
  
超长查询 ID → 异常回显数据目录绝对路径  
  
CVE-2026-129244 · CVSS 6.9 · 纯信息泄露，为后续环节提供数据目录定位  
  
第 2 环  
  
service=x/WFS → 访问控制规则被绕过  
  
CVE-2026-129243 · CVSS 8.8 · 匿名用户获得写入存储查询的入口  
  
第 3 环  
  
XInclude 注入 → 读走安全配置文件  
  
CVE-2026-120705 · CVSS 8.6 · 拿到 remember-me 密钥和管理员口令摘要  
  
第 4 环  
  
固定默认密钥 → 伪造管理员会话  
  
CVE-2026-129245 · CVSS 9.2 · 无需明文密码即可伪造管理员会话  
  
第 5 环  
  
JDBC 用户服务反序列化 → 命令执行  
  
CVE-2026-129242 · CVSS 8.6 · 以 GeoServer 进程权限执行任意命令，默认容器镜像下即 root  
  
一个容易被忽视的细节：第 5 环的 JDBC 用户服务默认处于未注册状态，看似不可触及。但第 4 环伪造的管理员会话，恰好提供了通过 REST 接口注册该服务的权限——前一环节为后一环节提供前置条件，这正是利用链的威胁所在。  
  
02  
  
五环逐个拆：每一步到底发生了什么  
  
环 1 · CVE-2026-129244 · 存储查询异常泄露路径  
CVSS 6.9  
  
WFS 存储查询接口在处理超长 ID时缺少长度限制，异常信息将GeoServer 数据目录的绝对路径原样回显给客户端。该路径是整条链的第一块拼图：后续环节要读取的配置文件位置，完全依赖它定位。  
  
单独评估时它只是信息泄露，多数扫描器会将其标为"低危"。但缺少该路径，后续文件读取将无从定位——利用链的威力，恰恰由这类"低危"漏洞累积而成。  
  
环 2 · CVE-2026-129243 · 服务名前缀绕过安全规则  
CVSS 8.8  
  
GeoServer 的服务调度器会把x/WFS 这种带路径分隔符的服务名按前缀解析成 WFS 处理，但服务安全检查仍用原始值去匹配规则——规则表中不存在 "x/WFS" 的匹配条目，检查直接放行。仅由服务安全规则保护的操作，匿名用户即可调用。  
  
默认配置下，攻击者由此获得创建和删除 WFS 存储查询的权限——相当于为第 3 环的注入载荷建立了投递通道。  
  
环 3 · CVE-2026-120705 · XInclude 读走安全配置  
CVSS 8.6  
  
WFS 2.0 的 GetFeatureById 存储查询未转义调用方提供的 ID 参数，且解析 XML 时没有使用项目统一的实体解析器。存储查询文本在重载时被二次解析，攻击者可以注入xi:include并利用允许的本地 file 协议，把数据目录中的安全配置文件完整读出，内容可经错误响应带回。  
  
该环节产出两项关键数据：remember-me 签名密钥与管理员口令摘要。至此，伪造管理员会话所需的全部材料已经齐备。  
  
环 4 · CVE-2026-129245 · 固定密钥伪造管理员会话  
CVSS 9.2 · 五环最高  
  
remember-me 自动登录 Cookie 用 security/config.xml 中的密钥加用户口令摘要签名。问题在于默认数据目录使用固定密钥——官方镜像的默认值，即全球实例的统一默认值。攻击者取得密钥与口令摘要后，无需获知明文密码，即可伪造合法的管理员 remember-me Cookie 并换取管理员会话。  
  
已公开的复现记录显示：伪造的 Cookie 直接被 REST API 接受，攻击者由此以管理员身份控制系统。该环节是整条利用链的分水岭：此前攻击者仅是未认证的越界访问，此后则具备完整管理员权限。  
  
环 5 · CVE-2026-129242 · JDBC 服务反序列化执行  
CVSS 8.6 · 终点  
  
最后一步落在 JDBC 用户组与角色服务上。它用 ResultSet.getObject() 读取用户和角色属性，而底层数据库驱动会对 OTHER 类型字段中的序列化 Java 对象执行不受限反序列化。攻击者以管理员身份通过 REST 接口上传一个特制的 HSQLDB 数据库并注册为 JDBC 服务，随后触发一次用户属性查询——反序列化执行，命令以 GeoServer 进程权限落地。  
  
公开的复现记录显示：进程内执行 id 命令，容器默认部署返回uid=0(root)，普通用户部署返回uid=999(tomcat)。前者意味着应用边界被完全击穿，攻击者可进一步向宿主机与内网横向扩展。  
  
03  
  
更值得警惕的问题：默认配置本身就是攻击面  
  
这条链为什么在默认配置下就能跑通？因为利用条件把四扇门全留开着：  
  
默认配置项  
  
它在链条里的作用  
  
匿名可访问 WFS  
  
第 1–3 环的入口全程无需登录  
  
remember-me 启用  
  
密钥为固定默认值  
  
第 4 环伪造会话成功率高，所有实例共用同一默认密钥  
  
JDBC 用户/角色服务  
  
可由管理员注册  
  
第 5 环的执行入口，由第 4 环的管理员会话打开  
  
官方容器镜像  
  
以 root 运行  
  
第 5 环的命令直接是 root 权限，应用边界形同虚设  
  
"开箱即用"不等于"安全可用"  
  
这并非 GeoServer 一个组件的问题。近两年的公开事件反复呈现同一类风险：默认配置的初衷是降低使用门槛，但当默认值中包含固定密钥、匿名服务与 root 进程时，"能够运行"与"能够被攻破"实际上是同一状态。对政企单位而言，资产暴露面评估除核查补丁情况外，更应优先确认服务的运行身份、进程权限与网络暴露方式。

05  
  
处置：升级是唯一解，缓解只是争取时间  
  
官方已发布修复版本：3.0.2 / 2.28.6 / 2.27.7及对应分支更高版本。要点在于：这条链由五个相互独立的缺陷串联，仅修复其中一处并不消除组合利用风险，因此不可选择性修复，应整体升级，一次性消除全部五环风险。  
  
  
第一步 · 立即  
  
收敛暴露面：WFS 与 REST 接口不再匿名可达，管理台与用户/角色服务限受控网段访问。公网可达实例应于当日完成收敛。  
  
  
第二步 · 补丁排期内  
  
升级至 3.0.2 / 2.28.6 / 2.27.7。2.27 系列已停止维护，2.27.7 仅为过渡性缓解，应纳入升级计划并尽快迁移至受支持分支。升级前应核对扩展组件与数据目录的兼容性。  
  
  
第三步 · 加固收尾  
  
更换 remember-me 默认密钥并轮换管理员口令（即便已完成升级，也应防范密钥此前已泄露）；以非 root 用户运行服务；限制数据目录写权限。  
  
✅ 暂无法升级的单位，可参考以下临时缓解清单  
  
① 反向代理/WAF 拦截service 参数含路径分隔符（如 x/WFS）的请求；② 拦截超长 storedQuery_id，并排查数据目录 wfs/query 与 workspaces/*/wfs/query 下有无非预期查询文件；③ 拦截请求中出现xi:include / file://的 WFS 报文与异常 remember-me Cookie；④ 认证过滤器链中移除 remember-me（代价：持久登录不可用）；⑤ 禁用或限制JDBC 用户/角色服务，收紧 /rest/resource 与 /rest/security 的访问。以上只能破坏部分前置条件，不能替代升级；恢复业务后逐项复核。  
  
06  
  
蓝队检测要点：利用链的日志特征  
  
鉴于 PoC 已公开，历史回溯与实时检测应同步开展。以下按链路顺序列出五个环节的日志特征：  
  
① 路径探测特征  
  
WFS 请求出现异常超长的存储查询 ID，随后服务端日志/响应中出现数据目录绝对路径回显。  
  
② 规则绕过特征  
  
请求参数service 的值包含路径分隔符（x/WFS 是已公开 PoC 的默认形态），且来源为匿名会话。  
  
③ 文件读取特征  
  
WFS 请求体中出现xi:include、file://等关键字；错误响应里带回 security/config.xml 类配置内容。  
  
④ 会话异常特征  
  
remember-me Cookie 登录后立即以管理员身份访问 REST API，尤其伴随 /rest/security/usergroup 系列调用——这是伪造会话换取会话的典型组合动作。  
  
⑤ 命令执行特征（最高优先级告警）  
  
REST 接口新增 JDBC 类型的用户组/角色服务；数据目录出现非预期的 HSQLDB 数据库文件（.script / .data）；GeoServer 进程拉起sh、id 等子进程，或进程用户从预期值变为 root。命中任何一条，按已失陷处置。  
  
最后需要强调：若按单环评分排序，最应优先处置的是 9.2 分那一环；但真实攻击中最终击穿系统的，恰是从 6.9 分"低危"漏洞开始的完整接力。风险排序不等于评分排序，利用链的每一环都需要单独认真对待。对承载地理信息服务的各行业单位，更具普适性的提醒是：固定密钥、匿名服务、root 进程——默认配置中的这三类项，在任何时候都应纳入重点核查范围。
