**01**  
  
**nginx2root：Nginx 五个独立内存安全漏洞可导致远程代码执行**  
  
  
奇安信 CERT 发布 Nginx 多漏洞安全风险通告，这组漏洞被称为 nginx2root，包含五个可独立触发的内存安全缺陷。其中，CVE‑2026‑123007 涉及 HTTP/2 流量控制中的整数下溢与堆越界读写；另外四个缺陷分别涉及子请求解析器、HTTP/2 代理连接、HTTP/3 请求流及邮件代理处理。各漏洞利用条件不同，并非全部需要同时触发。  
**攻击者无需身份认证，可通过相应暴露模块执行代码，权限为 Nginx 工作进程权限。部分漏洞组合利用还可绕过 ASLR，配合 Linux 内核提权漏洞进一步获取宿主机 root 权限，甚至突破 Docker 容器隔离**  
。启用 HTTP/2 的服务器受影响面最大，漏洞细节与 PoC 已公开，尚未发现明确在野利用证据。运维应尽快升级至 Nginx 1.31.9 或 1.30.7，升级后必须重启服务，仅重新加载配置不会替换运行中的程序；临时缓解措施包括关闭不必要的 HTTP/2、HTTP/3 及邮件代理模块。资产测绘应优先梳理公网 Nginx 实例，重点检查 HTTP/2 开启状态，做好 Web 访问日志留存与异常请求监测，防止 Web 服务器被攻陷后成为内网入侵入口。  
  
  
**02**  
  
**Visual Studio Copilot 与 SSMS 远程代码执行漏洞 CVE‑2026‑103572 分析**  
  
  
安全研究人员披露 Visual Studio Copilot 与 SQL Server Management Studio（SSMS）远程代码执行漏洞 CVE‑2026‑103572，CVSS 评分为 8.8。漏洞根源是文件名路径校验缺陷：AI 代理写入文件时检查字面文件名，而 Windows 文件系统会自动去掉文件名末尾的句点，导致校验被绕过。  
**攻击者通过提示注入诱导 Copilot 修改 MCP 配置文件与 IDE 设置，最终实现代码执行。该缺陷同时影响 Visual Studio 与 SSMS，因为两者共用部分 Copilot 核心组件**  
。攻击需要用户与受影响 Copilot 交互，并非无需用户操作的无交互漏洞。微软已于 2026 年 10 月 Patch Tuesday 发布修复更新，将其列为 “重要” 级别。研发团队应及时更新 Visual Studio 与 SSMS；审查 AI 代理对配置文件的写入权限，避免允许修改启动与安全控制配置；在开发环境中限制不可信提示注入来源，同时核查内部 MCP 服务路径校验逻辑。对开发终端做好进程与配置变更审计，防止恶意配置写入导致代码执行，保护开发环境中的代码仓库凭据与数据库连接信息。  
  
  
**03**  
  
**Docker 大模型扩展漏洞：默认配置下三条路径可实现容器逃逸**  
  
  
安全研究披露 Docker 大模型扩展组件的容器逃逸漏洞，PoC 已公开。在默认部署配置下，攻击者可通过三条不同路径突破容器隔离，访问宿主机文件系统与进程。官方将部分越界访问归为不在预设威胁模型内，不代表不存在实际安全风险。受影响扩展版本为 4.61.0 之前，建议相关用户尽快升级。  
**AI 研发团队常为调试便利直接使用默认配置，将模型服务部署在容器中。一旦恶意 AI 工作负载进入容器，攻击者可读取宿主机模型权重、API 密钥、云凭据，进一步横向渗透宿主机与其他容器**  
。容器沙箱不能仅凭默认配置判断为安全边界，仍需独立配置权限与访问控制。运维应升级扩展组件，限制扩展的系统调用能力；生产环境避免使用默认配置，启用容器只读挂载、必要的系统调用限制与文件访问白名单；扫描容器镜像中的扩展组件与配置；审计容器异常文件读取、宿主机进程访问及敏感凭据外联行为，防止容器逃逸导致模型资产与密钥泄露。  
  
  
**04**  
  
**Hugging Face 模型仓库遭投毒，伪装模型携带后门并滥用 GPU 算力**  
  
  
安全内参披露 Hugging Face 模型仓库投毒活动，攻击者上传伪装成开源项目的恶意模型。用户加载模型时，若启用远程代码加载功能，恶意代码可在推理环境中执行，建立后门连接，并利用 GPU 资源开展加密货币挖矿。受影响场景包括自托管推理服务、共享 GPU 服务器与 AI 开发工作站。  
**攻击者不依赖传统系统漏洞，而是利用模型仓库生态的信任关系，以及用户对远程代码加载功能的配置习惯。**  
部分项目为方便推理直接开启远程代码执行，没有限制模型来源与代码行为。大量企业与个人开发者直接从公共仓库下载模型，缺乏模型完整性校验与运行环境隔离。研发团队应禁用不必要的远程模型代码加载功能；优先使用可信模型源，对模型文件做哈希校验；隔离推理环境与开发、办公网络；监控 GPU 算力异常占用、异常后门外联及模型加载行为；定期审计模型仓库下载记录，避免恶意模型进入生产推理环境，造成算力滥用与敏感数据泄露。  
  
  
**05**  
  
**N‑able 披露 N‑central 平台 33 个零日漏洞，远程管理服务面临接管风险**  
  
  
安全研究人员披露 N‑able N‑central 远程监控与管理（RMM）平台的 33 个零日漏洞，部分漏洞可组合形成完整攻击链，导致服务器被接管。N‑able 随后关闭部分托管环境，并要求本地部署客户采取停机措施。截至 2026 年 11 月 10 日报道发布时，尚未发现明确在野利用证据，但 PoC 与技术细节已公开，存在后续被利用的风险。  
**N‑central 用于管理大量客户终端、服务器与网络设备，一旦平台失陷，攻击者可利用平台已有的客户信任关系，横向访问受管理系统、窃取保存的凭据、执行恶意软件**  
。这一事件再次凸显 RMM 平台作为供应链入口的风险。企业应核查是否使用 N‑central，按厂商要求采取停机、隔离措施；持续跟踪热修复与安全补丁，发布后立即部署；审计平台管理员账号、设备访问权限及操作日志；清理不必要的设备保存凭据，启用 MFA 并限制登录源 IP；定期核查 RMM 供应商安全公告，建立应急停机与客户访问隔离预案，避免远程管理平台成为批量入侵客户系统的跳板。  
  
  
**06**  
  
**法国国家血液服务机构遭攻击，攻击者篡改冷藏温度并威胁血液安全**  
  
  
安全媒体报道，法国血液服务机构 EFS 的血液冷藏系统遭到入侵，攻击者将部分存储温度设置提高至 110℃，造成血液制品报废。事件发生于 2026 年 11 月 2 日，相关组织随后宣称对攻击负责。安全研究人员将部分攻击追溯至 Danfoss AK‑SM 800A 控制器漏洞，截至报道发布时，全球仍有近 1.3 万台同类冷藏设备存在风险，部分设备使用默认密码。**这一事件并非传统 IT 服务器勒索，而是针对医疗冷链的物理破坏，通过篡改温度参数造成业务与公共卫生损失**  
。国内医疗机构、血站及冷链企业应关注同类工控设备风险；将冷藏控制网络与办公、互联网隔离，设置独立 VLAN 与访问白名单；修改设备默认密码，限制管理接口暴露；部署异常温度配置变更告警；建立温度数据备份与操作日志，定期扫描 IoT 设备漏洞。攻击发生后，应优先恢复温控业务、核查血液制品安全，再开展入侵溯源，防止攻击者再次通过温控系统实施破坏。  
  
  
**07**  
  
**4EverAble2Shell 零日漏洞遭利用，N‑central 服务器被植入挖矿程序**  
  
  
安全媒体 BleepingComputer 披露，4EverAble2Shell 零日漏洞在 PoC 公开后数小时内即遭利用。该漏洞影响 N‑able N‑central RMM 平台，攻击者入侵服务器后部署加密货币挖矿程序。研究人员确认至少 21 台受影响系统，其中 19 台已安装最新安全更新，说明更新仍不足以完全阻止已发生的入侵。  
**RMM 平台集中管理大量客户设备，攻击者利用平台权限关系后，可进一步访问终端、窃取凭据、部署后门。**  
攻击速度快、扩散范围广，给安全响应带来压力。企业应优先隔离受影响 RMM 服务器，核查挖矿进程、异常外联与后门账号；对已安装更新的实例仍开展入侵排查，不能仅凭补丁状态认定安全；审计客户设备访问权限，清理不必要的保存凭据；监控 CPU 与 GPU 异常占用、异常进程启动及外部连接；建立漏洞披露后的快速响应流程，缩短平台隔离与修复窗口，防止 RMM 服务器成为批量挖矿与横向入侵的据点。  
  
  
**08**  
  
**马士基旗下物流平台遭入侵，攻击者声称窃取司机密码并索要赎金**  
  
  
安全媒体 Cybernews 报道，WhiteArmour 勒索团伙宣称入侵马士基旗下 LF Logistics 供应链管理平台，声称窃取超过 1.6 万名司机的密码，并索要 500 万美元比特币赎金。  
**马士基随后确认调查相关事件，但表示部分密码并非明文存储，攻击者获取的部分是已过期的一次性代码。事件涉及订单、物流与司机信息，攻击者还声称操纵客户账户数据，创建或删除订单**  
。这一事件属于物流供应链数据泄露与勒索事件，并非马士基核心集装箱业务系统被攻破。物流企业应加强管理平台身份认证，禁止明文存储密码；隔离订单管理、司机信息与其他业务系统；审计管理员操作、订单变更及批量数据导出行为；限制第三方集成与供应链平台权限，定期评估供应商安全能力。员工与司机应警惕利用泄露信息开展的定向钓鱼、电信诈骗与身份冒用，企业应及时发布风险提示，对相关系统开展漏洞扫描与入侵溯源，防止攻击者继续操纵订单与访问账户。  
  
  
**09**  
  
**俄罗斯 APT 组织利用 MFA 疲劳攻击与 Passkey 凭证，持续渗透云环境**  
  
  
FreeBuf 披露名为 Cold Relic 的俄罗斯 APT 组织攻击活动。该组织使用 MFA 疲劳攻击，通过持续推送身份验证请求骚扰用户，诱使受害者批准恶意登录；攻击者还获取 Passkey 凭证，在用户修改密码后仍保持访问。该组织曾以此渗透美国大型企业的云环境，获得内部资源访问权限。  
**攻击重点在于绕过现代身份防护，而不是依靠传统系统漏洞。很多企业开启 MFA 后，仍缺少针对重复验证请求、异常设备与地理位置的检测，认为开启二次验证即可阻止账号入侵。**  
企业应配置异常登录防护，拦截陌生设备、异地及高频 MFA 请求；监控 Passkey 注册、使用与凭据导出行为；限制云账号跨账号访问权限，启用条件访问策略；开展员工安全培训，提醒拒绝非本人发起的验证请求；建立账号异常访问响应流程，及时撤销可疑会话、轮换凭据并开展溯源，防止 APT 组织长期潜伏云内网。  
  
  
10  
  
**11 月 Patch Tuesday：微软修复 1235 个漏洞，含已在野利用的 Outlook 漏洞**  
  
  
安全媒体 BleepingComputer 报道，微软 2026 年 11 月 Patch Tuesday 修复 1235 个漏洞，其中包含已在野利用的 Outlook 漏洞。更新覆盖 Windows、Office、Exchange 及相关组件，涉及远程代码执行、本地提权、信息泄露与拒绝服务等风险。本次更新数量较多，企业应按资产优先级分批部署，避免直接大规模重启影响业务。  
**已在野利用的 Outlook 漏洞需要重点关注，攻击者可能通过邮件交互或解析触发漏洞，进一步窃取身份信息、执行代码。**  
微软尚未在报道中披露该 Outlook 漏洞的完整编号与技术细节，应以微软官方安全更新指南为准。企业应优先更新邮件服务器、办公终端与域控；测试补丁兼容性，制定回滚方案；监控补丁部署状态与失败记录；开启异常进程、权限提升与邮件解析行为检测；定期备份系统与邮件数据，建立漏洞修复应急流程，避免遗漏高优先级漏洞或因大规模更新导致业务中断。
