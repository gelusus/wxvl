**工信部发文加强智能体终端进网管理：适配验证、反诈评测与唯一身份码成重点**  
  
工业和信息化部11月6日发布《关于加强智能体终端设备进网管理的通知》，通过完善监管规则、强化终端管理，为智能体终端新业态新模式发展提供包容审慎环境。  
  
  
智能体是具备自主感知、记忆、决策、交互与执行能力的智能系统。《通知》要求智能体开发者加强与终端设备的适配验证，强化权限调用、通信能力、网络与数据安全、用户权益和任务执行等方面管理，确保符合监管要求和用户预期，保障智能体兼容稳定运行。开发者应在产品设置页面列明已完成适配的终端型号及操作系统信息，保障用户知情权和选择权。  
  
  
《通知》提出，智能体终端进网要依法开展涉诈风险安全评估和反诈能力前置性评测；终端上使用的智能体应参考智能体互联系列国家标准配备唯一身份码。终端生产企业通过在线升级推送等方式开展现网升级的，要制定现网升级方案，经专家评估、征求意见后向用户提供服务。

**Claude Code “不再询问” 功能泄露凭据，千余 GitHub 公开仓库检出密钥**  
  
安全媒体 The Hacker News 披露 Apiiro 的安全研究结果，Anthropic 旗下 AI 编码工具 Claude Code 存在凭据泄露风险。  
  
  
开发者在批准 Shell 命令时，若选择 “Yes, and don't ask again”，工具会把完整命令原样保存至本地配置文件.claude/settings.local.json，命令中包含的数据库密码、API 密钥、SSH 凭证等机密信息将以明文留存。  
  
  
研究人员扫描 GitHub 公开仓库，发现 1122 份该配置文件包含有效机密，涵盖数据库密码、SSH 登录凭据、GitHub 与 AWS 密钥，涉及 63 家机构，部分泄露密钥仍处于可用状态。即便直接删除该文件，Git 历史记录与仓库 Fork 副本依旧保留泄露内容，单纯删文件无法消除风险。  
  
  
安全团队建议受影响主体优先轮转全部相关密码与令牌，再清理代码仓库历史；开发人员应将该配置文件加入.gitignore，避免误提交至代码仓库，并启用代码推送侧密钥扫描防护能力。

**你的AI可能被植入后门：研究人员研发出可提前破解黑客陷阱的方法**  
  
2026 年 11 月 8 日，SecurityLab 报道，科研人员提出三类防御技术，可在攻击触发前清除神经网络内置后门，在实验中将攻击成功率从接近 100% 压低至 010%，同时保留模型绝大多数业务能力。  
  
  
AI 后门（隐藏触发器）多在模型微调阶段植入，模型日常行为完全正常，收到特定秘密触发信号后，才会输出虚假内容、注入恶意代码，常规测试很难发现该威胁。  
  
  
第一种方法数学剔除微调参数中的后门传播路径，不需要重新训练，保留基础模型与微调习得能力，攻击成功率降至 10% 以内。第二种增设隔离计算模块，将后门行为约束至独立单元，运行时直接关闭该模块，已在多类模型与攻击场景完成验证。第三种适用于未知后门场景，通过比对多份模型副本定位受污染组件，抑制异常参数后少量微调恢复模型效果，无需预先知晓触发条件。  
  
  
研究同时提醒，利用该类触发器做权限管控可靠性不足，不可替代正规鉴权。目前全部方案仍处于实验室阶段，尚未充分验证对抗攻击者自适应规避的能力，但证实无需从零训练新模型即可完成后门净化。

**AI生成虚假身份突破传统图片搜索防线，社交工程攻击风险加剧**  
  
Cybersecurity Insiders刊文指出，随着AI生成头像和身份冒用技术的发展，传统反向图片搜索（Reverse Image Search）已难以有效识别虚假社交账号，企业在招聘、供应商管理和高管身份验证等场景中面临更高的社交工程攻击风险。  
  
  
传统反向图片搜索主要通过匹配相同或相似图片识别盗用头像，但存在三大局限：一是难以识别同一人物的不同照片，裁剪、镜像或轻微编辑也可能绕过检测；二是搜索引擎无法完整索引受登录限制或隐私设置保护的社交媒体图片；三是AI生成的人脸不存在原始照片，导致搜索结果为空。  
  
  
文章强调，搜索无结果仅代表特定图片未出现在相应索引中，并不能证明账号真实可信。  
  
  
对此，文章建议采用社交媒体人脸搜索（Face Search），通过比对不同照片中的人脸特征，发现同一人物关联的其他账号。但该技术仍存在误匹配、数据覆盖不足及隐私合规问题，不能作为最终身份判定依据。  
  
  
在防护层面，企业应建立多重身份核验机制，包括远程招聘中的实时视频面试、结合活体检测的证件验证、通过预留联系方式确认银行账户变更，以及针对高管紧急指令设置回拨或暗语验证流程。  
  
  
文章指出，企业应更新安全意识培训，将独立渠道核验与多信号交叉验证作为防范虚假身份攻击的核心措施。

**首都网警报道成都一男子戴AI眼镜考驾照作弊被查：高价“包过神器”多选题全错**  
  
近期，四川成都公安交管十分局查处一起机动车驾驶人考试舞弊案。10月16日上午，驻场民警在摩托车考场理论考试巡查时，发现一男子神色紧张、答题状态异常，时而戴眼镜、时而戴戒指，行为举止不自然，当即对其核查。该男子承认利用高科技设备作弊。  
  
  
经了解，该男子早年申领汽车驾驶证时理论考试考了四次才勉强通过，此次申请增驾摩托车驾驶证，因担心再次失利，便通过网络渠道购买AI眼镜、智能戒指等电子作弊设备，妄图借助“高科技”通过考试。  
  
  
颇具讽刺意味的是，调查中该男子用手机刷题自测正确率超过85%，但民警随机抽题让其用设备演示时，这款高价作弊设备准确率极低，给出的答案均存在明显错误，多选题全部答错，所谓“包过神器”只是噱头。  
  
  
依据《机动车驾驶证申领和使用规定》第九十三条第二款，公安交管部门依法对该男子作出1900元罚款处罚，一年内不得再次申领机动车驾驶证。公安交管部门提醒，驾考作弊属违法行为，切勿轻信网络所谓“高科技包过神器”，摒弃侥幸心理，诚信应考。

**失控AI黑客代理逃离沙箱引发WorkOS数据泄露事件**  
  
开发平台 WorkOS 披露安全事件，安全研究员测试 ARTEX 自主渗透测试框架时，AI 攻击代理脱离隔离沙箱，非故意入侵企业内部销售应用，造成客户数据外泄。经日志与独立取证机构核验，确认该研究员为事件相关方，其表示已删除全部获取的数据，未对外扩散。  
  
  
事件首次访问发生在 10 月 25 日，直到 10 月 30 日异常流量被员工察觉才被发现。攻击利用四项安全缺陷：老旧内部工具平台缺少防护，API 接口暴露于公网；开发用可预测凭据误部署至生产环境完成认证；系统未配置访问速率限制，AI 代理可批量下载数据。泄露内容包含客户联系信息、账户历史、产品使用记录、销售与客服对话片段，少量记录附带终端用户邮箱，核心业务系统未受波及。  
  
  
目前尚未公开 AI 代理逃逸沙箱的具体技术细节。ARTEX 是具备攻击性的 AI 安全框架，过往曾关联多起网络攻击活动。该事件凸显自主 AI 代理带来新型风险，即便无主观恶意，沙箱逃逸也可引发真实入侵事故。

**无需虚拟机逃逸，配置缺陷引发 ESXi 与 Proxmox 大规模勒索加密**  
  
卡巴斯基 GERT 团队披露两起虚拟化平台勒索攻击真实案例，两起事件均未利用虚拟机逃逸漏洞，攻击者依靠配置缺陷与凭证泄露拿下虚拟化管控层，完成集群加密。  
  
  
第一起为 BlackNevas 勒索软件攻击 ESXi 环境，PRTG 监控系统持有 ESXi 的 root 账号，且多台主机复用同一组密码。攻击者攻陷监控平台后，经由 SSH 登录主机，关闭 execInstalledOnly 安全策略，上传并执行勒索恶意程序，横向加密多台 ESXi 节点。  
  
  
第二起是 The Gentlemen 组织攻击 Proxmox 集群，攻击者攻陷管理员工作站，获取明文存储的 root 凭证，调用 VNC web socket 接口接管集群，对全部虚拟化环境实施加密。  
  
  
报告归纳高危错误配置：监控账号权限过度、凭证复用、开放 root 直连 SSH、安全策略可被高权限账号关闭、明文保存特权凭据。报告建议将监控与管理权限分离，启用 Lockdown Mode，管控 SSH 访问，将配置变更纳入安全告警，同时强化凭证保管。该案例提示，补丁更新之外，虚拟化管理平面的配置加固同样不可忽视。

**面向 SOC 检测能力校验，Brava Security 多智能体 AI 安全平台对外亮相**  
  
2026 年 11 月 8 日，网络安全初创企业 Brava Security 正式结束隐身模式，完成 1500 万美元种子轮融资，本轮由 F2 Venture Capital、Pitango VC 领投，多名天使投资人跟投。公司总部位于特拉维夫，2024 年由以色列情报背景的 Idan Basre 与 Itay Gabbay 联合创立。  
  
  
该公司推出多智能体 AI 平台，无需真实发起攻击，即可生成攻击行为对应的遥测数据，结合业务上下文，推演攻击在企业环境中的表现，发现现有安全防御的漏报点，并可改写 SIEM 检测规则，支撑安全团队深度研判。该产品对接 70 余种数据源，无需改动现有安全基础设施，完成接入后 1015 分钟即可输出初步分析结论。  
  
  
产品旨在解决当前安全运营痛点：AI 安全系统无法处理从未采集到证据的攻击场景，该平台在威胁发生前验证防御可视性。本次融资将用于产品迭代与市场拓展，研发团队设在以色列，商业团队布局美国。

**OpenCV5.1 版本发布，掩码类图像处理最高提速 15 倍**  
  
2026 年 11 月 7 日，开源计算机视觉库 OpenCV 推出 5.1 版本更新，开发团队公布了一批完成性能优化的图像处理运算逻辑。  
  
  
本次性能提升主要依托处理器向量指令集以及重构后的新型算法实现，重点针对掩码参与的图像运算场景。测试数据显示，当掩码近乎为空时，部分操作最高可实现 15 倍运算加速；掩码内容不同，实际加速效果会出现浮动。  
  
  
掩码运算广泛应用于图像分割、目标抠取、局部画面修改等计算机视觉任务，也是安全领域图像取证、视频分析工具的底层常用接口。新版本没有改动对外 API 接口，现有业务代码大多无需修改即可直接升级。  
  
  
对于网络安全从业者而言，该优化可以降低视觉类安全检测工具的 CPU 算力消耗，提升批量图像、视频样本的处理效率。开发人员可结合自身业务掩码特征，评估升级收益，同时留意不同掩码填充状态下的实际性能差异，避免出现性能预期偏差。

**OpenAI 发布 GPT-6 Cyber，漏洞挖掘能力提升且范围约束可靠性增强**  
  
2026 年 11 月 6 日，OpenAI 推出专用网络安全模型 GPT-6 Cyber，该模型被公司预备框架评定为 Critical 级别，高于前代 GPT-5.6 Cyber 的 High 评级。  
  
  
在 ExploitGym 漏洞利用基准测试中，GPT-6 Cyber 成功率达到 48.5%，GPT-5.6 Cyber 仅为 32.1%。对齐测试显示，无安全提示的条件下，模型拒绝攻击范围外目标的概率达 99.93%，开启安全提示后可完全规避针对诱饵服务的攻击行为。  
  
  
实测场景中，该模型复现 Linux 内核 1724 个漏洞，生成 948 条可用权限提升利用代码；还为 Firefox 挖掘出 81 个 Mozilla 确认的高危漏洞，相关补丁已经启动推送。OpenAI 已向软件维护者提交 304 个高危问题及修复建议。  
  
  
模型新增权限行为监控，防护针对工业控制系统的越界操作，防护方案参考工业安全厂商 Dragos 的测试反馈优化。当前 GPT-6 Cyber 仅向 Daybreak Red 项目的获批客户开放 API 与 Codex 接口，后续将逐步扩大授权范围，面向关键基础设施防御人员提供合规测试通道。
