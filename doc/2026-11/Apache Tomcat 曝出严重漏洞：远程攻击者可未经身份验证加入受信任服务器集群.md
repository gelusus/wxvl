#  Apache Tomcat 曝出严重漏洞：远程攻击者可未经身份验证加入受信任服务器集群  
 网安百色   2026-11-21 10:52  
  
![](https://mmbiz.qpic.cn/sz_mmbiz_png/WibvcdjxgJnusOjzuP7GNSVDob8GF5HibibggJSokTkvh5lefD9OLeXSHXhYEglxYsbgsXjiaLavbYmSbp7DRF6IscDd7q4chjrbdcv3FssXGfw/640?wx_fmt=png&from=appmsg "")  
  
Apache Software Foundation披露了 Apache Tomcat 中存在的一处严重漏洞，允许远程攻击者在未经身份验证的情况下，非法加入受信任的服务器集群。该漏洞编号为 CVE-2026-133325，主要影响配置了预共享密钥（Pre-Shared Key, PSK）并采用 TLS 1.3 协议的集群环境。  
  
Apache 于 2026 年 11 月 19 日发布了该安全公告，并对发现此问题的研究员 Mike Read 予以致谢。  
  
Apache Tomcat 11 的安全公告指出，11.0.28 和 11.0.29 版本受影响。此外，Apache 还列出了 Tomcat 10.1.62 和 9.0.124 版本。但需要注意的是，仅运行这些版本本身并不意味着服务器必然暴露于风险之中。  
  
触发该漏洞需要满足特定的集群加密配置，且远程攻击者必须能够通过网络访问处理集群成员间通信的服务端口。对外提供公共 Web 服务的 Tomcat 节点，并不一定会直接暴露该内部通信服务。

### Tomcat 集群身份验证失效漏洞详情  
  
Apache Tribes 组件负责处理 Tomcat 集群中服务器之间的内部通信。这些服务器通过共享会话（session）数据，确保当某台服务器接管请求时，用户仍能保持登录状态。预共享密钥（PSK）则是提前在受信任成员上配置的共享机密信息。  
  
在受影响的 TLS 1.3 配置下，Tomcat 未能验证连接对端服务器的真实身份。这意味着，即使无法证明该服务器具备加入集群的合法权限，连接依然可以建立并完成加密。  
  
Apache 建议将集群通信协议降级切换至 TLS 1.2，同时保持预共享密钥启用。此更改仅适用于 Tomcat 服务器之间的内部流量，不影响网站访客使用的 HTTPS 连接。各分支的修复版本分别为 11.0.30、10.1.63 和 9.0.125。Apache 在其 Tomcat 11、10 和 9 的安全公告中将这些版本列为“待发布（pending release）”状态。  
  
将集群通信端口通过防火墙或安全组严格限制为仅允许受信任的服务器访问，并审查现有日志以排查异常的成员变更。在应用临时缓解措施或完成更新后，需确认所有预期的成员均已重新连接，且在启用了会话复制（session replication）的环境中该功能仍正常工作。需要注意的是，即使服务器之间停止了会话数据共享，网站本身可能仍能正常响应外部请求。
