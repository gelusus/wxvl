#  【已复现】OpenSSH/musl 密码认证绕过漏洞  
原创 360漏洞研究院
                    360漏洞研究院  360漏洞研究院   2026-11-06 01:38  
  
2026年11月5日，OpenSSH 发布安全更新，修复了部分 musl Linux 环境下可通过 SSH 服务触发的密码认证绕过问题，公开披露名称为 SSHHole。远程攻击者在满足特定条件时，无需掌握目标账户的密码或私钥，即可能登录该账户，获得其对应权限。  
  
  
**利用条件与限制：**  
- SSH 服务使用 musl 的密码校验实现；  
  
- 未编译 PAM 支持或配置为 UsePAM no；  
  
- 允许密码认证；  
  
- 目标账户的密码字段恰好为单个 *；  
  
- 系统中还存在可供 sshd 选取备用校验参数的有效密码账户，并使校验进入相应的异常返回路径；  
  
- 攻击者还需能够访问 SSH 服务，且目标账户未被其他登录策略拒绝。  
  
目前360图龙锋 · 漏洞挖掘智能体已成功复现该漏洞。本文包含完整影响范围、正式修复方案、技术原理与复现细节。

**01**  
  
**漏洞影响范围**  
  
  
  
受影响的版本：  
  
7.3p1 至 10.6p1  
  
  
注：重点排查Alpine Linux，以及采用 musl 并部署 OpenSSH 服务的 OpenWrt、Buildroot、Yocto 系统、云镜像和容器。上述环境并非全部受影响，仍需同时满足利用条件。使用 glibc、通过 PAM 完成认证的部署，以及 Dropbear、OpenBSD，不属于本次公开披露的利用路径。  
  
  
**02**  
  
**修复建议**  
  
  
  
**正式修复方案**  
  
升级至 OpenSSH Portable 10.6p2  
  
  
**03**  
  
**漏洞描述**  
  
  
  
在 Linux 系统中，密码字段中的单个 * 通常用于表示该账户不能通过密码登录。受影响的 OpenSSH 处理此类字段时，会选择其他账户的密码算法和盐值进行备用计算，以减小认证耗时差异。  
  
  
musl 的 SHA-256/SHA-512 密码哈希实现对密码长度设有限制，超限时可能返回错误标记 *。旧版 sshd 未充分区分错误标记与有效密码哈希，可能将返回的 * 与账户中保存的 * 判定为相同，从而错误接受认证。
