#  花费120 万美元，让AI 找出 948 个 Linux 提权漏洞，价值数千万美元  
原创 网络安全透视镜
                    网络安全透视镜  网络安全透视镜   2026-11-05 03:32  
  
11 月 4 日，OpenAI 发布研究报告《A thousand fewer paths to root》。报告披露，其  
   
尚未发布的网络安全模型  
   
在一次针对 Linux 内核主分支的扫描中，验证了 948 个可让低权限本地用户提升至 root 的独立漏洞，并生成对应补丁，全程消耗约  
   
121.3 万美元 API 额度。  
  
11 月 5 日上午 7 时 13 分，OpenAI 官方账号在社交平台发布了这条消息，配图是一张  
   
标注各阶段数字的漏斗图  
   
。  
  
Linux 内核代码量  
   
超过 4000 万行  
   
，支撑着安卓设备、云基础设施和超算。这次被验证的问题全部是  
   
本地提权漏洞  
   
（LPE，local privilege escalation）：攻击者需要先拿到系统上的一个低权限账户，利用成功后获得 root 。

FINDINGS  
### 一次运行，948 个独立本地提权漏洞  
  
  
948  
  
独立本地提权漏洞  
  
121.3 万  
  
API 额度（美元）  
  
经静态初筛收窄为 313 个信息泄露候选和 1238 个本地提权候选；最终产出 291 个可用的信息泄露 PoC，以及  
   
948 个可用的本地提权利用。

按 Pwn2Own、TyphoonPWN 历史上对 Linux 内核 LPE 给出的 2 万美元和 7 万美元奖金测算，948 个利用对应约 1890 万至 6630 万美元的  
   
假设估值  
   
，是本次成本的 16 到 55 倍。

PIPELINE  
### 五个阶段的流水线，末端仍是人工  
  
  
![](https://mmbiz.qpic.cn/mmbiz_png/A6fTew8FFGGynTPdtoibMuf47kSBpfqVDC6iakSezC7Uu9lE0niaMjk5xGJsQzEWIlzibEtFxAcHZqV5X2ibicbbI3d1aPInK0qnvicaASv0XpbcYc/640?wx_fmt=png&from=appmsg "")  
  
— OpenAI 报告中的自主 Linux 内核漏洞研究流水线示意图  
  
系统被拆成五段：漏洞发现、动态验证、可利用性评估、补丁生成、  
   
人工复核。  
  
发现阶段，从 4000 多万行代码里圈出  
   
5034 个审计目标、约 280 万行  
   
，占整个内核的 7%，这一步花了 3426 美元。Analyst agents 接手后用类似 Codex Security plugin 的工作流扫描，  
   
12 小时交出 2308 个候选发现  
   
，成本 31.65 万美元。  
  
验证阶段，Triage agent 给每个候选写 PoC，丢进  
   
开启 KASAN 的隔离虚拟机  
   
里跑，再根据控制台输出迭代。报告称只有 3.1% 属于模型假设了不可能条件导致的  
   
彻底误报  
   
；没能复现的，多数是需要更高权限，或卡在竞态条件、指定行的分配失败这类难触发的条件上，以及 refcount wraparound 之类耗时过长的验证。这一阶段  
   
7.33 万美元。  
  
利用阶段先过一道宽松的静态初筛，由 agent 审阅报告、崩溃日志和相关源码，宁可放过也不误删，成本 4.42 万美元。剩下 313 个信息泄露候选和 1238 个提权候选交给 ExploitDev agents，在开启  
   
SMEP、SMAP、KASLR  
   
、HARDENED_USERCOPY 的标准发行版虚拟机里做利用开发，判定标准是  
   
拿到 root shell  
   
。整段 77.59 万美元，其中提权候选占 69.1 万美元。成功的利用平均耗  
   
359 美元 API 额度  
   
；69 个失败案例平均花掉 3922 美元。  
  
补丁阶段不算顺利  
   
。模型拿到相关源码后被要求做静态检查、遵循邻近代码的写法、检查同类变体，但最初生成的补丁虽然能挡住 PoC，仍常出现多余代码、潜在性能代价、偏离编码规范或  
   
漏掉变体导致修不干净  
   
。加了几轮指令和迭代才改善。报告还提到，系统曾发现人类专家所写补丁里的问题，并在合入前修掉。  
  
最后一道是人工。  
   
安全研究员审阅  
   
根因分析、最小崩溃 PoC、候选补丁、完整利用和严重性评估，再报给内核维护者。整条流水线  
   
并不是无人值守。  
  
03  
  
TECHNIQUES  
### 十种新技术与一次“跑偏”  
  
  
OpenAI 抽样了 166 个由智能体编写的利用程序，认为其中至少用到  
   
10 种此前未见过  
   
的 Linux 内核利用技术：2 种用于内核缓存精准堆喷射的持久弹性对象、2 种提高提权稳定性的页面编排（page grooming）手法、5 种通过任意写或直接篡改数据结构拿到权限的 data-only 技术，以及 1 种任意类型混淆。这些技术发给  
   
第三方内核利用专家  
   
看过，反馈同样是从未见过。出于安全考虑，报告  
   
没有公开完整技术细节。  
  
更值得记录的是早期测试里的一次意外。当时 ExploitDev 的任务被设成“针对指定的漏洞写利用，拿到 root shell 就算完成”。200 个报告成功的案例，人工复核发现有  
   
20 个根本没用指定漏洞  
   
——智能体在靶机里反复尝试后，  
   
转而挖了一个未知的 0-day  
   
，同样提到 root。OpenAI 之后收紧了任务约束，并加了一道独立检查，确认每个最终利用确实用了指定漏洞。报告把这条经验写成一条提示：自主安全研究里，除了验证结果，  
   
还要验证通向结果的路径  
   
，隔离、监控和独立检查都是必要控制。  
  
同一轮 kernelCTF 测试还有个插曲：智能体在  
   
没有 QEMU 源码的情况下  
   
，把一次意外的内核崩溃追溯到 QEMU TCG，并写出了提权利用。事后确认该问题在上游 QEMU 已经修过，但实验所用的  
   
release build 里没有。

RESPONSE  
### 修复端的时间窗口  
  
  
![](https://mmbiz.qpic.cn/sz_mmbiz_png/A6fTew8FFGFt7LzWdK5dIAsLFkiafSkPaTOMic7PzTVjx9wOianLIhvLz0ic1cJsHV390YfPiaexXPGX3uibe0lQ7xs1fj0cVCZ8S9I4arLxZKoiaQ/640?wx_fmt=png&from=appmsg "")  
  
— OpenAI 研究员 Eric Wallace 关于公益算力投入与漏洞发现速率的发帖  
  
OpenAI 研究员 Eric Wallace 在社交平台表示，公司正把大量前沿算力以  
   
完全公益（pro bono）  
   
的方式投入开源代码库的漏洞发现与修补。他在同一条帖子里给了一个对比：AI 之前，安全研究员一年在 Linux 里大概能发现  
   
约 20 个 LPE  
   
；这次即将发布的前沿网络安全模型用一周左右、约 100 万美元的 token，找到约 1000 个，过程中还总结出至少 10 类新的利用技术。  
  
这是研究者的个人表述，  
   
不是行业基准测量  
   
，“AI 用 10 天干完人类 50 年的活”是由此换算出来的说法，  
   
报告正文里没有这句  
   
。但它和报告的时间线放在一起，问题就很具体了：  
   
发现端的速度已超过修复端吞吐。  
  
报告记录了扫描与人工复核那 10 天里上游的变化：  
   
61 个 LPE 已在上游打上补丁  
   
，43 个补丁处于暂存状态，299 个正在公开报告与讨论。按 Linux 内核社区的建议，OpenAI 从严重漏洞开始报，已发出数百份报告和补丁，其余通过 Patch the Planet 计划与 Daybreak 承诺分批提交。公告里  
   
没有列出 Firefox、Chrome 的修复数字  
   
，只把浏览器列为后续需要“高保障建设”的核心软件类别之一，另外提到的具体项目是 Kata、Moby/Docker、gVisor 和 QEMU 这类基础设施。  
  
OpenAI 给的长期方向，是让每一代模型把软件修到下一代更难攻破，并提到训练模型默认写出安全代码、削减不必要功能以缩小攻击面、形式化验证等路线。报告也承认，大型复杂项目大概率要经过多轮“扫描—修复”才能把存量问题压到底，理想情况是  
   
每代前沿模型出来后重跑一遍，  
   
开源和闭源项目都一样。
