## 一、简介  
  
      Hephaestus是集资产收集、攻击面评估、漏洞验证与AI渗透对话于一体的安全测试平台。提供Web服务、桌面客户端及独立扫描代理，支持本机扫描、组合任务和遍布节点执行。

二、核心功能  
### 2.1. 组合扫描：把“多工具”变成“一条任务链”  
  
Hephaestus 的“组合任务”支持把多个扫描阶段编排进同一个任务：  
- 子域名收集 → 端口与服务识别 → 网站指纹与漏洞 → 目录扫描 → 弱口令检测 → JS/API 发现；  
  
- 每个阶段可以独立配置参数与执行顺序，前序结果可作为后续输入；  
  
- 同一任务里查看各阶段进度、日志与结果，而不是在多个工具间导出、导入。  
  
任务管理配套完整：并发控制、暂停/恢复、取消、扫描历史、计划任务、参数模板与结果检索。对需要“跑一晚上、第二天看结果”的安服场景，这些比单点扫描能力更重要。  
### 2.2. 攻击面评估：从子域名到 JS/API  
  
攻击面评估模块覆盖了常见入口：  
- **子域名收集**  
：多源 DNS 查询与爆破；  
  
- **端口与服务**  
：Connect 默认，SYN 需要授权与抓包权限；  
  
- **网站指纹与漏洞**  
：识别框架、中间件、CMS、OA 等，并对接漏洞验证；  
  
- **目录扫描**  
：基于字典发现隐藏路径与后台；  
  
- **弱口令检测**  
：按服务类型选择字典与并发；  
  
- **JS/API 发现**  
：从前端资源中提取接口、参数与敏感信息。  
  
同时集成 **FOFA、Hunter、Quake**  
 等空间引擎，支持查询、聚合搜索、历史、配额查看与结果下载。这样“外部测绘 + 主动扫描”可以在同一个资产视图里合并，而不是两套数据。  
### 2.3. AI 渗透工作台：能调工具，也能留证据  
  
这是 Hephaestus 最有辨识度的部分。AI 工作台是围绕“项目—会话—工具调用—证据”来组织的，并非普通聊天框：  
- 新建会话时说明授权目标与测试范围；  
  
- AI 规划下一步，调用平台内的扫描、请求、空间引擎等工具；  
  
- 支持图片输入（截图、报错、页面）；  
  
- 测试过程、工具调用、发现与复现步骤都记录在会话中，可回看、可复核；  
  
- 支持 **AI 批量任务**  
：批量创建、队列管理与执行状态查看。  
  
工具执行侧有两层约束：  
- **toolguard**  
：调用前做规则检查，默认开启；  
  
- **可选 Docker 出口网关**  
：把命令、Python 和原生 HTTP 请求放进隔离网络执行，适合需要更强隔离的场景。  
  
AI 会话中的本地命令还做了文件写入隔离：macOS 用 sandbox-exec  
，Linux 用 Bubblewrap；缺少隔离工具或初始化失败时直接拒绝执行。这个设计比“提示词里写不要乱执行”可靠。  
### 2.4. 漏洞中心：扫描与 AI 发现统一收口  
  
Hephaestus 把“扫描结果”和“AI 发现”合并进同一个漏洞中心：  
- 按来源、级别、状态筛选；  
  
- 查看复现步骤与证据；  
  
- 跟踪人工处置状态；  
  
- 与资产、任务、会话关联，能回溯“这条漏洞是从哪个任务、哪次对话来的”。  
  
对交付来说，这解决的是“证据散落”的问题：扫描器发现的漏洞在 A 表，AI 发现的记录在聊天记录里，最后写报告时又要重新整理。统一收口后，报告素材在测试过程中就积累下来了。  
### 2.5. 资产、企业与拓扑：知道“这是什么、属于谁”  
  
资产管理模块提供：  
- **资产中心**  
：IP、端口、子域名、网站等收集结果的集中视图；  
  
- **资产拓扑与地图**  
：从资产关系看暴露面；  
  
- **企业信息**  
：企业及关联资产收集，支持 Excel 导出与合并导出。  
  
这部分和扫描能力同样重要。授权测试里，“这个 IP 属于哪个业务、是不是靶标范围”往往比“这个端口开没开”更难确认。把企业关联与资产拓扑放在同一平台，能减少误伤和越界。  
### 2.6. 请求转发、PoC 与报告：验证与交付的最后一公里  
- **请求转发**  
：HTTP 请求编辑与响应查看，支持标签页保存、cURL/HEX 视图；  
  
- **Nuclei 模板**  
：检索、编辑、扩展目录、调试，支持模板润色与 OOB 连通性测试；  
  
- **报告管理**  
：多任务批量导出 Word / Excel / HTML，自定义导出名称。  
  
这三块对应渗透测试的“手工验证 → 模板固化 → 报告交付”。尤其是请求转发与模板调试放在同一平台，省掉了“在 Burp 里调完、再复制到 Nuclei”的来回搬运。  
### 2.7. 分析工具：一个轻量 CyberChef  
  
平台内置了一组分析工具，覆盖常见 CyberChef 场景：  
- 编解码、哈希、JWT、加解密，可组合成处理流水线；  
  
- API 文档测试、文本比较、杀软识别；  
  
- 数据库信息采集与密钥管理；  
  
- 桌面端额外支持**小程序反编译**  
。  
  
这些工具本身不稀奇，但在连续测试中，不必来回切换浏览器和命令行能省不少时间。  
### 2.8. 分布式 Agent：把执行端放到应在的网络里  
  
当目标在客户内网、或需要从不同区域发起扫描时，单机就不够了。Hephaestus 的 Agent 机制：  
- 节点通过共享 PostgreSQL 领取任务、发送心跳、回传结果；  
  
- 支持角色（如 ai,scan  
）与容量管理；  
  
- 平台统一查看节点状态、版本与任务分配；  
  
- 提供 Linux/macOS 安装脚本、Windows 安装器与批量更新/回滚文档。  
  
这使“控制台在一处、执行端在多处”成为可能，同时保持任务与结果的一致性。
